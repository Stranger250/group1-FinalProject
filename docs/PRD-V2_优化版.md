## 2. 功能需求

### O1 隐患类别精细化（todo-1）

**现状**：隐患类型为 6 个平铺分类（高处作业/用电安全/机械伤害/消防/临边防护/其他），H02 按字符串筛选，AI 识别映射到粗分类。

**需求**：
1. **三级分类体系**：大类（现行 6 类）→ 子类（每大类 4-8 个子类，如「用电安全→配电箱/电缆线路/电动工具/接地保护」）→ 检查项说明（可选）。
2. 分类表独立建表（`hazard_category`：id/parent_id/code/name/检查项说明/启用状态），支持树形加载。
3. H01 上报支持选择到**子类**（大类自动推导）；H02 列表筛选支持大类/子类两级。
4. AI 视觉识别输出映射到子类（`type_suggest` 升级为 `{category, subcategory}`），置信度低的回退大类。
5. 列表/统计按子类聚合展示。

**验收标准**：
- [ ] 分类表可维护（新增/停用子类不影响存量数据）
- [ ] 上报可选子类、详情展示子类；旧数据（仅大类）兼容展示为「大类·未细分」
- [ ] AI 识别返回子类建议，且可手动改选
- [ ] 列表筛选按大类/子类均有效，统计页支持子类分布

### O2 数据量扩充：隐患图片 ≥100 张、法律条文库六类 >1000 条（todo-2）

**现状**：隐患 60+、题库 157、法规语料 28 篇；隐患现场图片不足 10 张，演示与评测受数据量制约。

**需求**：
1. **隐患图片素材 ≥100 张**：由项目方提供真实隐患现场图片（`施工现场隐患图片/` 目录现有 25+，需扩充至 ≥100 张，覆盖 6 大类 × 多子类）；图片入库管理（`hazard_image` 种子数据，可直接用于上报/识别演示与 AI 识别评测）。
2. **法律条文数据库（六类，合计 >1000 条）**：
   - 内容构成与数量要求见 **O4**：安全生产法、建设工程安全生产管理条例、企业安全管理制度、安全操作规程、应急预案、典型事故案例分析六类文档，合计 >1000 条；
   - 本项聚焦数据工程：国家法规走爬虫批量扩充（`crawler.py`/`sichuan.py` 扩展 targets），制度/规程/预案模板与事故案例人工整理导入，全部走统一 JSON schema（`doc_type` 六类）。
3. **种子数据工程**：`scripts/seed_demo.py` 升级为可配置批量造数（隐患 200 条多状态/多类别/带图片、用户 20 个、会话 50 个、题库 300 题全题型），幂等可清理。
4. **评测用数据**：随 RAG 评测集（O6）配套的标注样本。

**验收标准**：
- [ ] 隐患图片素材 ≥100 张（入库可查询、可预览）
- [ ] 法律条文库六类文档合计 >1000 条（构成与数量口径见 O4），JSON schema 校验通过
- [ ] 一条命令生成 ≥500 条演示数据，覆盖全部状态/等级/类别分支；造数幂等、可清理
- [ ] 题库 ≥300 题、五题型齐全、含 AI 出题批次样例

### O3 隐患上报界面优化：布局 = 图片 + 隐患 + 详细内容（todo-4）

**现状**：上报（`/hazards/report`）与 AI 识别（`/hazards/analyze`）为独立页面；AI 识别结果（risk_report）是否随上报保留由前端自行传参，无用户选择环节。

**需求**：
1. **上报页面布局（用户确认）：图片 + 隐患 + 详细内容 三段式**：
   - **① 图片区**：现场图片上传与预览（多图拖拽、缩略图、点击放大；AI 识别后此处显示标注图）；
   - **② 隐患区**：隐患概要信息——现场上报人、隐患类型（子类联动）、等级、位置、标题（快速填写区）；
   - **③ 详细内容区**：隐患描述（必填）、整改建议/备注、AI 识别结果摘要与勾选保留。
   - 视觉上按竖排三段分区（或左图右文两栏 + 下方详细内容），信息密度与现场录入动线匹配。
2. **一步式上报**：上传图片 →（可选）AI 识别回显 → 表单确认 → 提交；识别与上报合并为同一页面流程，移除独立「AI 分析」页入口（保留接口兼容）。
3. **AI 识别结果可选择保留（用户反馈核心）**：
   - 识别完成后展示识别结果摘要（类别/等级/描述/置信度 + 检测项明细），用户可勾选「**保留 AI 识别结果**」或「**不保留**」（仅留原图）；
   - 支持**按检测项选择保留**：多隐患图中每处 detection 可单独勾选保留/丢弃，标注图（annotated_url）随勾选结果同步生成；
   - 保留与否、保留哪些项，明确落库到 `hazard.risk_report`（结构：`{detections:[已勾选项], annotated_url, kept:true/false}`），详情页据此展示。
4. 提交流程引导：必填项实时校验、提交后跳转详情。

**验收标准**：
- [ ] 上报页为「图片 + 隐患 + 详细内容」三段式布局，动线清晰（传图→填概要→写详情→提交）
- [ ] 单页完成「传图→识别→确认（勾选保留）→上报」全流程，无跨页
- [ ] 识别结果可勾选「保留/不保留」；多检测项可逐项勾选，标注图随勾选同步
- [ ] 详情页按 risk_report 展示：kept=false 只显示原图；kept=true 显示标注图 + 已勾选检测项
- [ ] 识别 503 降级可手动填写继续上报；旧入口 `/hazards/analyze` 重定向到新流程

### O4 法律条文知识库：六类文档库，总量 >1000 条（todo-5，用户重定义）

**现状**：crawler 已爬 28 部法规（国家层面），无企业级语料；前端无文档展示页（文档展示页见 O10）。

**需求**：
1. **法律条文数据库重构为六类文档**（统一入库、统一 schema、`doc_type` 区分）：
   - **安全生产法**：现行《中华人民共和国安全生产法》全文按条入库，及配套法规/释义；
   - **建设工程安全生产管理条例**：国务院《建设工程安全生产管理条例》全文按条入库，及建筑施工安全相关配套规定；
   - **企业安全管理制度**：安全生产责任制度、隐患排查治理制度、安全教育培训制度、应急管理制度、奖惩制度等制度类文档（含样例模板）；
   - **安全操作规程**：动火作业、高处作业、受限空间作业、吊装作业、临时用电、机械设备、危化品使用等作业安全操作规程（SOP）；
   - **应急预案**：综合应急预案、专项预案（火灾/防汛/触电/坍塌/机械伤害等）、现场处置方案；
   - **典型事故案例分析**：事故调查报告公开件，结构化（事故概况/原因分析/责任追究/整改措施）。
2. **数量要求：六类合计 >1000 条**（以「条」为最小入库单元：法律/条例按条文、制度按条款、规程按操作条目、预案按条款/步骤、案例按单起案例条目），六类均需有覆盖；建库报告按 doc_type 分组统计条数/块数用于验收。
3. **数据来源与工程**：国家法规走爬虫批量扩充（`crawler.py`/`sichuan.py` 扩展 targets），企业安全管理制度/安全操作规程/应急预案模板由项目方整理导入，典型事故案例导入公开事故调查报告；`crawler_output/` 输出统一 JSON schema（`doc_type`：law/regulation/company/sop/plan/case）。
4. **知识库重建**：`build_knowledge_base.py` 支持按 doc_type 分组统计与验收断言更新（文件数/条数/块数）。
5. **检索权限分层（配合 O7）**：企业安全管理制度等企业级语料默认仅管理端可见。

**验收标准**：
- [ ] 知识库含六类文档（安全生产法 / 建设工程安全生产管理条例 / 企业安全管理制度 / 安全操作规程 / 应急预案 / 典型事故案例分析），六类合计 >1000 条
- [ ] 六类均有数据且可检索；建库报告按 doc_type 分组输出（文件数/条数/块数）
- [ ] JSON schema 校验通过（doc_type 枚举六类）；既有 28 部法规数据迁移兼容
- [ ] 检索可按 doc_type 过滤；企业级语料对员工端不可见

### O5 分块策略明确化与参数化（todo-6，管理端可配置）

**现状**：分块参数散落在 build 层（父块 >400 字、子块 100-250 字、重叠 1 句），策略未文档化、不可配置。

**需求**：
1. **分块策略文档化**：明确「章头块/父块/子块」划分规则、重叠策略、父子回溯映射、块 ID 规范，写入 RAG 方案并成为唯一真源。
2. **参数化（RAG v1.0 配置面）**：分块参数集中到 `rag_config.py`（`parent_split_chars`、`child_min_chars`、`child_max_chars`、`overlap_sentences`），build 与检索共用。
3. **管理端「分块策略设置」页（O9 配置中心之一）**：管理员可在页面查看/修改分块参数并保存（写入配置库或 .env 兼容层），修改后触发知识库重建（带确认与回滚提示）。
4. **按 doc_type 差异化**：法规按条（现状）；预案/SOP 按章节+段落；案例按「事件/原因/措施」语义段。
5. 分块质量自检：块长度分布、断句完整率、跨块重复率统计进入建库断言。

**验收标准**：
- [ ] 分块参数全部可配置（管理端页面可改）且默认值通过评测基线（O6）
- [ ] 管理端修改分块参数 → 保存 → 触发重建 → 检索生效；重建失败可回滚旧索引
- [ ] 各 doc_type 分块规则生效，块内句子完整（无截断句占比 <2%）
- [ ] 建库报告输出分块质量统计（长度分布/重复率）

### O6 RAG 评测基线、测试集与大模型测试（todo-7，以 RAG v1.0 为基线）

**现状**：无评测集、无 baseline、无指标闭环（仅建库抽样 Recall@5 粗查）；模型由 .env 配置但未做过对比测试。当前已交付 RAG 链路标记为 **RAG v1.0**（混合检索 50+50 → RRF K60 → 展开 → 重排 Top5、置信度 0.30/0.45、vec_sim 下限 0.75、SSE 流式）。

**需求**：
1. **评测集构建**（`data/eval/` 带版本）：
   - 法规问答 ≥500 条（含条号命中标注）
   - 拒答样本 ≥100 条（无关/歧义问题）
   - 多轮样本 ≥100 组（指代/追问）
   - 出题样本 ≥100 条（知识点→题面质量标注）
2. **测试 Query 集（100 条，用于测试查看检索效果）**：
   - 构建 100 条测试 query（贴合真实问答场景），**按答案与 chunk 的对应关系分三组**：
     - **50 条「1对1 chunk」**：答案完整落在单个 chunk 内——验证检索精准命中、不冗余召回；
     - **33 条「1对2 chunk」**：答案分布在相邻 2 个 chunk（父子块/同章相邻块）——验证块关联回溯与展开召回；
     - **17 条「1对3 chunk」**：答案分散在 3 个 chunk（跨章/跨节）——验证多块召回与重排整合。
   - 每条 query 标注期望命中的 chunk 列表；评测脚本可**逐条输出检索效果供查看**（召回块清单 + 命中判定 + 依据拼接预览），便于人工抽查与调参。
3. **指标脚本**：`scripts/eval_rag.py` 输出 Recall@5、MRR、NDCG@5、条号命中率、拒答正确率、幻觉率（grounding）、出题通过率；生成 `baseline_v1.json` 存档（git 可追溯，标记 RAG v1.0）。
4. **大模型对比测试**：同一评测集跑多模型（DeepSeek 系列 / qwen 系列，管理端模型设置切换），输出对比报告（质量/延迟/成本三表）。
5. **RAG 优化闭环**：基于 baseline_v1 迭代（分块/检索/重排/阈值），每次改动对比基线，回退劣化 >1pt 的改动；优化版本顺延（v1.1/v2.0…）。

**验收标准**：
- [ ] 评测集入库带版本号，脚本可一键跑出全指标
- [ ] 100 条测试 query 入库（50 条 1对1 chunk / 33 条 1对2 / 17 条 1对3），每条标注期望命中的 chunk
- [ ] 评测脚本支持逐条查看检索效果（召回块清单/命中判定/依据预览），供人工抽查
- [ ] baseline_v1.json 生成并提交 git；CI 可对比回归
- [ ] 至少完成 2 个模型的对比测试并输出报告
- [ ] 优化后主指标不低于 baseline_v1（Recall@5 ≥0.92、拒答正确率 ≥95%）

### O7 回答依据分层：按行政层级（国家级 / 省级 / 更低级）（todo-8）

**现状**：引用卡片仅展示法规名/条号，无层级区分；检索不区分国家/地方依据。

**层级口径（用户确认）**：依据按**行政层级**分三层展示——
- **国家级**：法律、行政法规、部门规章（国务院及部委制定，如《安全生产法》《建设工程安全生产管理条例》）；
- **省级**：四川省地方性法规、省政府规章（如《四川省安全生产条例》《四川省消防条例》）；
- **更低级**：市级及以下规定、企业规范/制度（如企业安全管理制度、行业标准、操作流程）。

**需求**：
1. **依据分层呈现**：回答引用按行政层级分组展示——国家级 > 省级 > 更低级；层级标识（标签色/分组标题），同一组内再按效力（法律 > 行政法规 > 部门规章）排序。
2. **国家优先**：检索/重排对国家级依据加权（国家规定优先于地方，地方补充细化）；同一主题国家与省均有规定时，回答以国家级为准、省级作补充，并标注层级。
3. **层级识别**：crawler 建库时为每篇文档标注 `region` 与 `doc_level`（国家/省级/更低级，O4 语料入库时统一打标）；
   引用来源扩展：message_source 增加 `doc_level`、`doc_type` 字段（迁移幂等）；历史数据缺省按文档 region 归类。
4. 查看原文弹窗展示行政层级与时效信息（现行/已废止）。

**验收标准**：
- [ ] 回答引用按「国家级 / 省级 / 更低级」三层分组展示，顺序正确（国家级在前）
- [ ] 同一主题国家与省均有依据时：国家级优先引用并标注层级，省级作为补充
- [ ] 建库文档均标注层级（国家/省级/更低级）；历史引用（无层级字段）不报错、按 region 归类
- [ ] 检索结果中地方依据不遮蔽国家依据（国家优先加权生效）

### O8 考试工坊重做：普通用户「生成试卷 → 分享链接 → 收藏他人试卷 → 考试」，仅默认展示自己生成的试卷（todo-9）

**现状**：考试工坊为「管理端出题/组卷 → 员工参加正式考试」模式。用户反馈核心定位收敛为：**普通用户主要使用三个功能——生成试卷、分享链接、考试**；用户默认只看见自己生成的试卷，**但可通过分享链接查看/收藏他人的试卷**（收藏后进入自己的试卷库并可答题）。

**需求**：

1. **普通用户生成试卷（核心）**：
   - 用户进入「我的试卷」页（默认展示**自己创建的**试卷，按 creator 隔离）；
   - 生成方式：从题库选题（全部 APPROVED 题，含管理端 AI 出题与用户自建）或手动录入题目，组成一套试卷（名称/时长/合格线/题目与分值）；
   - 支持编辑/复制/删除自己的试卷；试卷状态：草稿/已分享。

2. **分享链接（核心）**：
   - 每套试卷生成**分享链接**（带 token）；被分享者打开链接 → 查看试卷说明与题目预览（脱敏答案）→ 免登录/登录作答 → 提交即出成绩；
   - 出题人可查看自己试卷的作答统计（参与人数/平均分/通过率/各题正确率）；
   - 链接可停用/过期；分享数据落库（share_mode 标记，与正式考试隔离）。

3. **通过链接查看他人试卷 + 收藏（用户新增确认）**：
   - 打开他人分享链接，可查看试卷概要（名称/时长/题量/题目列表，作答前不暴露答案）；
   - 链接提供「**添加到我的试卷库**」入口：将他人试卷**复制一份到当前用户试卷库**（`source_paper_id` 记录来源，题目以快照复制，编辑不影响原卷）；
   - 收藏成功后，该试卷出现在「我的试卷」页（标记「收藏」来源），可直接**发起答题**（自测）或再次分享；
   - 防滥用：收藏仅通过分享链接进行（非公开搜索他人试卷）；出题人可随时停用链接，停用后新收藏/作答被拒（已收藏副本不受影响）。

4. **用户默认只看见自己生成的试卷**：
   - 用户端「我的试卷」列表默认按 `creator_id=当前用户` 过滤（接口层强制，防越权）；
   - **例外：收藏来源的试卷（copied/source_paper_id 非空）也展示在「我的试卷」**（属用户自己的试卷库）；
   - 用户不直接看到管理端试卷（管理端正式考试入口与管理端试卷仍保留，面向管理员发布流程）；
   - 管理端「考试情况」页可查看全部试卷的作答统计。

5. **考试（核心）**：作答走既有在线考试链路（倒计时/自动保存/自动阅卷）；用户可从「我的试卷」（含收藏副本）直接发起自测。

6. **试卷另存为 Word 文档（用户新增）**：
   - 「我的试卷」页提供「**导出 Word**」：将试卷（名称/说明/题型分组/逐题题干/选项/分值/参考答案与解析）生成为 `.docx` 文档下载；
   - 导出内容区分两种模式：**仅题目版**（不含答案，供打印/分发）与 **含答案版**（题目+参考答案+解析，供备课/留档），导出前可选；
   - 生成方式：后端 `python-docx` 渲染（含标题页、题型分组标题、题目编号、选项缩进、分值标注），文件名 = 试卷名 + 日期。

7. **管理端查看考试情况**：全部试卷作答统计——参与人数、平均分、通过率、各题正确率排行，可按试卷/用户筛选，可导出 Excel。

**验收标准**：
- [ ] 用户默认仅能看见自己创建的试卷（接口层按 creator_id 过滤，越权访问他人试卷 404）
- [ ] 打开他人分享链接可查看试卷概要（答案脱敏）；可「添加到我的试卷库」→ 出现在本人「我的试卷」且可直接答题
- [ ] 收藏副本与原创试卷互不影响（编辑副本不改原卷）；收藏来源有标记（「收藏」/source_paper_id）
- [ ] 链接停用后：新收藏/作答被拒；已收藏副本答题不受影响
- [ ] 用户可生成试卷（选题/手录）、编辑/复制/删除、分享链接
- [ ] 被分享者经链接作答并即时出成绩；链接可停用/过期
- [ ] **试卷可导出 Word（仅题目版/含答案版两模式），docx 可正常打开且内容完整（题号/选项/分值/解析）**
- [ ] 出题人可查看自己试卷作答统计；管理端可查看全部试卷考试情况并导出
- [ ] 回归：v1 正式考试链路全绿，分享考试与正式考试数据不串扰

### O9 用户端/管理端分离：管理端精简为「监管 + 配置」（todo-10）

**现状**：单前端按角色隐藏菜单；管理端现有业务页面（题库/出题/组卷/试卷）与用户端混在同一框架；审计已有 18 类动作 + 查询页。

   - 原管理业务页面（题库/出题/组卷/试卷）从管理端移除入口；其中题库选题/组卷能力由用户端「我的试卷」承接（O8）。
3. **权限细化**：SAFETY 可查看监管类 + 部分配置（文档上传/分块）；ADMIN 全量（含模型设置、用户管理）；接口层维持双门禁。

**验收标准**：
- [ ] 员工/管理端入口分流生效，切换无鉴权漏洞（回归 403 矩阵）
- [ ] 管理端仅含：审计日志、用户管理、数据文档上传、分块策略设置、模型设置五个页面；原业务页入口移除
- [ ] 数据文档上传：上传即建库，列表可见已上传文档与状态
- [ ] 分块策略设置：修改保存 → 重建 → 检索生效；失败可回滚
- [ ] 模型设置：修改保存 → 生效（重启后保持）；模型对比测试入口可跑
- [ ] SAFETY/ADMIN 权限差异在接口与 UI 双生效

### B1 Bug 修复：重启后隐患图片不可见；图片无 AI 识别部分（仅原图）（用户反馈）

**现象**：
1. 系统重启后，历史隐患记录的现场图片在列表中/详情中不可见（图片缺失或无法加载）；
2. 可见的图片只有原图，没有 AI 识别部分（标注框/检测项/识别报告不展示）。

**根因定位（v1 代码核对）**：
- 图片物理文件存 `backend/data/uploads/<日期>/<uuid>.<ext>`，DB 存相对 URL `/uploads/...`；`/uploads` 由 `main.py` 挂载 StaticFiles 服务。重启后不可见的三类可能：① 上传目录未随部署卷持久化（本地/容器切换时 data/uploads 路径不一致）；② 静态挂载目录与写入目录不一致（`settings.upload_dir` 与 main.py 挂载点漂移）；③ DB 中 `hazard_image` 行存在但文件丢失（目录清理/gitignore）。
- AI 识别部分：`/hazards/analyze` 返回 `report`（含 detections/annotated_url），但**是否随上报落库取决于前端是否把 risk_report 传回**——v1 无「选择保留」环节，存在识别后不上报、或上报未带 risk_report 的场景，导致详情只有原图。

**需求**：
1. **图片可见性修复**：
   - 上传目录路径收敛为单一真源（`settings.upload_dir` 与 main.py 挂载点同源，容器版 DATA_DIR/UPLOAD_DIR 卷持久化校验）；
   - 重启自检：启动时校验 uploads 目录存在且可写，记录目录内文件数；
   - 数据修复：对 DB 有记录但文件缺失的图片做巡检报告（管理端可见「失效图片清单」），提供重传/清理入口。
2. **AI 识别部分可见性修复**：
   - 上报请求强制纳入 risk_report（含 kept 标记与勾选后的 detections/annotated_url），后端校验其结构与 analyze 输出一致；
   - 详情页按 risk_report 渲染：`kept=true` 展示标注图 + 检测项卡片（类型/等级/描述/置信度/bbox）；`kept=false` 仅原图；
   - 历史数据兜底：`risk_report` 为空的记录显示「未保留 AI 识别」提示，不报错。

**验收标准**：
- [ ] 重启前后同一隐患图片均可见（列表缩略图 + 详情原图）
- [ ] 上传目录单一真源校验通过；容器版重启后卷内图片完整
- [ ] 识别→勾选保留→上报 的隐患，详情展示标注图与勾选检测项
- [ ] 未保留识别/历史空数据的隐患，详情正常显示原图 + 明确提示，无报错
- [ ] 新增失效图片巡检脚本（或管理端入口），输出缺失清单
