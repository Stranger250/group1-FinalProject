# 检索层优化（召回层）

目标：在 2087 条条文（条均 134.6 字，最长 907 字）的语料规模下，把 A01 的精准检索做到可量化——检索到**正确且最小可回答单元**的条文，为 A01 的来源引用与 A01 的避免幻觉打好底。整体采用**领域过滤 → 混合召回 → RRF 融合 → 交叉编码器重排**的四段流水线，关键参数如下：

| 阶段 | 输入 | 输出 | 手段 |
|---|---|---|---|
| 领域过滤 | 改写后查询 | 候选法规子集 | 元数据过滤（Chroma `where`）+ 法律层级加权 |
| 混合召回 | 查询（原句+改写句） | 各 Top-50 | 向量（bge-large-zh）+ BM25（jieba） |
| 融合 | 两路 Top-50 | Top-20 | RRF（K=60） |
| 重排 | Top-20 | Top-5 | bge-reranker-base（cross-encoder） |
| 供给 LLM | Top-5 | Top-3~5 条文 + 引用 | 附 法规名/章/条号 元数据 |

---

## 1. Embedding 选型：确定 bge-large-zh，暂不精调

在 bge-large-zh-v1.5 与 bge-m3 之间**选定 bge-large-zh-v1.5 作为生产默认**，理由按本语料实测数据逐条给出：

| 维度 | bge-large-zh-v1.5 | bge-m3 | 对本语料的结论 |
|---|---|---|---|
| 向量维度 | 1024 | 1024 | 持平 |
| 最大长度 | 512 token | 8192 token | 见下方"长条文"分析 |
| 检索能力 | 稠密向量 | 稠密+稀疏+ColBERT 多向量 | 稀疏能力与本方案 BM25 重复，边际收益低 |
| 推理成本 | 低（单向量，CPU/ONNX 可跑） | 高（多向量，CPU 显著更慢） | 直接影响 50QPS / ≤3s 预算 |
| 精调门槛 | 成熟，社区权重多 | 较重 | 本方案不需要 |

**关键决策点——长度**：中文约 1 字 ≈ 1 token。本语料条文均长 134.6 字（15–907），**绝大多数（>95%）落在 512 token 窗口内**，仅少数长条文（上限 907 字）会触顶。处理方式不是上 bge-m3，而是**在分块层按"条"为单位切分**：一条条文作为最小检索单元，超过 500 字的单条内按句切子块、子块保留条号前缀（`第X条` 作为块标题），既保住语义完整又不出窗口。之所以敢放弃 bge-m3 的 8192 窗口，是因为**本方案在重排层用 bge-reranker 兜长度**，见第 4 节。

**暂不精调的决策**：法规条文是规范书面语，bge-large-zh 的中文通用能力已覆盖，**首版不做领域精调**。预留判定标准——上线后评测 **Top-5 召回率 < 80%** 时，才用 2087 条做领域对比学习（LLM 构造难负例，条内字面替换做正例增强）。语料仅 2087 条、303,734 字符，切换/重灌 embedding 成本极低，故"先用通用模型，有问题再精调"是风险最优路径。

补充：embedding 必开 `normalize_embeddings=True`（已在本项目 8_10 验证），保证 cosine 可比性；本地加载用绝对路径规避 transformers 相对路径 bug。

## 2. 混合检索：向量 + BM25（jieba）+ RRF 融合

**决策：双路召回 + RRF 融合，非单向量检索，非加权求和。** 理由直接来自本语料的两个数据特征：

1. **172 处内容内"第X条"交叉引用 + 大量精确术语**：法规问题往往依赖字面精确命中——用户会问"《安全生产法》第一百一十三条怎么规定的""有限空间作业必须审批吗"。此类查询靠语义向量（换说法也成立）和靠关键词（"第一百一十三条""有限空间"必须字面命中）各占一半，**单路必然漏召回**。BM25 天然擅长大写数字、法条号、术语的精确匹配，向量擅长口语化表述的语义近似，二者互补。
2. **条文短（条均 134.6 字）**：短文本的 BM25 得分不受长度归一化稀释，关键词命中即高相关，BM25 在"条文级"语料上比在长段落语料上可靠得多，这条数据特征让"BM25 值得上"从直觉变成结论。

**融合算法决策：RRF（倒数排名融合），K=60，而非加权求和。** 理由：
- 向量分数与 BM25 分数**量纲不同且不可比**，加权需要调两组权重，稳定性差；
- RRF 只看排名：`RRF(d) = Σ 1/(K + rank_i)`，K=60 为经验稳定值（本项目 8_10 已实测），鲁棒、零调参、两路分数尺度畸变不影响融合质量。

**实现细节**：
- BM25 用 `rank_bm25` + **jieba 分词**（中文必须分词，否则"有限空间作业"整体切不开）；BM25 的文档即"条"级 chunk，构建在检索服务启动时一次性完成（2087 条，内存级，<10ms 查询）。
- 向量路：Chroma（开发）/ Milvus（生产）余弦检索，取 Top-50。
- 融合后取 Top-20 交重排层。向量 score 下限 `cos ≥ 0.30` 作为粗剪（宽松，精筛交给重排，避免误杀）。

## 3. 查询理解与改写

目标：把"用户怎么问"翻译成"条文怎么表述"。三级改写，**全部带延迟预算与旁路开关**（改写是耗时的 LLM 调用，必须在 ≤3s 首字内消化）。

### 3.1 口语化 → 法言法语（query normalization）

| 用户口语 | 改写为法言法语（检索词） |
|---|---|
| 高速上出了事故找谁 | 高速公路交通事故 应急处置 职责 |
| 隧道里着火了咋办 | 隧道 火灾 应急处置 |
| 高速公路上车子坏了停哪 | 高速公路 故障车辆 停驶 警示标志 |
| 有限空间干活要办啥手续 | 有限空间作业 审批 气体检测 |

实现：**规则初筛 + LLM 改写**。先用轻量规则判断查询是否"非标准"（含口语词库标记词、标点符号、疑问词、长度 > 4 且带"咋/咋办/找谁/要啥"等），命中才调改写 LLM（文心/通义/智谱，`max_tokens ≤ 48`，仅输出改写后检索词），否则原句直通——**约六成规范查询零改写成本**。

### 3.2 多轮对话查询改写（支撑 5 轮多轮对话）

- 维护最近 2~3 轮 + 当前问，LLM 生成**独立成句查询**（standalone query），解决指代消解："它是谁负责"→"（前轮主题）应急管理职责分工"。
- **继承会话上下文中的领域/法规范围**：首轮已锁定"隧道"领域，后续轮次改写结果自动带上该过滤条件，避免第二轮起检索漂移出范围。
- 延迟控制：**仅当满足触发条件才改写**——当前问含指代词（它/这个/该/上述/前面）或 `轮次 ≥ 2 且 当前问 ≤ 6 字`；否则复用首轮改写结果或直通。改写结果做**会话级缓存**（同主题多问可复用）。

### 3.3 同义词 / 术语扩展

构建**蜀道领域术语词典**（人工审核 + 评测校验），仅用于 **BM25 路**（向量路不做扩展，避免引入噪音）：
- 高速公路 ↔ 高速 ↔ 高等级公路；隧道 ↔ 洞室 ↔ 洞身；
- 有限空间 ↔ 受限空间；坍塌 ↔ 冒顶 ↔ 塌方；
- 特种作业人员 ↔ 持证上岗；应急救援 ↔ 应急处置。

扩展方式：BM25 查询 OR 扩展，**每条术语最多扩展 2~3 个同义词**。扩展会抬召回、压精度，故词典必须人工审核，且每次扩展上线跑一轮评测对比（见 §6 评测口径）。同义词扩展是典型的"BM25 兜关键词"增强，与第 2 节混合检索配合使用。

### 3.4 改写链路与延迟预算

改写为**离线/异步**在检索引擎内完成：改写 LLM 调用 100~300ms（GPU 服务化后更低），检索本体 <100ms，重排 100~300ms，**改写→重排整链预算 <1s，为 LLM 生成预留 ≥2s**，满足首字 ≤3s。全部检索组件用 FastAPI 异步服务 + 连接池常驻，支撑 50QPS。

## 4. 重排：cross-encoder 精排（bge-reranker-base）

**决策：重排层必做，用 bge-reranker-base（cross-encoder），对融合后 Top-20 精排出 Top-5。** 理由是本语料的特性决定了重排的"必要性"而非"可选优化"：

- 法规答案是**细节敏感**的——正确条文与混淆条文（同法规不同条、相近术语不同条款）在语义向量上往往邻近，却承担完全不同义务（时限 30 日 vs 15 日、负责部门 A vs B）。向量/BM25 的 bi-encoder 只做查询与文档独立编码，**对"细节差异"钝感**；cross-encoder 让查询与条文**联合注意力**，对这类细粒度判别显著更准。
- 直接服务 A01 的来源引用（引用准确）与 A01 的避免幻觉：Top-5 里混入一条"像但不准"的条文，LLM 大概率引用它 → 幻觉源头。**重排把正确条文顶到首位，是引用可信度的最后一道闸**。
- 代价可控：cross-encoder 只在 **Top-20** 上跑（20 个 `(query, chunk)` 对，GPU <100ms / CPU 数百 ms），对 ≤3s 预算可接受；2087 条语料下这个 top-k 已经覆盖了几乎所有相关条文。

选型：`bge-reranker-base`（512 窗口，条文级足够，快）；若后续引入超长条文或多文档聚合，升级 `bge-reranker-v2-m3`（8192 窗口）。重排分数做**相对排序取 Top-5**，另设绝对下界：若重排最高分过低（经验阈值 `<0.35`，按评测调），判为"无匹配"返回引导话术（"请补充单位/时限/场景"），**宁可少答不乱引，这是防幻觉红线**。

## 5. 蜀道领域过滤

语料含 28 部法规、5 类分类（法律 9 / 地方性法规 6 / 政府规章 5 / 部门规章 2 / 行政法规 6）。为每个 chunk 加元数据：`title / category / doc_no / chapter / article_no(条号) / domain_tags(业务域) / level(上位法/地方法)`。域过滤分两级：

**5.1 域元数据过滤**（Chroma `where`，召回前）：

| 业务域 | 优先命中的法规类型（domain_tags 命中即过滤） |
|---|---|
| 隧道/公路施工 | 高速、道路运输、消防、有限空间 |
| 地质灾害 | 地质灾害、突发事件、应急 |
| 有限空间作业 | 有限空间、安全生产法、安全生产条例 |
| 生产安全事故 | 事故报告、生产责任、突发事件 |
| 道路交通事故 | 道交责任制、道路运输、高速 |

**5.2 意图分域**：查询改写后做一次轻量意图分域（关键词表命中优先，兜底 LLM 分类，标签集合固定）。分域置信度高时**先过滤再召回**（显著降噪音、提 precision）；置信度低时**不过滤全量召回，把域相关性交给重排层**裁决——两级兜底避免误过滤漏召。

**5.3 法律层级优先**：四川条例存在对《安全生产法》的层级交叉引用，且本库以"国家法为上位依据、地方法为主体"。重排分数基础上给**上位法小幅加权（+0.05~0.1）**；并在供给 LLM 的引用元数据中标注法律层级，生成时对"地方法与上位法冲突"场景提示"以上位法为准"——这一条直接响应数据盘点里的"层级交叉引用"质量问题。

## 6. 交叉引用联动召回（针对 172 处内容内"第X条"交叉引用的数据专项）

本语料正文含 **172 处内容内"第X条"交叉引用**——条文 A 规定"按本法第 X 条执行"，用户问的是 A，答案却依赖 X 的实际内容。**决策：在重排后加一次引用解析联动召回**：

1. 解析 Top-3 命中条文中出现的"第X条"引用（正则匹配，去重）；
2. 在同一法规（或按层级映射到上位法）中按条号精确查回被引条文；
3. 将原命中条文 + 被引条文一并进 LLM 上下文，**引用标注为 `法规名·第X条`**。

价值：① 避免 LLM 对"第X条"内容凭空生成（防幻觉直接命中数据痛点）；② 联动条文即"精确检索"的天然答案扩展，显著提升回答完成度；③ 精确条号查找由 BM25 词表索引保证零丢失。查表在内存索引上完成，毫秒级，不占延迟预算。

## 7. 检索性能与参数

**7.1 索引与阈值**：

| 项目 | 取值 | 说明 |
|---|---|---|
| 向量索引 | 开发 Chroma（HNSW/cosine）；生产 Milvus HNSW | 2087 条极小微库，索引构建毫秒级，无需分片 |
| BM25 索引 | 内存 `rank_bm25` + jieba 词表 | 构建一次性、查询 <10ms |
| 召回剪枝 | 向量 `cos ≥ 0.30`；两路各取 Top-50 | 宽松剪枝，精筛交给重排 |
| 融合后 | RRF(K=60) 取 Top-20 | — |
| 重排后 | Top-5，绝对分数 <0.35 判"无匹配" | 防幻觉红线 |
| 进 LLM | Top-3~5 条文，携带 法规名/章/条号 元数据 | 服务 A01 的来源引用 |

**7.2 top-k 取值逻辑**：2087 条语料足够小，召回层可以给足 Top-50（穷尽相关条文），**靠重排层收敛到 Top-5**——"召回宽、精排严"是低成本高收益的组合，不依赖召回层调参抠精度。

**7.3 性能与 QPS 达标**：
- 语料规模 303,734 字符 / 2087 条，检索与重排全部内存级；bge-large-zh 与 bge-reranker 用 **ONNX Runtime 量化**（int8）CPU 部署，embedding <30ms、rerank Top-20 <300ms；
- 整链（改写→召回→融合→重排）预算 **<1s**，LLM 生成预留 ≥2s，满足 AI 回答 ≤3s 首字；
- 服务用 **FastAPI 异步 + 连接池 + 会话级查询缓存**，单实例即可支撑 50QPS；embedding/rerank 模型**常驻内存**，杜绝每次请求加载模型（这是新手最常见的 QPS 杀手）。

**7.4 评测口径（配套 80% 准确率要求）**：离线评测集按业务域抽样 200 问，标定"应命中的条文号"（利用 172 处内容内交叉引用做正例来源）；指标用 **Top-5 条文召回率**（阈值 ≥80%）与**首答引用正确率**（是否命中标注条文）。任何层级的改动（术语扩展、阈值、重排模型）上线前先跑此评测，保证改动可量化、可回滚。
