## 5 生成层（Generation）优化：回答基于知识库、可溯源、不幻觉

生成层是 A01 的来源引用与 A01 的避免幻觉的落地层。设计目标一句话：**让模型只能"照着检索到的块说话"，引用的每一条都能点回原文，检索不到就明说不知道**。本层承接第 4 章混合检索（向量+BM25+RRF）产出的 top-k 块，输出格式化的、带脚注的流式回答。

### 5.1 生成层输入输出与职责边界

| 环节 | 输入 | 输出 | 职责 |
|---|---|---|---|
| 安全前置 | 用户原始问题 | 过滤后问题 / 拦截响应 | 敏感词、涉密、诱导违规拦截（5.8） |
| 会话管理 | session_id + 问题 | 改写后问题 + 历史摘要 | 5 轮多轮上下文（5.6） |
| 检索 | 改写后问题 | top-k 块 + 元数据 + RRF 分 | 来自第 4 章，本层只用其结果 |
| 引用校验 | 注入块列表 | 合法引用集合 | 防伪造引用（5.4.4） |
| Prompt 组装 | 系统 Prompt + 检索块 | 注入后的消息 | 硬约束注入（5.3） |
| 生成 | 注入消息 | SSE 流（meta + delta 事件） | 流式输出（5.7） |
| 输出后处理 | 模型原始流 | 清洗后回答 | 越界角标删除、安全复检 |

关键决策：**检索块放 user message、系统约束放 system message**。理由：① 每轮检索块都变，放 user message 只需替换该段，system message 保持固定可做 Prompt 版本缓存；② 避免长上下文稀释 system 约束；③ 便于后端把"注入块列表"与"允许引用集合"严格对齐做引用校验。

### 5.2 生成模型选型与参数

- **选型决策**：主模型用 **DeepSeek-V3**（实训环境已通过 `BASE_URL/API_KEY/MODEL_NAME` 接通，TTFT 低、SSE 支持好、并发性价比高，符合 50QPS/3s 首字预算）；备选 **通义 qwen-max**（对长文本法律条款的忠实复述表现稳定），通过统一 OpenAI 兼容接口可无缝切换。不用本地部署 LLM——法律回答对生成质量要求高，本地 7B 级模型在"只依据上下文复述"上抖动大，且实训机无推理卡。
- **参数决策**：`temperature=0.1`（法律回答要确定性，不用创造）；`top_p=0.9`；`max_tokens=1024`；`presence_penalty/frequency_penalty=0`（防止打断条款复述的连贯性）。
- **模型输入侧**：注入块截断规则——最多注入 top-5 块（2087 条/134.6 字均长下约 700 字正文，加元数据约 2.2k token，远低于上下文窗口，且与检索 Top-k 一致），超过 5 块按 RRF 分截断。**块即条款，不跨条切分**（见 5.4.1），保证注入内容颗粒度与引用粒度一致。

### 5.3 系统 Prompt 设计

#### 5.3.1 角色设定（面向交通建设企业安全员）

角色定位为"**蜀道安全助手——为交通建设企业安全员提供安全生产法规咨询的专职助手**"。设定三个限定：服务对象是安全员（回答落到"现场安全管理/责任/处罚"场景），知识范围只限蜀道知识库（28 部法规），输出风格严谨（列依据、给原文、不猜测）。角色设定不要写成营销话术，要写成可执行的回答规范。

#### 5.3.2 硬约束："只依据检索到的知识库内容回答"

这是对抗幻觉的第一道闸门，写入 system message 首部：

```
【最高约束】
1. 你只能依据下方 <context> 中给出的知识库条文回答。
2. 回答中的每一个事实断言（罚款金额、期限、责任主体、处罚措施等）都必须能在 <context> 中逐字找到出处，并标注脚注编号。
3. 严禁使用 <context> 之外的任何法律条文、你的预训练记忆或常识推断法律内容。
4. <context> 之外的内容一律不回答。
5. 涉及具体数值/期限/条款号时，必须原样复述 <context> 原文，不得改写、推算或四舍五入。
```

第 5 条针对实测数据中的"172 处第X条内容交叉引用"和大量数字条款（期限、金额），是最容易产生幻觉的点——模型倾向"补充常识"，必须用"原样复述"压死。

#### 5.3.3 未知不编造 → 拒答引导

检索层判定"无充分依据"（见 5.5.2）时，不走模型自由发挥，直接注入固定话术（模板放 prompt 中，检索层命中后替换为最终话术）：

```
抱歉，知识库中没有检索到与您问题直接相关的条文。当前知识库收录 28 部安全生产法规（2087 条），您的问题可能涉及：
· 企业内部制度/操作规程/事故案例（该类资料尚缺，已记录您的需求，将反馈补充）——建议补充后再问；
· 未收录法规或您的问题过于宽泛——建议按"法规名 + 关键词"提问，例如"四川省安全生产条例 有限空间作业 审批要求"。
```

拒答不是空壳，而是**带检索建议的引导**，把"不知道"转化为可改进路径（也是人工补充知识库的入口，呼应知识库定位）。

#### 5.3.4 完整 Prompt 草案（可直接落地）

```
【system】
你是"蜀道安全助手"，面向交通建设企业安全员提供安全生产法规咨询。
服务范围：蜀道安全知识库收录的 28 部安全生产法规（法律9部、行政法规6部、地方性法规6部、政府规章5部、部门规章2部）。
回答要求：
1. 只依据 <context> 条文回答，每句事实断言标注 [n] 脚注，n 对应 <context> 中条块编号。
2. 数值、期限、条款号一律原样复述原文。
3. 原文未覆盖的内容不回答；检索不足时给出 5.3.3 拒答话术并给检索建议。
4. 引用多部法规且结论冲突时，按层级给出：上位依据（国家法）优先，并并列列出地方规定（见 5.5.4）。
5. 不输出任何政治性、涉密、诱导违规内容；涉及处罚条款只陈述原文，不做主观评价。
6. 回答结构：结论（1-2 句）→ 依据原文（分点）→ 引用来源列表（见 5.4.3）。

【user】
<context>
[1] block_id=scaq_第二十一条_v2023 | 四川省安全生产条例 | 第二章 安全生产保障 | 第二十一条 | 内容……
[2] block_id=scaq_第二十二条_v2023 | 四川省安全生产条例 | …… 
（仅检索到的 top-k 块，最多 5 个）
</context>
【历史摘要】第 1 轮：用户询问有限空间作业审批要求，已答依据四川条例第 21 条……
【本轮问题】……
```

**决策**：context 与历史摘要、本轮问题都放 user message 内，用明确分隔标签。历史摘要仅存"实体+法规名+结论要点"，不逐字存（控 token、防上下文稀释），见 5.6。

### 5.4 引用机制（A01 的来源引用验收点）

#### 5.4.1 块元数据与 block_id 设计（对齐实测数据）

知识库 199 章 2087 条、均长 134.6 字（最大 907 字）、全文 30.4 万字符——**每条"第X条"天然是一个语义完整的块，直接以条款为块单元，不做跨条切分**。这与 bge-large-zh 的 512 token 窗口、500 字 chunk 设置天然兼容（907 字最大条也仅约 1.8 个 chunk，可用 overlap 覆盖）。

block_id 结构 = `{doc_id}_{article_no}_{version}`，块元数据：

```json
{"block_id":"scaq_第二十一条_v2023",
 "doc_id":"scaq",
 "title":"四川省安全生产条例",
 "doc_no":"川人大〔XXXX〕X号",        // 空则留空，不强造
 "category":"地方性法规",              // 法律/行政法规/部门规章/政府规章/地方性法规
 "chapter":"第二章 安全生产保障",
 "article_no":"第二十一条",
 "text":"……原文 134.6 字……",
 "char_count":134.6,
 "source_url":"……/docs/scaq/第二十一条"}
```

理由：① 引用可直接到"条"，这是 A01 的来源引用的最小可信粒度；② category 字段支撑 5.5.4 的层级判断；③ doc_no 为空的数据质量问题由清洗层处理（不强造文号），生成层只透传。

#### 5.4.2 回答内脚注标注 [1][2]

回答正文用 `[n]` 脚注，**n = context 中块的注入序号**（与 5.3.4 的 `[1]…[n]` 一一对应）。规则：一条依据原文句子后跟一个 `[n]`；同一段落引用多块时用 `[1][2]` 并列。禁止模型自造编号——编号集合由注入块决定，模型只是"点选"。

示例：
> 有限空间作业前应制定作业方案并经审批，未经审批不得作业[2]。作业方案应包括风险辨识、防控措施和应急处置[2][3]。

#### 5.4.3 引用来源列表（回答末尾）

回答末尾固定输出"引用来源"列表，由后端**从 meta/done 事件的 citations 累积数据组装，而非由模型生成**（杜绝模型编造来源）。格式：

```
【引用来源】
[1] 《四川省安全生产条例》第二章 第二十一条｜川人大〔XXXX〕X号｜地方性法规｜[查看原文](url)
[2] 《四川省安全生产条例》第二章 第二十二条｜…… 
[3] 《安全生产法》第三章 第四十条｜法律｜[查看原文](url)
```

理由：来源列表是 A01 的来源引用验收点，由模型自由写会引入"有脚注但无对应来源"的伪造；改为后端依据实际注入块的元数据渲染，保证 100% 可点回原文。

#### 5.4.4 引用合规后处理（防伪造引用）

模型仍可能输出越界角标（如 context 只有 5 块却输出 [6]）或"有脚注无来源"。后端加 **grounding 校验器**（在流式结束、缓存入库前执行）：

1. 正则提取回答中全部 `[n]` 角标；
2. 校验 n ≤ 注入块数且该块确实在本轮注入列表内；越界角标从回答中删除；
3. 若删除后回答正文无任何有效脚注 → 判定"无依据回答"，触发重生成（最多 1 次）或降级为拒答话术；
4. 可选加强：对每个断言句与其引用块做 embedding 余弦相似度（bge-large-zh，复用检索向量），低于 0.60 的句子打标"待人工复核"并标注在管理端。

该校验器同时是 A01 的来源引用自动评测的一部分（见 5.9）。

#### 5.4.5 交叉引用处理（172 处"第X条"）

实测正文内容含 172 处"第X条"真实交叉引用（全文含 2087 个条号头在内共字面出现 2259 处，如四川条例引用国家安全生产法第几条）。决策：**生成层不展开交叉引用**——模型展开可能引入记忆里的错误条文。策略：
- 回答中提到其他条款时，若该条在库内，脚注照常（该条可能是另一检索块）；若不在本轮检索块内，则原样保留"依据安全生产法第X条"字样但不给脚注，并在来源列表加一行"※ 第X条原文未在当前知识库检索范围内，建议点击查看全文"；
- 这是防止"模型替交叉引用补全原文"的最稳做法，也把交叉引用当作后续"关联检索 + 点击跳转"的埋点。

### 5.5 幻觉抑制策略

#### 5.5.1 强制引用（grounding 驱动生成）

通过 5.3.2 硬约束 + 5.4.4 后校验双保险，把"先有依据再生成"固化为管线：**没有检索块 → 不进入生成**。检索层空结果直接走 5.5.2，不调 LLM，既防幻觉又省一次调用。

#### 5.5.2 无检索结果 → 拒答 + 检索建议

判断分支（与检索层联动）：

| 情形 | 判定 | 动作 |
|---|---|---|
| top-1 块归一化 RRF 分 < 阈值 | 无充分依据 | 拒答话术 + 检索建议（5.3.3），不调生成 |
| top-1 在阈值以上但 < 保守线 | 依据偏弱 | 保守模式：只答单点结论，末尾附"建议查阅原文" |
| top-1 ≥ 保守线 | 正常生成 | 全量回答 |

阈值的标定方法（实训可跑）：用 2087 条构造正样本 query（改写自条款内容）与 50 条无关 query 负样本，测两组 RRF 归一化分的分布，取正负样本分位数的中间值。起步可用经验值 **top-1 < 0.30 拒答、0.30–0.45 保守模式**，上线后按人工抽检校准。

#### 5.5.3 置信度阈值

RRF 融合得分经 min-max 归一化后即为生成置信度输入，与 5.5.2 共用一套阈值。对**多轮追问**场景，改写后 query 的置信度可能波动，故置信度在"改写后"再算，避免改写失败导致假阳性。

#### 5.5.4 多文档一致性校验（28 部法规层级）

实测分类含 9 部法律、6 部行政法规、2 部部门规章、5 部政府规章、6 部地方性法规，且存在"四川条例引用国家安全生产法"的层级交叉。决策：**规则优先级 = 法律 > 行政法规 > 部门规章 > 政府规章 > 地方性法规**。处理流程：

1. 检索块含 ≥2 部法规且主题重叠（同一条款关键词命中）时触发一致性检查；
2. 将候选块交给 LLM 做结构化判定：`{conflict: true/false, summary, level: "上位/下位", verdict: "以下位法补充/以上位法为准"}`；
3. 判定冲突时，生成侧输出并列结构：`上位依据：安全生产法第X条……；地方补充：四川省安全生产条例第X条……`，并加提示"两者不一致时以国家上位法为准，具体执行请咨询企业法务"——**不替用户裁决**，把冲突显式暴露给安全员，比悄悄选一个更符合法律实务。

#### 5.5.5 置信度外的兜底：人工审核

对"处罚金额/事故等级/审批流程"三类高风险断言，管理端提供一键"引用原文比对"（点击脚注即看到 5.4.4 校验器打分与原文并排）。A01 的避免幻觉验收按 5.9 的幻觉率抽检。

### 5.6 多轮对话：5 轮上下文管理

#### 5.6.1 会话状态与历史摘要

- 会话槽：`session_id` 维度的 Redis/内存会话，**上限 5 轮**（对应 PRD A01"支持 5 轮多轮对话"），第 6 轮提示"本次会话已达 5 轮上限，建议新开会话"并归档。
- **历史不逐字存，只存每轮摘要**：每轮回答结束后，用轻量模型或规则把「用户问 → 2-3 句摘要（含法规名、条款号、关键实体、结论）」写入历史队列。注入时拼接为一段"历史摘要"文本。理由：法律条款长、逐字存会迅速稀释 context，且历史摘要专门保留"实体+条款号"供改写使用。

#### 5.6.2 本轮 Query 改写

改写解决"它/那个条例/刚才那条"类指代。做法：**本轮原始问题 + 历史摘要 → 改写规则**（不上重模型，规则+轻量模型皆可）：

| 原问题（第 2 轮） | 历史摘要关键实体 | 改写后检索 query |
|---|---|---|
| 有限空间作业要备案吗？ | 第1轮：有限空间作业审批，四川条例第21条 | 有限空间作业 审批 备案 四川条例 |
| 它的罚款标准是多少？ | 第1轮：未审批进行有限空间作业 | 未审批 有限空间作业 罚款标准 处罚 |
| 那国家法怎么规定？ | 第1轮：四川条例第21条 | 安全生产法 有限空间作业 规定 |

改写后 query 仅用于检索；生成时历史摘要也一并注入，保证回答承接上文。**决策：改写发生在检索之前**，因为不指代清楚检索就捞错块。

#### 5.6.3 引用追溯

- **引用只指向当轮注入块**，历史摘要不携带脚注（避免跨轮引用错乱）；
- 前端支持点击脚注查看原文（块级），并标记该条来自"第 N 轮"——若用户追问"你上轮说的第 21 条"，改写把"第 21 条"带回检索，重新命中该块并给出**本轮新脚注**，实现跨轮追溯。

### 5.7 流式输出与引用同步返回（SSE）

#### 5.7.1 SSE 事件协议

```
GET /api/chat/stream  →  SSE
event: meta          // 第 1 个事件（引用预声明）：预声明本轮将引用的块列表（由注入块直接生成，不依赖模型输出）
data: {"citations":[{"n":1,"block_id":"scaq_第二十一条_v2023","title":"四川省安全生产条例","chapter":"第二章 安全生产保障","article_no":"第二十一条"}]}

event: delta         // 文本增量
data: {"content":"有限空间作业前应制定作业方案并…"}

event: done          // 结束：附完整引用列表与统计
data: {"answer_id":"...","citations":[...],"grounding_score":0.92,"elapsed_ms":2800}
```

**决策：引用元数据先于文本发出（预声明）**，理由：
- 前端可先渲染"依据：四川条例 第二十一条"占位行，文本流到 `[1]` 处即可高亮，无需后端事后解析，首屏体验更好；
- 后端无需在流中解析角标——文本与引用解耦，校验器仍做最终校验，但展示不依赖它。

#### 5.7.2 引用同步返回与前端高亮

前端规则：`[n]` 在渲染时转为脚注（`<sup>`），悬停显示"法规名/文号/章/条"，点击跳原文；正文中被引用的条款对应句子高亮；末尾来源列表由 `done` 事件组装。角标高亮与 meta 事件按 n 匹配，天然同步。

#### 5.7.3 3 秒首字与 50QPS 的生成侧保障

- **首字 ≤3s**：首事件为 meta（引用预声明，毫秒级、不依赖 LLM）；LLM 侧选 TTFT 低的 DeepSeek，且 system prompt 固定可做前缀缓存（API 侧 KV cache 命中），delta 事件边生成边 flush；检索层预算 ≤600ms（第 4 章保障），余量留给 LLM TTFT。
- **50QPS**：LLM 推理是吞吐瓶颈（单路约 1–2 QPS）。三道措施：① **语义缓存**——相同/相似 query（embedding 余弦 > 0.95）直接复用答案，命中率目标 30%，把实际打到 LLM 的 QPS 摊薄；② 模型实例并发池（多 key 轮询 / 负载均衡，DeepSeek API 支持高并发，预算 30–40 并发）；③ 超时与熔断——单轮生成超 8s 熔断降级为"已检索到依据，正在生成中，请稍后刷新"占位，避免请求堆积拖垮后续。缓存按 session+query 维度做 5 分钟 TTL。

### 5.8 敏感词过滤与安全审核前置

- **前置服务（请求进入生成管线前）**：敏感词过滤（政治敏感、涉密、人身攻击、诱导违规），采用"自建词典 + 开源基础词库"双源，命中即拦截并返回固定提示，不进 LLM（省算力且从源头杜绝）。
- **生成侧复检**：模型输出流式过一遍同样的过滤器，命中即终止该 delta 并打标（防止模型被诱导越狱输出）。
- **Prompt 内置护栏**：5.3.4 中第 5 条硬约束——不输出政治性/涉密内容，涉处罚条款只陈述原文不做评价。
- **涉法内容专规**：凡涉及法律条款，只允许引用库内原文，禁止模型"创作"法条（对应 5.3.2 第 5 条原样复述约束）。此条同时服务 A01 的避免幻觉与合规要求。

### 5.9 Prompt 版本管理与效果评估（对应 A01 的来源引用/避免幻觉）

- **Prompt 版本化**：system prompt 与拒答话术存配置中心（带 version 字段），引用来源、结构指令的改动可回滚、可 A/B。
- **评测集**：从 2087 条抽 200 条构造 Q-A 对，覆盖 5 类法规与高危险条款（处罚/事故等级/审批流程）；另加 30 条库外/无依据 query 测拒答正确率。
- **A01 的来源引用指标**：引用覆盖率（有脚注回答占比，目标 ≥95%）、引用可核验率（脚注点击跳原文成功率，目标 100%，由 5.4.4 校验器自动统计）、来源列表完整率。
- **A01 的避免幻觉指标**：幻觉率 = 人工抽检中"与引用块不符的断言"占比（目标 ≤5%）；拒答正确率 = 库外 query 正确拒答占比（目标 ≥95%）。

生成层与检索层（第 4 章）联动即可闭环：检索保证"捞得准"，生成保证"答得稳、答得可溯源"。下一章将给出各模块的部署与性能测试方案。
