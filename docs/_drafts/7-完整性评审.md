# RAG 优化方案 完整性评审结论

## 1. 已覆盖要点清单

六大章已覆盖：知识库构建（三层语料/元数据 Schema/增量与修订/企业文档补入/质量治理）、检索层（混合召回+RRF+重排+领域过滤+交叉引用+评测口径）、生成层（防幻觉硬约束/引用机制/多轮/SSE/敏感词/拒答引导）、AI 出题（四题型模板/难度评分/去重/干扰项溯源/≥80%审核口径）、评估闭环（评测集/检索与生成指标/回归门禁/线上反馈/出题专项评测）、工程与性能（指标分解/多级缓存/限流并发/SSE 协议/成本/部署/内容安全），并对接了 50QPS、≤3s 首字、5 轮多轮、A01 的来源引用、A01 的避免幻觉、AI出题≥80%、SSE 七项硬指标。

## 2. 缺失或可强化的点

1. **跨章数据契约/参数冲突统一**（缺）：分块阈值（400字父子块 vs 检索层"500字切分" vs 工程层"2087条即2087块不切"）、注入 LLM 的 top-k（Top-3~5 vs Top-10）、max_tokens（1024 vs 800）、块 ID 体系（知识库 chunk_id 与生成层 block_id 已统一为 `{doc_id}_{article_no}_{version}`= `scaq_第二十四条_v2023`；评估层主键 `法规标识_第X条` 仍为另一套人读式，需明确与 chunk_id 的转换）、条号字段已统一为 `article_no`；且知识库 2.4 元数据 Schema 里**没有**出题专项要求入库预计算的 `difficulty` 字段。建议：建"参数配置中心+数据契约清单"作唯一真源，加一致性门禁。重要性：**高**（直接导致实现走样）。
2. **多轮对话无评测**（缺）：PRD A01 的 5 轮多轮是硬指标，但评估章三类样本（法规问答/场景问答/边界拒答）完全没有多轮集，也无指代消解率、上下文承接、跨轮引用追溯指标。建议：补 5 轮多轮评测集与目标值。重要性：**高**。
3. **AI 出题≥80% 口径两处定义冲突**（缺/冲突）：出题专项 §5 定义为"审核通过率=（直接通过+文案润色后通过）/批次总数"，评估章 8.4 定义为"单题只要答案或解析任一项错误即计错"的从严口径。建议：统一对外口径、写明分母与通过判定。重要性：**高**。
4. **性能验收/压测方案缺失**（缺）：三处都给了预算推导，但无 locust/k6 压测计划、无 50QPS 下 125 在途请求叠加 LLM Semaphore(8~16) 后排队延迟是否仍≤3s 的验证、无端到端首字验收与回滚门禁。建议：补性能测试方案与指标验收表。重要性：**高**。
5. **交叉引用展开执行层归属不明**（缺/冲突）：知识库 2.2.3、检索层 §6、工程层 4.2 三处都做"检索时展开"，生成层 5.4.5 却决策"生成层不展开"。建议：明确唯一执行层、防双重展开/前后逻辑冲突。重要性：**高**。
6. **权限过滤未落地检索管线**（缺）：元数据有 `access_level`，但检索层 §5 领域过滤无权限过滤步骤，"内部/机密"可见范围未实现。建议：在召回前加权限 where 过滤与降级策略。重要性：**中**。
7. **AI 合成内容标识与合规**（缺）：只有敏感词过滤，无《人工智能生成合成内容标识办法》要求的显式/隐式合成标识、无审计留痕说明。建议：补标识与合规章节。重要性：**中**。
8. **冷启动/缓存未命中路径**（缺）：L3 语义缓存命中率目标 30%，但未补冷启动方案（embedding/rerank 模型首次加载、连接池预热、prompt 前缀缓存、缓存全失时的兜底延迟）。重要性：**中**。
9. **检索/重排/拒答阈值未联合标定**（缺）：cos≥0.30、重排<0.35、RRF 归一化 0.30/0.45 是不同分制的三套阈值，各章孤立设定，无统一归一与联合回归流程。重要性：**中**。
10. **"查看原文"浏览接口缺失**（缺）：A01 的来源引用"点击跳原文"只有 `source_url`，无按 doc_id/条号取全文的接口与权限设计。重要性：**中**。
11. **评测集三处定义规模不一致**（缺/重复）：评估章（2200/600/300）、生成层 5.9（200+30）、出题（200/620）各建一套。建议：统一评测集管理、版本号与回流规则。重要性：**中**。
12. **企业文档层与出题/检索衔接**（缺）：2.6 企业文档（制度/规程/案例）入库后，是否进入出题取料、`access_level` 与出题审核关系、案例"结论性要点"是否参与难度评分，均未定义。重要性：**低**。

## 3. 各章节间重复或冲突之处

1. **生成模型选型直接矛盾**：生成层 5.2"主模型 DeepSeek-V3、备选 qwen-max"vs 工程 4.7"首选文心 ERNIE-Speed/qwen-turbo 小模型、高难路由大模型"。两处都写成"决策"。
2. **分块策略冲突**：知识库 2.3.2（400字阈值、父子块、召回只做子块）vs 检索层 §1（500字按句切）vs 工程 4.2"2087 条即 2087 个 chunk、不切分"。
3. **注入 LLM 的 top-k 冲突**：检索层 7.1/生成层 5.2（Top-5、最多 5 块）vs 工程 4.2/4.7（top10）。
4. **max_tokens 冲突**：生成层 5.2（1024）vs 工程 4.2/4.7（≤800）。
5. **SSE 事件协议重复且命名不一致**：生成层 5.7.1（citation/delta/done）vs 工程 4.6（meta/delta/done + ping 心跳），同一协议两处定义。
6. **多轮改写重复**：检索层 §3.2 与生成层 5.6.2 各写一套多轮指代改写，未明确改写归属检索层还是生成层。
7. **交叉引用展开重复+冲突**：知识库 2.2.3、检索层 §6、工程 4.2 三处都实现联动召回，与生成层 5.4.5"不展开"冲突。
8. **AI 出题准确率口径冲突**：出题专项 §5 vs 评估 8.4（含文案润色 vs 从严"完全正确"），见上第 3 条。
9. **拒答/无匹配阈值两套分制**：检索层 §4"重排最高分<0.35"vs 生成层 5.5.2"RRF 归一化 0.30 拒答 / 0.30–0.45 保守"，未说明两套分数如何换算与协同。
10. **块 ID/字段命名（已统一，残留评估主键口径）**：doc_id 命名（`aqscf`/`scaq`）；知识库 chunk_id 与生成层 block_id 已统一为 `{doc_id}_{article_no}_{version}`（`scaq_第二十四条_v2023`）；评估层主键 `法规标识_第X条`（如 `安全生产法_第114条`）为另一套人读式，建议文档注明二者转换；条号字段各章已统一为 `article_no`。
11. **元数据字段缺口**：知识库 2.4 Schema 未含出题专项要求的 `difficulty` 字段，也未统一 `domain_tags`（检索层 §5 用到但 2.4 表无此列）。

总体判断：方案完整度很高，最大风险不在"缺模块"而在"跨章数据契约与参数口径不统一 + 多轮/性能两类硬指标缺验收方法 + 出题准确率口径自相矛盾"，建议先补一处"全局参数与数据契约清单"再落代码。
