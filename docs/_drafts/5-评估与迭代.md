# 【评估与迭代】RAG 效果评估与迭代闭环

## 一、总体思路：三层闭环

| 层 | 环节 | 目标 |
|---|---|---|
| 离线层 | 评测集构建 → 自动化评测 → 回归门禁 | 用可重复的量化指标约束每次改动 |
| 在线层 | 日志埋点 → 点赞/踩回流 → 难例入库 | 让真实使用数据反哺评测集与模型 |
| 专项层 | AI 出题独立评测流程 | 单独保障模块三准确率 ≥ 80% |

整个体系建立在一条强监督信号上：**条号即答案**。本知识库 28 部法规、2087 条条文均带 `article_no: 第X条` 编号，正文含 172 处"第X条"内容内交叉引用（全文"第X条"字面出现 2259 处，含 2087 个条号头）。因此"引用了哪几条"天然可精确判定，无需依赖模型主观判断即可完成大半指标自动化——这是本方案相对通用 RAG 评测的最大红利。

## 二、评测集构建

### 2.1 检索粒度决策
条文均长 134.6 字（15–907 字），远小于常见 chunk 上限，**直接以"条款"为检索单位、以"第X条"为块 id**。不另做 chunk 切分，避免跨条截断破坏引用完整性。评测中的"标准答案"统一用条号表示，天然对齐检索单位。

### 2.2 三类样本与生成方式

| 类别 | 数量 | 生成方式 | 判定依据 |
|---|---|---|---|
| 法规问答 | ≈2200 | 规则模板 60% + LLM 生成 40% | 标准答案 = 条号，可精确判定 |
| 场景问答 | ≈600 | LLM 生成 + 人工修订 | 跨法规检索（四川条例引用国家法），标准答案含多条条号 |
| 边界拒答 | ≈300 | 人工编写 + LLM 扩展 | 应拒答 / 应说明缺乏依据 |

**法规问答（规则模板）**：对每条条文按固定的事实类型抽取问法，覆盖处罚金额、期限、主体、程序四类。例如以《安全生产法》第 X 条内容生成"违反本条规定的罚款金额是多少？""整改期限是几天？"。规则模板利用条文结构（条文多为"应当/不得/处…罚款/自…起"句式）做正则切分，生成率低时用 LLM 补足。

**法规问答（LLM 生成）**：输入 = 单条条文全文 + 其交叉引用条文（用正则抽出的 172 处内容内引用关系做引文扩展），输出 = {question, standard_article_no, reference_article_nos}。LLM 生成部分必须逐条做"答案可回溯校验"：生成内容必须出现在输入条文中，否则丢弃。

**场景问答**：模拟一线工人/安全管理员提问，设计跨法规消歧样本——例如四川某条例与上位国家法对同一行为规定不一致时，应优先检索并引用哪条（知识库定位：国家法为上位依据、四川法规为主体），这类样本专门压测"层级交叉引用"这一数据质量短板。

**边界拒答**：两类典型——知识库外（合同纠纷、具体赔偿金额计算）与**知识库"尚缺"类**（企业内部操作规程、事故案例：盘点结论明确这些企业文档未入库），模型必须拒答或回复"当前知识库无可靠依据"，不得编造。

### 2.3 抽样与人工抽检
- 2087 条按法规 × 章节分层抽生成，覆盖 28 部法规、199 章全部；重点加大地方性法规 6 部 + 政府规章 5 部权重（主体定位）。
- 人工抽检 10%（约 310 题），双人独立标注 + 计算 Kappa 一致性（目标 ≥ 0.8），不一致样本三人复议。
- 评测集冻结：80/20 划分后，评测子集一旦冻结不再改动，仅回流新增。

### 2.4 数据格式
```json
{
  "version": "20260811-v1",
  "category": "法规问答",
  "question": "……？",
  "standard_article_no": ["安全生产法_第114条"],
  "reference_article_nos": ["安全生产法_第94条", "四川条例_第X条"],
  "refuse": false,
  "source_doc": "title + doc_no"
}
```
条号统一用 `法规标识_第X条` 主键，跨法规不重名（11 部四川法规均含"第X条"，必须前缀去歧义）。

## 三、检索指标

| 指标 | 定义 | 目标值 |
|---|---|---|
| Recall@5 | 标准答案条号出现在前 5 个检索块的比例 | ≥ 0.92 |
| MRR | 首个命中条号的倒数排名均值 | ≥ 0.85 |
| NDCG@5 | 按条号相关度分级的折损累积收益 | ≥ 0.90 |
| 命中条号正确率 | 标准引用条号 ∈ 检索块集合的比例（集合级，非排名） | ≥ 0.95 |

计算要点：
- 检索块返回结构需暴露 `article_no` 字段，指标脚本直接比对条号集合，不依赖语义相似度阈值。
- 单独统计 **Recall@k 的 top-1 命中率**（≥ 0.7），因为在线只展示 top-1，该指标与用户感知最相关。
- 负样本专项：同主题易混条文对（如四川某条例与《安全生产法》同性质条款）单独成集，检验跨法规消歧能力，避免"检索出条文但条号错"的隐性错误。

## 四、生成指标

| 指标 | 定义 | 判定方式 |
|---|---|---|
| 忠实度 faithfulness | 回答中每句关键声明能否在检索块中找到依据 | LLM-as-judge 逐句打分 |
| 引用正确率 | 回答引用的条号集合 ⊆ 检索块条号集合 | 规则精确比对 |
| 幻觉率 | 出现检索块中无依据的事实性内容 | judge 判定 + 条号交叉校验 |
| 拒答正确率 | 边界样本中正确拒绝或明示缺依据的比例 | 规则 + judge |

**引用正确率采用纯规则判定**：从回答文本用正则抽取"第X条"、匹配条号主键，判断是否全部落在检索块集合内。这是零成本、确定性指标，作为每次评测必跑项。
**忠实度/幻觉率采用 LLM-as-judge**：将检索块原文与回答逐句切片，判定每句是否被原文支撑；"事实在块内但逻辑推不出"计入忠实度扣分，"块内完全无依据"计入幻觉。

## 五、自动化评估方法

**决策：规则层 + LLM-as-judge 双层结合，先规则后 LLM。**

1. **规则层（零成本、确定性，全量必跑）**：命中条号正确率、引用正确率、拒答正确率、多选题答案格式校验。全部基于条号主键比对，秒级完成 2200 题，作为第一道防线。
2. **LLM-as-judge 层（抽样跑，控制成本）**：仅对规则层无法判定的样本（忠实度、幻觉、开放回答质量）跑 judge，法规问答与场景问答各抽 30%。
   - **judge 模型选择**：固定一个国内 API 模型（建议通义 qwen-plus 或智谱 GLM-4），不随被评模型换版。理由：①judge 与被评模型同厂会引入系统性偏差（自评偏乐观），选独立来源；②国内 API 成本可控，千字打分费用可忽略。
   - judge 输出结构化为 JSON：`{"faithfulness": 1-5, "hallucination": true/false, "reason": "…"}`，同一模型固定 prompt 模板（评分标准写死），避免跨版本漂移。
3. **一致性校准**：首个版本用 100 题双轨运行（规则 + judge），验证 judge 与规则判定一致率 > 95%，不达标则调 judge prompt，达标后才信任 judge 单测结果。
4. **批量流水线**：一条命令跑完整评测，输出 `report.json`（各指标汇总、按法规/类别分维度、失败样例前 50 条含检索块与答案快照），失败样例进难例库。

## 六、回归测试

- **触发时机**：知识库增删改（新增法规/补录内部制度）、embedding 模型换版、检索参数调整（top-k、重排阈值）、prompt 或生成模型换版。
- **基线锁定**：首次发布上线版本跑通全量评测集后，指标结果写 `baseline.json` 并 git 存档；后续每次改动跑同一冻结评测集，与基线对比。
- **门禁规则**：命中条号正确率、幻觉率两项主指标回退超 1 个百分点即阻断上线；Recall@5 回退超 2pt 阻断。允许单指标波动时，必须附失败样例差异说明。
- **版本管理**：评测集 JSON 带 `version` 字段；回归报告落 `versions/{date}-{change_desc}.json`，支持历史任意两版 diff。

## 七、线上反馈闭环

1. **结构化日志**：每次问答记录 `{query, retrieved_article_nos, answer, cited_article_nos, latency, feedback}`，feedback 取值为 点赞/踩/未评。日志表按日分区，SSE 流式输出对埋点无额外负担。
2. **回流规则**：全部"踩"样本 + 随机 5% 点赞样本 + judge 低分样本，进 Kafka 难例队列，按周聚合。
3. **难例入库**：每周 Top-100 难例（踩样本按频次 + judge 幻觉分排序）人工复核，判定错误类型——检索失败、引用错误、幻觉、拒答失误四类；正确修正后的样本回流评测集（走 2.3 人工抽检同流程），同时沉淀为 prompt 示例与微调数据。
4. **闭环指标**：监控每周"踩率/被拒答率/引用命中率"趋势，与离线评测集指标对照——离线高分而线上踩率高，说明评测集覆盖不足，反向扩充该类别样本。

## 八、AI 出题准确率 ≥ 80% 专项评测

出题与问答共享同一知识底座，但验收标准独立，单设流程。

### 8.1 出题评测集
从 2087 条按 法规 × 章节分层抽样 200 条，每条生成 单选 1 题、多选 1 题、判断 1 题，另抽 20 条生成填空——共约 620 题。难度分基础/进阶两档（按条文内容复杂度与是否涉交叉引用判定）。

### 8.2 自动一致性校验（规则层，全量跑）
- **答案可判定性**：题面与选项仅使用给定条文及其引用条文（利用 172 处内容内引用关系扩展知识范围），答案必须能从原文明确推出。
- **选项质量**：四选项无重复、无同义改写、无"以上都对"式取巧；正确选项唯一。
- **解析规范性**：解析必须含"依据《XX》第X条"且条号在主键库中真实存在、属于该题知识范围——直接复检了出题是否忠实原文。
- **知识点一致性**：题目声明的知识点标签与条文实际内容经 judge 校验一致。

### 8.3 人工审核抽样
- **线下验收**：620 题全量双人审核（准确率门槛为上线前置条件，不可只抽检），Kappa ≥ 0.8；审核不通过的题目记录错误类型（答案错误/选项歧义/解析引用错/知识点不符），据此统计准确率。首版不达标则调出题 prompt + 扩大校验规则，再生成重测。
- **上线后持续抽样**：每周随机抽 30 题人工复核，统计准确率趋势；连续两周 < 80% 触发题库停用、重跑生成与审核。

### 8.4 判定口径
准确率分母 = 人工审核判定"完全正确"的题数 / 审核总数；单题只要答案或解析任一项错误即计为错误，从严口径（高于常见"答案正确即可"口径），保证 80% 是安全水位。

## 九、迭代优先级

1. **第一迭代（上线前）**：完成评测集 10% 人工抽检 + 规则层全量跑，锁基线；专项出题 620 题全量人工审核过线。
2. **第二迭代（上线后 2 周）**：接通线上日志与踩反馈回流，首周难例人工复核；扩充场景问答与边界拒答样本。
3. **第三迭代（知识库补录后）**：内部制度/操作规程入库时，重跑回归门禁，同步把新文档加入场景问答构造来源，验证"尚缺→补录"闭环有效。
