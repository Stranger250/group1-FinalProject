## 二、AI 出题专项：模块三 E02（AI 出题）的 RAG 专项优化

### 1. 出题场景与问答场景的差异及检索策略

出题（E02）复用 A01 的向量索引（bge-large-zh + Chroma，条文级 chunk），但**检索模式与问答完全不同**，不能直接复用问答链路。

| 维度 | A01 问答 | E02 AI 出题 |
|---|---|---|
| 输入 | 自然语言问题（一条） | 知识点 + 难度（结构化） |
| 检索目标 | top-1 相关条文，答准即可 | **每个知识点捞多条相关条文**，构成"题目取料包" |
| 召回粒度 | 相关度优先 | 知识点标签过滤 + 难度过滤 + 相关度排序 |
| 对单条依赖 | 高（答案来自最相关条文） | 低（1 题需要 1 正确条文 + 2~4 干扰条文） |
| 时效性 | 在线、SSE、≤3s 首字、≥50QPS | **离线批处理，不占在线并发指标**，对准确率极度敏感 |
| 输出 | 自然语言回答 + 引用 | 结构化 JSON 题目（入题库，经人工审核后上线） |

**核心差异结论**：问答是"找最相关的一条"，出题是"按知识点组织一组条文做素材"。实测 2087 条均长仅 134.6 字（15~907），单条信息量不足以支撑一道题的四个选项，且题目需要"正确条文 + 干扰条文"两类素材——**每个知识点必须取料 6~10 条**（单选取 1 正确 + 3 干扰、多选取 2~3 正确 + 3~4 干扰，加 2 条冗余缓冲），否则要么选项不够、要么逼模型编造干扰项。

**出题检索策略（三段式）**：

1. **知识点路由**：先建"知识点大纲"，把输入知识点映射为条文集合。2087 条规模小，采用**LLM 离线批量打标 + 人工抽检**方式为每条条文打 1~3 个知识点标签（词表约 80 个，如"主要负责人职责、安全生产责任制、双重预防机制、有限空间作业审批、事故报告时限、处罚幅度、应急演练频次"），标签写入 chunk metadata。打标脚本一次跑完 2087 条，人工抽检 5%~10% 校准。
2. **难度过滤**：条文在入库时就预计算好难度字段（见 §3），按输入难度先过滤条文池（metadata filter），再在池内排序。
3. **多条文取料**：在知识点×难度过滤后的池内，用知识点描述性 query 做向量 top-8 召回（可叠加 BM25+RRF 混合检索增强鲁棒性，见 RAG 混合检索方案）。按"知识库定位"默认**以四川本地法规规章为主体取料**（考试贴近本地实务），国家法条文作为解析中的上位依据补充——处理"四川条例引用国家安全生产法"的层级交叉引用时，解析输出引用链如"《四川省安全生产条例》第X条 → 依据《中华人民共和国安全生产法》第Y条"。

### 2. 出题 Prompt 设计：四种题型生成模板

统一约束（**防幻觉锚点：条号**）在 system prompt 中强制声明：

```
你是安全生产法规领域的出题专家，服务于"蜀道安全助手"考试工坊。
硬性规则：
1. 所有选项、答案、解析中的事实（主体、数字、期限、金额、处罚）必须逐字或严格等价于给定材料中的条文，禁止编造材料中不存在的数字、期限、条号。
2. 解析必须引用具体条文号，格式：【《法规名》第X条】，且该条号必须存在于材料中。
3. 干扰项必须取自材料中其他条文的真实内容改写，不得凭空设计。
4. 单选/判断/填空答案唯一；多选答案集合明确。
5. 严格按 JSON 输出，字段与 schema 完全一致，不输出多余文字。
```

**通用 user prompt 结构**（四种题型共用取料与框架）：

```
【任务】根据材料生成 1 道{题型}题。
【知识点】{knowledge_point}
【目标难度】{difficulty}（材料条文已按此难度筛选）
【材料】
{formatted_articles}   // 6~10 条条文，每条前缀标注【《法规名》第X条】原文
【输出 JSON】见题型模板。
```

**单选模板**（题干挖空/情景 + 4 选项 + 解析）：

```json
{"type":"single","stem":"...","options":[{"key":"A","text":"..."},{"key":"B","text":"..."},{"key":"C","text":"..."},{"key":"D","text":"..."}],"answer":"B",
 "analysis":"依据：《生产安全事故报告和调查处理条例》第九条……；排除：A项将报告时限由1小时改为24小时，与条文不符。",
 "source":[{"law_title":"生产安全事故报告和调查处理条例","article_no":"第九条","role":"answer"},{"law_title":"...","article_no":"第X条","role":"distractor"}]}
```
规则：正确项逐字对应一条文；3 个干扰项从取料包中其他条文的真实事实改写；解析分"依据（引条号摘关键句）"+"排除（说明干扰项事实差异）"两段。

**多选模板**：5 个选项（2~3 个正确），要求正确项集合唯一、解析逐一说明每个正确项依据与每个干扰项排除理由。典型出题点：**多主体并列义务条款**（如"政府及有关部门、生产经营单位、从业人员各自职责"）、"三同时"包含项、应急预案演练的多个频次要求。

**判断题模板**：
```json
{"type":"judge","stem":"生产经营单位应当对从业人员进行安全生产教育和培训，未经培训或者培训不合格的，不得上岗作业。","options":[],"answer":"正确",
 "analysis":"依据：《中华人民共和国安全生产法》第二十八条……（同义改写，事实一致）。",
 "source":[{"law_title":"中华人民共和国安全生产法","article_no":"第二十八条","role":"answer"}]}
```
规则：陈述句为对原文条文的同义改写或**扭曲改写**（改期限/改主体/改倍数/加否定词），扭曲必须源于真实条文；禁止用"材料未规定"构造错误判断，解析须点明改写点。

**填空模板**：
```json
{"type":"blank","stem":"生产安全事故发生后，单位负责人接到报告后，应当于____小时内报告县级以上人民政府安全生产监督管理部门。","options":[],"answer":["1"],
 "analysis":"依据：《生产安全事故报告和调查处理条例》第九条，单位负责人接到报告后应当于1小时内向……报告。",
 "source":[{"law_title":"生产安全事故报告和调查处理条例","article_no":"第九条","role":"answer"}]}
```
规则：空位唯一、答案唯一、答案逐字出自条文（多为期限/金额/主体名词），严禁"多解"填空。

**输出后硬校验（防幻觉锚点落地为代码，不依赖模型自觉）**：从 `analysis` 中正则抽取"第X条"，逐一核对是否存在于取料包对应 `law_title` 中；条号不在材料内 → 整题重生成（最多 2 次），仍失败则标记 `generation_failed` 不进库。

### 3. 难度控制：从条文特征自动判定难度

难度不靠模型感觉，由**条文难度评分器**在入库时离线预计算并存入 metadata（2087 条批处理一次，出题时查表 O(1) 过滤，不做在线计算）。

| 条文特征（正则/规则识别） | 加分 | 档位倾向 |
|---|---|---|
| 定义性条款（"本法所称……是指"） | 0 | 简单 |
| 单纯义务条款（应当/必须，无数字无处罚） | 0 | 简单 |
| 含处罚条款（罚款/责令停产/吊销/拘留/万元） | +1 | 中/难 |
| 含数字条款（X日/月/年、倍数、金额、百分比） | +1 | 中/难 |
| 多主体/多情形并列（多处"和/以及"列举） | +1 | 难 |
| 交叉引用"第X条" ≥2 处（实测正文内容内真实引用 172 处，命中率高） | +1 | 难 |
| 条文长度 >300 字（均值 134.6，>300 属长条） | +1 | 难 |

**三档判定**：总分 0 → 简单；1 → 中等；≥2 → 困难。

- 简单档：定义性、单一义务条款（如《四川省安全生产条例》对"安全生产主体责任"的定义、常见概念）；
- 中等档：单一处罚幅度或单一数字条款（如"未按规定上报事故的，对单位处 1 万元以上 3 万元以下罚款"）；
- 困难档：处罚条款 + 数字条款叠加、多主体列举、跨条引用链（如《安全生产违法行为行政处罚办法》法律责任章的多档处罚、责令期限与罚款并存的复合条款）。

出题流程中：`difficulty=困难` 时，检索强制要求取料包内 ≥3 条带处罚/数字特征的条文（供选项构造），并对召回结果按难度评分做重排序。

### 4. 题目去重与干扰项生成（同一知识点多题互斥、干扰项取自真实条文）

**三层去重**：

1. **检索层**：批次内维护"已用条文集合"，每道题取料时过滤掉前序题目已作为**正确项**的条文，保证同一知识点生成的 N 道题正确条文互不重叠。
2. **生成层（库内去重）**：题干规范化（去空白、全半角归一）后计算 SimHash 64bit 指纹，与题库已入库题目比对，汉明距离 ≤3 判定重复 → 丢弃并从池内换条文重新取料生成。
3. **选项级互斥**：同一知识点维护一个"干扰项条款池"，某条文已作为某题正确项或干扰项使用后，后续题目优先从池内未用条文取材，避免多题间选项雷同；同知识点同一数字（如报告时限 1 小时）只允许作一次正确答案。

**干扰项生成策略（杜绝编造）**：

| 题型 | 干扰项来源（全部来自取料包真实条文） |
|---|---|
| 单选/多选 | 同知识点其他条文的真实主体、真实处罚幅度、真实期限（数字改写为同一法规真实存在的另一数字） |
| 判断题 | 真实条文的关键要素替换（改主体/改期限/改倍数/加否定词） |
| 填空 | 空位答案本身唯一，干扰体现在"备选数字池"（题干场景中多给真实数字选项则转单选） |

**干扰项溯源校验（代码强校验）**：对每个生成选项抽取关键事实（数字/期限/金额/主体词/行为短语），在取料包条文中做匹配（jieba 分词 + 正则数字匹配，全角数字归一）；**任一选项关键事实在材料中无出处 → 整题重生成**；重试 2 次仍失败，则用规则从真实条文构造替换选项（取同知识点另一条文的真实处罚幅度/期限作干扰项）。校验结果写入题目字段 `interference_verified`，供审核人在 E02 工作台查看每个选项的出处条文。

### 5. 与人工审核流程衔接（E02 人工确认）与准确率 ≥80% 评测口径

**状态机**：`draft（LLM 生成）→ pending（待审核）→ approved（可用）| rejected（驳回，记录原因）`，另设 `draft 修改` 路径（审核人编辑后通过，记 `modified=1`）。

**审核工作台**：题干+选项+解析左侧展示，右侧按 `source` 字段展示溯源条文原文（条号高亮），审核人可点条号跳转法规原文。一键通过/驳回，驳回必选原因：事实错误 / 条号引用错误 / 选项重复 / 超纲 / 难度不符 / 解析不足。按批次批量通过/驳回。

**准确率 ≥80% 评测口径（对外承诺口径 = 人工审核通过率）**：

```
审核通过率 R = (直接通过数 + 文案润色后通过数) / 批次生成总数 ≥ 80%
```

- 口径界定：仅**不影响事实与答案**的文案润色计入通过；任何涉及**条号引用错、数字错、主体错、选项重复、正确答案错、超纲、解析缺失或与答案矛盾**的修改/驳回，一律计为未通过。
- 以人工审核为金标准（对应 PRD E02"AI 出题准确率需 ≥80%（经人工审核）"）。
- **内控抽样审计（次口径）**：每月从已入库题库随机抽 10%，双人独立复核，进库题目正确率应 ≥95%（进库题基本无错是内控线，非对外达标线），并统计各知识点/难度的通过率分布，倒逼修正检索权重与 prompt。
- **负样本回流闭环**：`rejected` 记录 + 审核原因进入反例库，作为出题 prompt 的 few-shot 负例与检索修正依据；每两周用反例库更新一次出题 prompt 与取料排序，形成"出题→审核→修正"闭环。

### 6. 题库导入/导出（Excel）与条文溯源字段设计

**题目主表（E01 题库管理）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | |
| batch_id | VARCHAR | 一次 AI 出题 = 一批，便于整批统计/回滚 |
| question_type | ENUM | single/multiple/judge/blank |
| knowledge_point | VARCHAR | 知识点标签 |
| difficulty | ENUM | easy/medium/hard |
| stem | TEXT | 题干 |
| options | JSON | 选项列表（单选/多选）；判断/填空为空 |
| answer | JSON | 正确答案（单选"B"/多选["A","C"]/判断"正确"/填空["1"]） |
| analysis | TEXT | 解析（含条号引用） |
| **sources** | **JSON** | **溯源数组**：`[{"law_title","article_no","role":"answer/distractor/analysis"}]` |
| source_law_title / source_article_no | VARCHAR | 主溯源冗余列（便于检索与去重） |
| status | ENUM | draft/pending/approved/rejected |
| reviewer / review_note / reviewed_at | | 审核痕迹 |
| interference_verified | TINYINT | 干扰项溯源校验是否通过 |
| created_at / updated_at | | |

建索引：`(knowledge_point, difficulty, question_type, status)` 组合索引——E03 组卷按"知识点×难度×题型"抽样，优先取 `approved`，某格题目不足时提示"触发 AI 补题"（复用本方案出题链路补料）。

**Excel 导出列（E01 批量导入/导出）**：

```
序号 | 题型 | 知识点 | 难度 | 题干 | 选项A | 选项B | 选项C | 选项D | 选项E | 正确答案 | 解析 | 来源法规 | 来源条号 | 附加引用条文 | 备注
```

**导入校验**（不中断整表，逐行返回错误原因）：题型/难度枚举合法；答案在选项范围内（多选逗号分隔）；题干/解析/正确答案非空；来源法规+条号与知识库核对（软校验，不匹配给警告但仍可入库，标记 `unverified`）；跨行重复题干给出警告。

**溯源字段设计要点（结合实测数据问题）**：
- 法规名一律用**清洗后的 title**（实测个别 title 带前导空格，入库时 `strip()`）；
- 溯源以**条文 no 为准**（如"第九条"），不依赖 `doc_no`/`effective_date`（实测部分为空）；
- `sources` 的 `role` 字段支撑 E02 审核工作台高亮、E05 自动阅卷的答案解析、以及事后审计的"题目→条文→法规→官网 source_url"全链路追溯（`index.json` 已含 source_url，直接关联）。
