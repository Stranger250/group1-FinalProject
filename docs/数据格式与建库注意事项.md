# 蜀道数据格式与建库注意事项

> 用途：**RAG 项目生成（P0 建库管道 clean.py / parse.py / tag.py / ref.py）启动前必读的数据契约**。
> 内容：输出 JSON 统一结构、全国 vs 省内差异、数据质量坑、建库必须处理的事项、相关文件索引。
> 数据：`crawler_output/` 28 部法规，2026-08-12 实测核对。

---

## 1. 一页速览（结论先行）

- **28 部法规 JSON 格式统一**，全国（17 部）与四川（11 部）核心结构完全一致，可一套管道直接消化，**不需要按来源分流**。
- 唯一 3 点小差异：四川多 `formulation_unit`、flk 来源国家法规多 `parse_error: null`、`status` 措辞不统一（数据质量，非格式）。
- 章/条结构一字不差：`chapters[].{chapter, articles[].{no, content}}`；条号字段在 JSON 里叫 **`no`**（建库时统一改名为 `article_no`）。
- 数据质量坑集中在**元数据缺失**（doc_no / effective_date 空、status 措辞不一、title 前导空格），正文干净。

---

## 2. 输出 JSON 统一结构（schema）

```json
{
  "title": "四川省安全生产条例",
  "doc_no": "川常备〔2023〕17号",          // 部分文件为空 ""
  "category": "地方性法规",                // 法律/行政法规/部门规章/政府规章/地方性法规
  "source": "rhpt.scspc.gov.cn",           // 来源通道标识
  "source_url": "https://…",               // 可回源
  "publish_date": "2023-05-25",            // 部分为空 ""
  "effective_date": "2023-09-01",          // 部分为空 ""
  "status": "现行有效",                     // ⚠ 措辞不统一（见 §4.1）
  "formulation_unit": "四川省人民政府",      // ✅ 仅四川 11 部有；全国 17 部没有此字段
  "full_text": "整篇纯文本（供 RAG 分块）",
  "chapters": [
    {"chapter": "第一章 总则",
     "articles": [{"no": "第一条", "content": "……"}]}
  ]
}
```

- 顶层字段固定 9 个 + 四川可选的 `formulation_unit`；`parse_error` 在全部 14 部 flk 来源国家法规里有（值均为 `null`，即解析正常，忽略）。
- 章/条：28 部全部是标准 `第X章` / `第X条`，无隐式"正文"章，无异常条号（已脚本核验）。
- `index.json` 是统一扁平 list（28 条），每条 `[title, doc_no, category, source, source_url, publish_date, effective_date, status, articles, file]`，**不含 formulation_unit**。

## 3. 全国 vs 省内差异（仅 3 点）

| # | 差异 | 全国 17 部 | 四川 11 部 | 建库处理 |
|---|---|---|---|---|
| 1 | `formulation_unit`（制定单位） | 无 | 有 | 可选字段，判空即可 |
| 2 | `parse_error` | 14 部 flk 来源国家法规均有（值 `null` = 解析正常） | 无 | 一律丢弃 |
| 3 | `status` 措辞 | `现行有效` / `有效` / `""` 并存 | `现行有效` / `已修改` | 归一化三态（§4.1） |

**结论：差异不构成格式障碍**，清洗管道可对 28 部无差别处理。

## 4. 数据质量注意事项（实测清单）

### 4.1 元数据缺失（建库重点处理）

| 问题 | 涉及文件 | 处置 |
|---|---|---|
| `doc_no` 为空 | 新增 8 部国家法（公路法/建筑法/消防法/突发事件应对法/职业病防治法/行政处罚法/行政强制法/道交法）+ 原清单 7 部（安全生产法、四川地灾条例、四川消防条例、四川道路运输条例、四川事故报告规定、生产责任规定、四川突发事件办法），共 15 部 | 官网核对人工补；兜底置"—" |
| `effective_date` 为空 | 建设工程条例、行政处罚办法、应急预案办法、事故报告条例、地灾条例、特种设备条例（6 部） | 从源网页补；兜底用 publish_date |
| `status` 措辞不一 | 行政处罚办法/应急预案办法=`""`；事故报告条例=`"有效"` | 统一为 `现行有效/已修改/已废止` 三态 |
| `title` 前导空格 | 四川事故报告规定、突发事件办法（已修复，防复发） | 统一 `strip()` |

### 4.2 版本/时效隐患（需人工核实，勿默认现行有效）

- 四川省消防条例 `status=已修改`（2011 生效）→ 需核实最新修订文本后入新版；
- 四川省生产经营单位安全生产责任规定（2007）、四川省突发事件应对办法（2012）→ 人工核实修订/废止后走增量更新。

### 4.3 正文特征（影响分块与检索）

- 条均 **134.6 字**（15–907），绝大多数在 bge-large-zh 512 token 窗口内；**最长 907 字**（>400 字需父子块，见 RAG 方案 §1.2）。
- 正文含 **172 处"第X条"交叉引用**（正文内容内的真实引用，如四川条例"依照《安全生产法》第X条"）→ 建库时扫描建 `ref_out` 引用边。
  - ⚠ **口径修正说明**：旧版写"1048 处交叉引用"实为全文"第X条"**字面出现次数（含条号标题本身）**；2087 个条号头 + 172 处内容引用 = 全文字面总出现 2259 处。RAG 引用展开关注的是内容内真实引用 = **172 处**。
- 正文干净无噪音（WPS 页眉页脚/工具栏已在爬虫清洗），`full_text` 与 `chapters` 拼接一致性校验通过。

## 5. 建库时（P0 管道）必须处理的事

按 `docs/RAG优化方案.md` §1.3 流水线逐项对齐：

1. **字段改名**：JSON 里 `no` → 元数据统一 `article_no`（引用/评估主键都用它）。
2. **status 归一化**：`""`/`"有效"`/`"现行有效"`/`"已修改"` → 三态（`现行有效/已修改/已废止`）。
3. **空元数据三级兜底**：官网核对 → 相邻字段推导（`effective_date ← publish_date`）→ 占位符"待核实"并打 flag。
4. **formulation_unit 判空**：有则存、无则空，不报错。
5. **parse_error 丢弃**：不为它建任何字段。
6. **title 统一 strip()**。
7. **分块**：2087 条 = 2087 父块 + 199 章头辅助块；>400 字按句切子块（召回子块、引用父块）。
8. **打标**：`domain_tags`（蜀道业务域）+ `difficulty`（出题难度评分器）离线预计算入 metadata。
9. **引用索引**：正则扫描 172 处内容内 `《…》第X条` 建 `ref_out`；覆盖率（解析到库内目标的比例）≥90% 作质量闸门。
10. **块 ID**：`{doc_id}_{article_no}_{version}`，如 `scaq_第二十四条_v2023`；doc_id 命名见 RAG 方案 §1.1。

**验收断言**：每 doc 章/条/总字符与 `docs/_rag_data_audit.json` 一致（199 章/2087 条/303734 字）；条号唯一且递增；`full_text` 与 `chapters` 拼接一致。
