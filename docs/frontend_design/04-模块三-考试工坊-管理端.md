# 模块三 考试工坊 管理端前端设计（E01 题库 / E02 AI 出题 / E03 组卷）

> 文档状态：初稿（2026-08-13）
> 对应 PRD §3.4 E01/E02/E03、PRD §5.1 P06/P07/P08；页面清单 §5.1 中 P09/P10（在线考试/成绩）属考生侧，不在本章。
> 本文契约以 `backend/app/api/exam.py`、`backend/app/api/ai.py`、`backend/app/api/paper.py` 及 `backend/app/schema/{question,ai,paper}.py`、`backend/app/service/{question,gen,review,paper}_service.py` 为准（2026-08-13 已核实）。

## 0. 范围与共性约定

- 本章三块功能（题库管理、AI 出题、试卷管理）全部为**管理类功能**，仅 `SAFETY(2)` / `ADMIN(3)` 可见可操作，`EMPLOYEE(1)` 无入口（菜单隐藏 + 路由守卫双重控制）。
- 所有接口挂载前缀 `/api/v1`，统一响应 `{code, message, data}`；`code !== 200` 视为业务失败，读取 `message` 提示。
- 鉴权：`Authorization: Bearer <token>`；统一 401（含 token 过期、账号被禁用）→ 清空登录态跳 `/login`。
- 403（越权）/ 404（资源不存在，含越权掩码）统一提示「无权限或资源不存在」。
- 后端校验严格，前端表单需同步做约束（见各节「异常/边界处理」），减少无效请求与更差体验的 4xx。
- 全部接口经 `require_roles(RoleId.SAFETY, RoleId.ADMIN)`，前端路由 `meta.roles: ['SAFETY', 'ADMIN']`。

### 0.1 登录后角色获取

- `POST /api/v1/auth/login`（form：`username` / `password`）→ `data: {access_token, token_type: "bearer", user: {id, username, name, role_id, phone}}`；登录成功即把 `user.role_id` 写入 Pinia `auth` store，据此渲染菜单。
- 兜底 `GET /api/v1/auth/me` → `data: {id, username, name, role_id, phone}`，供刷新后恢复登录态校验角色。

## 2. E01 题库管理（P06）

### 2.1 页面结构

```
QuestionBank.vue
├─ el-card 筛选栏（一行内多控件 + 搜索/重置）
│   ├─ el-select type     # 单选/多选/判断/填空，可清空=全部
│   ├─ el-select difficulty
│   ├─ el-input knowledge_point
│   ├─ el-select status
│   ├─ el-select source
│   ├─ el-input keyword   # 题干模糊，回车触发
│   ├─ 搜索按钮 / 重置按钮
│   └─ el-button primary 新建题目
├─ el-table（data=分页 items）
│   ├─ id / type(标签) / content(题干, show-overflow-tooltip) / knowledge_point
│   ├─ difficulty(标签) / source(标签) / status(el-tag 变色)
│   ├─ analysis 摘要 / source_law_title 溯源
│   └─ 操作列：编辑 / 删除（ElMessageBox.confirm）
└─ el-pagination（page/page_size/total）
```

### 2.2 新建/编辑弹窗（按题型动态表单）

```
QuestionFormDialog.vue（新建与编辑复用）
├─ el-form（rules 见 2.5）
│   ├─ 公共：type(编辑时禁改) / content(题干, textarea) / knowledge_point / difficulty
│   ├─ 按 type 渲染：
│   │   ├─ SINGLE：options 编辑列表（动态行，至少 2 项；答案 el-radio 取「选项标签字母」）
│   │   ├─ MULTIPLE：options 编辑列表；答案 el-checkbox 多选 → 以英文逗号拼接（如 "A,B"）
│   │   ├─ JUDGE：固定 options ["A 正确","B 错误"]，仅答案 el-radio A/B
│   │   └─ FILL：无 options；答案 input，多空用「；」或「,」分隔
│   ├─ 公共：analysis(解析, textarea, 必填) / source_law_title / source_article_no
│   └─ 编辑时额外：status(el-select，供停用/重新通过)
└─ 确定 / 取消
```

- **答案格式约定（与后端 `_validate_answers` 一致）**：
  - 选项标签取选项首字母大写（支持 `"A. xxx"` / `"A xxx"` / `"A"` 三种写法）。前端给每个选项配置「标签」时，可直接以 `A/B/C/D` 前缀生成，避免歧义。
  - 单选答案=某个选项标签（`A`）；多选答案=`A,B`（逗号分隔、后端兼容中文逗号）；判断答案=`A`(正确) 或 `B`(错误)；填空答案=文本，多空用 `；`/`;` 分隔、每空非空。
- **选项编辑行**：`el-input` + 删除按钮 + 「添加选项」；单选/多选至少 2 个选项。为可读性，选项文本统一展示为 `A. xxx` 形式（提交时存 `"A. xxx"` 或 `"A xxx"` 均可，后端兼容）。
- 编辑回填：用列表行 `QuestionOut` 字段回填（列表已含全部字段，无需额外详情请求）。

### 2.3 关键交互与数据流

1. 进入页面 → `GET /api/v1/questions`（默认 page=1,page_size=20）→ 渲染表格 + 分页。
2. 筛选任意变更 → 重置到第 1 页重新请求（全部条件作为 query 拼参）。
3. 新建：填表单 → `POST /api/v1/questions` → 成功（data 为入库题，**status=APPROVED**，人工录入直接通过）→ 关闭弹窗、刷新列表、ElMessage.success。
4. 编辑：`PUT /api/v1/questions/{id}`，body 仅传变更字段（`exclude_unset` 语义由后端处理，前端直接传完整表单即可）。成功后刷新。
5. 删除：ElMessageBox.confirm → `DELETE /api/v1/questions/{id}` → 刷新。被试卷引用会收到 400 → toast 后端 message。
6. 详情按钮（可选）：`GET /api/v1/questions/{id}` 弹只读抽屉；非必须（列表字段已全）。

### 2.4 与后端契约

#### GET /api/v1/questions（列表筛选分页）

Query（均可选）：`type`(SINGLE/MULTIPLE/JUDGE/FILL)、`difficulty`(EASY/MEDIUM/HARD)、`knowledge_point`、`status`(PENDING/APPROVED/REJECTED/DISABLED)、`source`(manual/ai)、`batch_id`、`keyword`、`page`(默认1)、`page_size`(默认20, ≤100)。

`data`（`PageOut`）：
```ts
interface QuestionPage {
  page: number; page_size: number; total: number;
  items: QuestionOut[];
}
interface QuestionOut {
  id: number;
  batch_id: string | null;            // AI 生成批次，manual 为 null
  type: 'SINGLE' | 'MULTIPLE' | 'JUDGE' | 'FILL';
  content: string;
  options: string[] | null;           // FILL 为 null；JUDGE 固定 ["A 正确","B 错误"]
  answer: string;                     // 单选"A" / 多选"A,B" / 判断"A"|"B" / 填空文本(多空;分隔)
  analysis: string | null;            // E01 必填
  knowledge_point: string;
  difficulty: 'EASY' | 'MEDIUM' | 'HARD';
  source: 'manual' | 'ai';
  sources: { role: string; law_title?: string|null; article_no?: string|null }[] | null;
  source_law_title: string | null;
  source_article_no: string | null;
  status: 'PENDING' | 'APPROVED' | 'REJECTED' | 'DISABLED';
  reviewer: number | null;            // 审核人用户 id（无姓名，见 6）
  review_note: string | null;
  interference_verified: number;      // 0|1
  rewrite_of: number | null;
  rewrite_feedback: string | null;
  create_time: string | null;         // ISO
  update_time: string | null;
}
```

#### POST /api/v1/questions（新建，body=QuestionCreate）

```ts
{
  type: 'SINGLE'|'MULTIPLE'|'JUDGE'|'FILL';  // 必填
  content: string;                            // 必填
  options?: string[] | null;                  // 单选/多选必填；判断/填空后端忽略或校验
  answer: string;                             // 必填，≤64
  analysis: string;                           // 必填（PRD E01 正确答案与解析必填）
  knowledge_point: string;                    // 必填，≤128
  difficulty: 'EASY'|'MEDIUM'|'HARD';         // 必填
  source_law_title?: string | null;
  source_article_no?: string | null;
}
```
`data`：新建后的 `QuestionOut`（source=manual、status=APPROVED）。

#### PUT /api/v1/questions/{id}（body=QuestionUpdate）

字段均可选：`type` / `content` / `options` / `answer` / `analysis` / `knowledge_point` / `difficulty` / `status` / `review_note`。`data`：更新后 `QuestionOut`。

#### DELETE /api/v1/questions/{id}

成功 `{code:200, message:"删除成功", data:null}`；被试卷引用 → 400 `message="题目已被试卷引用，不可删除（请先在试卷中移除该题）"`。

### 2.5 异常/边界处理

- 表单校验（提交前拦截，减少 400）：
  - content/analysis/knowledge_point 非空；analysis 必填。
  - SINGLE/MULTIPLE：选项 ≥2；单选答案∈选项标签；多选答案⊆选项标签且非空。
  - JUDGE：答案∈{A,B}。
  - FILL：答案非空；多空用分隔符切分后每空非空。
- 后端 400 处理：toast `message`（如「单选答案必须是选项标签之一」「填空题多空答案用分号分隔…」）。
- 删除 400（被试卷引用）→ 明确 toast 后端文案，提示先到试卷移除。
- 编辑时 type 禁改（改题型需连带重建 options/answer，成本高；后端虽允许改 type 但会重新校验答案）。
- 新建/编辑提交期间按钮 loading，防重复提交。
- 列表 `total` 大时保持服务端分页，前端不做本地过滤。

## 3. E02 AI 出题

### 3.1 页面结构

```
AiGenerate.vue          # 生成题目
├─ el-card 参数表单：knowledge_point(必填) / types(多选,≥1) / difficulty / count(5–20) / law_title(可选)
└─ el-button primary 开始生成 → 生成中态（全屏/卡片 loading，文案「AI 生成中，约需数十秒…」）→ 完成跳转批次详情
AiBatches.vue           # 批次列表
├─ el-card 统计摘要（总批次/总题数，可选，来自 /ai/stats 或前端汇总）
└─ el-table：batch_id / total / pending / approved / rejected / pass_rate(进度条) / 操作(查看详情)
AiBatchDetail.vue       # 批次详情（:batchId）
├─ el-card 批次头部：batch_id、total、pending/approved/rejected、pass_rate、批量操作按钮
├─ 批量操作条（勾选多题时出现）：通过勾选题 / 驳回勾选题(必填意见)
└─ 题目卡片列表：逐题内容/选项/答案/解析/溯源 + 审核状态 tag + 操作（审核/重写/复核）
AiStats.vue             # 统计
└─ el-row 指标卡（total_ai / total_pending / total_approved / total_rejected / total_rewritten / pass_rate）
   └─ 批次明细表（同 AiBatches 表格）
```

### 3.2 关键交互与数据流

**生成（AiGenerate）**
1. 填表单 → 校验（knowledge_point 非空、types 至少 1、count∈[5,20]）。
2. `POST /api/v1/ai/generate` → 进入**生成中态**（loading，按钮禁用 + 提示文案；后台调用 LLM 耗时较长）。
3. 成功：`data = {batch_id, count, knowledge_point, difficulty}` → `ElMessage.success(\`已生成 ${count} 题，待审核\`)` → `router.push(/exam/ai/batches/${batch_id})`。
4. 失败：400（如「未检索到相关法规条款，请更换知识点」）→ toast message，停留表单；502（AI 输出不符合要求）→ toast message，提示可重试。

**批次列表（AiBatches）**
- `GET /api/v1/ai/batches` → `data: BatchOut[]`（无分页）。
- 每行 pass_rate 用 `el-progress` 展示：`<80%` 用 warning/danger 色，`≥80%` 用 success 色（对齐 PRD E02 审核通过率 ≥80% 验收口径）。
- 行操作「查看详情」→ `/exam/ai/batches/:batchId`。

**批次详情/审核（AiBatchDetail）**
- `GET /api/v1/ai/batches/:batchId` → `data: BatchDetailOut`（含 `questions: QuestionOut[]`），batch 不存在 → 404 → 统一提示 + 返回列表。
- 每张题目卡展示：type/difficulty/status tag、题干、选项（按题型渲染）、答案、解析、溯源（sources/source_law_title/source_article_no）、review_note、interference_verified。
- **单题审核**：点「审核」→ 弹 `ReviewDialog`：action 单选（通过/驳回）、`review_note`（**驳回必填**，前端强制）、`interference_verified`（「已核对干扰项」勾选，单选/多选类才有意义）→ `POST /api/v1/ai/questions/{qid}/review` → 刷新详情。
- **AI 重写**（对 source=ai 且 status=REJECTED 的题）：点「AI 重写」→ 弹 `RewriteDialog`：textarea `feedback`（本次修订要求，必填）→ `POST /api/v1/ai/questions/{qid}/rewrite`（loading，后台调用 LLM）→ 成功提示「已生成修订版（待审核），新批次已生成」→ 刷新；409（已存在修订版）→ toast message。
- **批量审核**：题目卡带多选框，勾选后出现批量操作条：
  - 批量通过 → `POST /api/v1/ai/batches/:batchId/review` body `{action:'APPROVE', ids:[勾选id]}`。
  - 批量驳回 → 需先弹框填 `review_note`（必填）→ 同接口 `{action:'REJECT', review_note, ids}`。
  - 未勾选任何题时点「整批通过/整批驳回」→ 不传 `ids`（=整批）；整批驳回意见必填。
  - 成功 `data = {batch_id, reviewed, action}` → 提示 + 刷新。
- **复核纠正**：APPROVED 题可再走审核（如 REJECT），REJECTED 题可复核 APPROVE；前端对已审题目仍保留「复核」入口。

**统计（AiStats）**
- `GET /api/v1/ai/stats` → 指标卡 + 批次明细表（同批次列表数据）。

#### POST /api/v1/ai/questions/{qid}/review（body=ReviewIn）

```ts
{ action: 'APPROVE' | 'REJECT'; review_note?: string | null; interference_verified?: boolean }
```
约束：REJECT 且无 review_note → 400「驳回必须填写审核意见」；source≠ai → 400；DISABLED → 400；存在待审/已通过修订版时直接复核 APPROVE 原题 → 400。
成功 `data: QuestionOut`（审核后的完整题）。

#### POST /api/v1/ai/questions/{qid}/rewrite（body=RewriteIn）

```ts
{ feedback: string }   // 修订要求，必填，≤255
```
仅 source=ai 且 status=REJECTED 可重写（否则 400）；已存在修订版 → 409；AI 输出不合要求 → 502。
成功 `data: QuestionOut`（修订版新题，status=PENDING、rewrite_of=原题 id、独立新 batch）。

#### POST /api/v1/ai/batches/{batch_id}/review（body=BatchReviewIn）

```ts
{ action: 'APPROVE' | 'REJECT'; review_note?: string | null;
  interference_verified?: boolean; ids?: number[] | null }  // ids 为空=整批
```
整批 REJECT 无 review_note → 400；目标题不在批次 → 404。
成功 `data: { batch_id: string; reviewed: number; action: string }`。

### 3.4 异常/边界处理

- 生成中态必须有（LLM 耗时），按钮防重复点击；失败保留表单，便于改参重试。
- 重写也有 LLM 耗时 → 同 loading；502 时提示「AI 重写失败」并引导检查原题是否正确（后端 hint 会提示可直接复核通过）。
- 驳回意见必填：前端对话框内校验 + 后端 400 兜底。
- 批次列表无分页，批次过多时后端数据可能较大 → 见 6（待后端加分页）。
- pass_rate 分母为已审题数（approved+rejected），尚未审核任何题时为 0，UI 进度条显示 0% 而非异常。
- 单题审核/重写/批量审核后统一重新拉取 `GET /ai/batches/{batch_id}`，保证卡片状态一致。

## 4. E03 试卷生成（P08）

### 4.1 页面结构

```
PaperList.vue
├─ el-card 筛选栏：gen_mode / status / keyword + 搜索/重置
├─ 操作区：手动组卷 → /exam/papers/create?mode=manual；AI 智能组卷 → ?mode=auto
├─ el-table：id / name / total_score / pass_score / duration(min) / question_count
│            / gen_mode(tag) / status(tag) / creator_name / create_time / 操作(详情/删除)
└─ el-pagination

PaperCreate.vue（mode=manual|auto 复用一套壳：头部配置 + 中间选题目区）
├─ 配置区 el-form：name(必填) / duration(30|60|90) / pass_score(默认60) / total_score(默认100)
├─ mode=manual：
│   ├─ 选题来源：内嵌「题目选择抽屉/卡片列表」（复用 E01 列表，只显示 status=APPROVED，可搜索筛选+勾选）
│   ├─ 已选题目列表（含 score 输入：全部指定或全部不指定=均分）
│   └─ 提交 → POST /papers/manual
├─ mode=auto：
│   ├─ rules 编辑列表（动态行：type + difficulty(可选=全部) + count）
│   ├─ knowledge_points 多选输入（el-select 可创建选项，可选）
│   └─ 提交 → POST /papers/auto → 若有 warnings 先 ElMessageBox 提示后跳详情
└─ 提交按钮

PaperDetail.vue（:pid）
├─ 基本信息 + 状态 tag + 编辑配置（el-dialog 或行内 form，PUT /papers/{pid}）
├─ 题目预览：按 seq 排序列表，每题展示 score + type/content/options/answer/analysis
└─ 删除按钮（PUBLISHED 禁用+提示）
```

### 4.2 关键交互与数据流

1. 列表：`GET /api/v1/papers?gen_mode&status&keyword&page&page_size` → 表格 + 分页。
2. 手动组卷：
   - 进入 `create?mode=manual`；选题区仅展示并允许勾选 `status=APPROVED` 题目（后端也强制只取 APPROVED）。
   - 选题支持搜索/筛选（复用 E01 的筛选参数），勾选后进已选列表。
   - **分值策略**：要么每题都填 score、要么都不填（=总分均分）；混合 → 前端直接拦截并提示「题目分值需统一」。
   - 提交 → `POST /api/v1/papers/manual` → 成功跳 `/exam/papers/:pid`。
3. AI 智能组卷：
   - 进入 `create?mode=auto`；rules 至少 1 条（每条 type+count，difficulty 可选），knowledge_points 可选。
   - 提交 → `POST /api/v1/papers/auto` → 成功 `data` 含 `warnings?: string[]`：
     - warnings 非空 → `ElMessageBox` 列出「XXX: 需求 N 题，实际可用 M 题」等，用户确认后跳详情（试卷已按可用题生成）。
     - 无 warnings → 直接跳详情。
   - 全部规则都抽不到题 → 400「无可用题目（无已审核题目或条件过严），请调整抽题规则」→ toast + 停留表单。
4. 详情：`GET /api/v1/papers/{pid}` → 渲染预览。
5. 编辑配置：`PUT /api/v1/papers/{pid}`（name/duration/pass_score/total_score/status）→ 成功刷新。**已发布（PUBLISHED）**：总分/及格线禁改（前端禁用输入 + 后端 400 兜底）；有进行中考试时 duration 禁改。
6. 删除：确认 → `DELETE /api/v1/papers/{pid}`；PUBLISHED 按钮禁用（tooltip「已发布不可删除」）；存在考试记录 → 400 toast。

### 4.3 与后端契约

#### GET /api/v1/papers

Query（均可选）：`gen_mode`(manual/ai)、`status`(DRAFT/PUBLISHED/DISABLED)、`keyword`、`page`、`page_size`(≤100)。
`data`：
```ts
interface PaperPage {
  page: number; page_size: number; total: number;
  items: PaperListItem[];
}
interface PaperListItem {
  id: number; name: string; total_score: number; pass_score: number;
  duration: 30|60|90; question_count: number;
  gen_mode: 'manual'|'ai';
  status: 'DRAFT'|'PUBLISHED'|'DISABLED';
  creator_id: number; creator_name: string | null; create_time: string | null;
}
```

#### POST /api/v1/papers/manual（body=PaperManualCreate）

```ts
{
  name: string;                       // 必填，≤128
  duration: 30|60|90;                 // 必填，PRD E03 三档
  pass_score: number;                 // 默认60，1–100
  total_score: number;                // 默认100，10–500
  questions: { question_id: number; score?: number|null }[];  // 1–200，score 全空=均分
}
```
约束（后端）：`pass_score > total_score` → 400「及格线不能高于总分」；同题重复 → 400；题不在 APPROVED → 400 并列出 id；分值「全指定/全不指定」混用 → 400；指定分值之和≠total_score → 400。
成功 `data: PaperDetail`。

#### POST /api/v1/papers/auto（body=PaperAutoCreate）

```ts
{
  name: string; duration: 30|60|90; pass_score: number; total_score: number;
  rules: { type: 'SINGLE'|'MULTIPLE'|'JUDGE'|'FILL';
           difficulty?: 'EASY'|'MEDIUM'|'HARD'|null;   // 缺省=全部难度
           count: number }[];                            // 1–100，≥1 条
  knowledge_points?: string[] | null;                    // 缺省=全部知识点
}
```
成功 `data: PaperDetail & { warnings?: string[] }`（warnings 形如 `"SINGLE(中等): 需求 10 题，实际可用 6 题"`）；一条规则都没抽到 → 400。

#### GET /api/v1/papers/{pid}

`data: PaperDetail`：
```ts
interface PaperDetail {
  id: number; name: string; total_score: number; pass_score: number;
  duration: 30|60|90; question_count: number;
  difficulty_ratio: unknown;      // 智能组卷的配置留痕（create_auto 存 rules/knowledge_points）
  gen_mode: 'manual'|'ai'; status: 'DRAFT'|'PUBLISHED'|'DISABLED';
  creator_id: number; creator_name: string | null; create_time: string | null;
  questions: {
    seq: number;                  // 卷内题序
    score: number;
    question: {
      id: number; type: 'SINGLE'|'MULTIPLE'|'JUDGE'|'FILL'; content: string;
      options: string[] | null; answer: string; analysis: string | null;
      knowledge_point: string; difficulty: 'EASY'|'MEDIUM'|'HARD';
      source_law_title: string|null; source_article_no: string|null;
    } | null;
  }[];
}
```

#### PUT /api/v1/papers/{pid}（body=PaperUpdate）

字段均可选：`name` / `duration` / `pass_score` / `total_score` / `status`。
约束：PUBLISHED 下 `total_score`/`pass_score` 禁改（400「已发布试卷不可修改总分/及格线，请先取消发布」）；有进行中考试时 `duration` 禁改（400）；改后 pass_score>total_score → 400。成功 `data: PaperDetail`。

#### DELETE /api/v1/papers/{pid}

成功 `{code:200, message:"删除成功", data:null}`；PUBLISHED → 400「已发布试卷不可删除，请先取消发布」；有考试记录 → 400「试卷存在考试记录，不可删除」。

### 4.4 异常/边界处理

- 手动组卷已选题目与选题区状态分离（勾选去重；同题不可重复入卷）。
- 分值策略混合（部分填部分空）前端先拦截。
- 智能组卷 warnings 必须在生成成功提示里展示（PRD E03 验收「不足时给出提示」），且确认后仍可查看已生成试卷。
- 已发布试卷：编辑弹窗锁定 total_score/pass_score；删除按钮禁用并提示先取消发布（`status` 改回 DRAFT 需 E04 之前先取消发布——本章仅提供 status 编辑能力，发布/取消发布由状态字段流转）。
- 试卷预览含答案与解析（管理端场景，无需脱敏；E04 考生侧另行脱敏）。

## 6. 待实现细节 / 待后端确认

1. **`/ai/stats` 暂无按题型/难度分布**：当前仅返回总量、状态计数、pass_rate、批次明细。统计页「按题型/难度分布」需后端扩展 `stats` 返回 `by_type: {SINGLE/MULTIPLE/JUDGE/FILL: {approved,rejected,pending,total}}` 与 `by_difficulty: {EASY/MEDIUM/HARD:{...}}`；在未扩展前，统计页只展示可用聚合数据，分布图后置（不造假数据、不做 N+1 聚合）。
2. **`reviewer` 为用户 id**：`QuestionOut.reviewer: number|null`，列表展示姓名需后端在 `QuestionOut` 增加 `reviewer_name`（同 `paper_service` 的 creator_name 做法），或前端维护 id→name 映射（数据来源不足，倾向后端扩展）。
3. **批次列表无分页**：`GET /ai/batches` 返回全量；批次多时建议后端加分页/`limit`，前端暂按全量渲染。
4. **组卷选题复用**：手动组卷的选题区复用 E01 列表组件需注意默认过滤 `status=APPROVED`（后端强制，前端同步限定避免无效勾选）。

6. **生成中态可中断性**：`POST /ai/generate` 与 `POST /ai/questions/{qid}/rewrite` 为同步请求（非异步任务），LLM 耗时期间前端仅 loading，未做取消/进度；若后续 LLM 超时过长，可评估后端改为异步任务 + 轮询。
