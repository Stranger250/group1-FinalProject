## 0. 概览

- 页面：P05 AI 助手页（企业后台「左侧会话列表 + 右侧对话区」布局，PRD §5.1 / §5.2 线框图）。

## 3. 关键交互与数据流

### 3.1 页面初始化
进入 `/ai/assistant`：并行触发 `GET /conversations?page=1&page_size=20` 填充左栏；右侧为「空会话态」（显示欢迎语 + 快捷提问），不自动建会话。

### 3.2 会话管理（A02）

| 操作 | 交互 | 数据流 |
| --- | --- | --- |
| 新建 | 点击「＋ 新建会话」 | `POST /conversations`（可不带 body）→ 新会话 `unshift` 到列表并高亮，清空消息缓存（若无则新建本地空数组），聚焦输入框。**不发默认问候。** |
| 切换 | 点击列表项 | 若 `messages[cid]` 未加载 → `GET /conversations/{cid}/messages`，loading 态；加载后渲染。已加载直接切。切换时若正在 streaming → 先停止（AbortController.abort）。 |
| 重命名 | hover 出现铅笔图标 / 双击标题 | 内联编辑（或弹窗），提交 `PUT /conversations/{cid}` `{title}`，成功更新列表项 title。 |
| 删除 | hover 出现垃圾桶 → `el-popconfirm` 二次确认 | `DELETE /conversations/{cid}` → 从列表移除、清缓存；若删除的是当前会话 → 回落到空会话态。 |

会话列表为空 / 全删后，右栏始终显示空会话态（快捷提问仍可用）。

### 3.3 发送问题与 SSE 流式渲染（核心时序，A01/A03）

前置校验：`message.trim()` 非空；长度 ≤2000（超出提示「请拆分后再发送」）；发送中禁止再次发送（单流）。

发送流程：

1. 本地**乐观渲染** user 气泡（内容 = message，右对齐，标记为已发送）。
2. `fetch POST /api/v1/ai/chat`：
   - body：`{ conversation_id: currentCid, message }`（无会话则 `conversation_id: null`，由后端新建）。
   - headers：`Content-Type: application/json` + `Authorization: Bearer <token>`。
   - signal：`AbortController`（供停止）。
3. 响应非 2xx → **流开始前的业务错误**（HTTP 状态码），解析 `{code, message}` 后 `ElMessage.error`；AI 气泡回滚删除，输入恢复。此时不产生任何 SSE。
4. `res.ok` 后进入 fetch stream 解析循环（见 `useChatStream` 实现）：
   - **`event: meta`**：取 `conversation_id`、`user_message_id`、`mode`、`confidence`、`citations`、`rewritten_used`。
     - 若是新会话（发起时 `conversation_id=null`）→ 用 `meta.conversation_id` 在左栏新建会话项并高亮、`currentCid` 更新为它。
     - 立即渲染「依据来源」引用卡片（meta 先于正文到达，不阻塞首字）。
     - `mode === 'refuse'` 或 `citations` 为空 → 不渲染引用区。
     - `rewritten_used` 为 true → AI 气泡头部展示小标签「已结合上文」。
   - **`event: delta`**：`text` 增量 append 到 `streaming.answerText`；经 **rAF 节流**后增量重渲染 Markdown（见 3.8），并自动滚底。
   - **`event: ping`**：忽略，不渲染（仅用于保活 / 判定卡死，见 §5）。
   - **`event: done`**：记 `answer_id`、`citations`、`grounding_score`、`synthetic`；若 `answer_id === 0` 或含 `error` 字段 → 按失败态处理（§5）。流关闭，`streaming.status='idle'`，刷新左栏排序（`updated_time` 已 touch）。
5. 渲染完成后的 AI 气泡进入「静态态」：Markdown 全文 + 引用折叠区 + 反馈栏（点赞/点踩）+ grounding 徽标（可选）。

### 3.4 停止 / 中断 / 重试

- **停止**：`AbortController.abort()` → fetch 抛 AbortError → 保留已收到的部分文本，AI 气泡标记「（回答中断）」，本地态 `interrupted`，显示「重试」按钮。后端会 best-effort 落 `INTERRUPTED` 历史。
- **重试**：对同一会话以相同 `message` 重新 `POST /chat`（后端会再落一条 user 消息；作为补偿，若上次 user 消息是刚才那条，可让后端靠历史改写消歧——MVP 不做消息级去重，见 §6）。
- **失败**：`done.error` 存在或 fetch 网络异常 → AI 气泡显示「回答生成失败，请重试」，态 `failed`，提供重试。

### 3.5 反馈（A07）

- 仅当该 AI 消息 `status === 'SUCCESS'` 且拿到 `answer_id` 时显示反馈栏（中断/失败态无 answer_id，不显示）。
- 点赞 `value=1` / 点踩 `value=-1`，再次点击取消（`value=0`）。
- `POST /feedback/{message_id}` body `{value}`；本地即时切换高亮，接口失败回滚 + `ElMessage.error`。
- **点踩后展开操作区**：「换一个回答」「重新生成」。二者当前都实现为对同一会话重发相同 message（后端无候选答案接口）；`meta.rewritten_used` 用于决定是否给出「重新生成」提示（已结合上文时优先「换一个回答」话术），MVP 两个按钮等效。

### 3.6 查看原文（A03）

- 触发源：引用卡片点击（`doc_id + article_no` 已具备）；或正文 `[n]` 上标点击（n → `citations[n-1]`）。
- `GET /article?doc_id=<doc_id>&article_no=<article_no>` → `data: ArticleOut` → `ArticleDialog` 弹窗展示全文（title/doc_no/category/doc_level/region/chapter/article_no/content/status/publish_date/effective_date/version/source_url）。
- **历史消息限制（契约缺口）**：`GET /conversations/{cid}/messages` 返回的 `sources` 只含 `document_id`（DB int）/`chunk_id`/`document_name`/`chapter`/`content`/`score`，**不含 `doc_id` + `article_no`**。故：
  - 当前会话内**流式回答的**引用卡片（来自 meta/done citations）可点查看原文；
  - **重新进入会话加载的历史消息**，其 sources 无法构造 `doc_id/article_no` → 「查看原文」按钮**置灰并提示「历史会话暂不支持查看原文」**，仅保留 snippet 展示。后端补齐字段见 §6。
- 404（未找到对应条文）→ `ElMessage.warning('未找到对应条文')`，弹窗不打开。

### 3.7 快捷提问（A04）

- 空会话态展示：`GET /quick-questions` → `[{category, question}]`，按 `category` 分组（安全生产/消防/应急处置/事故报告/职业健康/法律责任），每组为可点击标签。
- 点击 → 填入输入框并直接发送（走 3.3 完整链路）。

### 3.8 Markdown 渲染与引用脚注（安全）

- 用 `marked`（`breaks: true`，禁用 `raw html`）+ `DOMPurify.sanitize(..., {USE_PROFILES:{html:true}})`，所有 AI 文本**只经 `v-html` 输出清洗后的 HTML**，禁止直接 `v-html` 原文。
- `[n]` 脚注（1–3 位数字）在 **markdown 渲染后的 HTML** 上后处理：`html.replace(/\[(\d{1,3})\]/g, '<sup class="cite-ref" data-n="$1">[$1]</sup>')`。
  - 缺点：代码块内的 `[n]` 也可能被替换；MVP 接受，见 §6。
  - 点击 `sup.cite-ref` → 高亮对应 `CitationItem`（`el-scroll` 到引用卡片）或展开引用区；引用卡片点击正文中的 `[n]` 同理联动。
- 增量渲染：正文以增量文本累积，**rAF 节流**（约每帧一次）重渲染整段 Markdown 后局部替换气泡 DOM；回答较长时可降为「每 200ms 或最终渲染一次」防卡顿。`done` 后做一次最终全量渲染。
- 自动滚底：新内容到达时滚到底部；用户手动上滚时暂停自动滚（`messageListRef` 距底 <80px 才自动滚）。

## 4. 与后端契约（字段级）

### 4.0 通用约定
- 请求头：`Authorization: Bearer <access_token>`（token 来自 `POST /api/v1/auth/login`，OAuth2 表单）。任何接口 401 → 全局 Axios 拦截器清 token 并跳 `/login`。
- 统一响应 `{code, message, data}`：`code !== 200` 视为业务失败（HTTP 状态码 400/401/403/404/422，body 同为 `{code, message, data:null}`）。
- 归属校验 404 掩码：会话/消息「不存在 / 非本人」返回同文案（`会话不存在` / `消息不存在`），前端**统一提示**，不做区分。
- 全部接口需登录，**任意角色**可访问（模块二无管理员限制）。

### 4.1 智能问答 SSE（A01）— `POST /api/v1/ai/chat`

请求：
```json
{
  "conversation_id": 12,        // int | null；null=新建会话（首问自动标题=message 前 20 字）
  "message": "高处作业有哪些要求？", // string，1..2000
  "mode": null                  // string|null，MVP 恒 null（保留扩展位）
}
```
响应：`200`，`Content-Type: text/event-stream`，`Cache-Control: no-cache`，`X-Accel-Buffering: no`。

**流开始前**（尚无 SSE）即发生的错误——以 HTTP 状态码 + `{code,message,data}` 返回，前端走普通错误分支：
- `400`：命中敏感词（`message: "内容包含敏感词：…"`）；
- `401`：未登录；
- `404`：`conversation_id` 不存在或非本人（`会话不存在`）；
- `422`：`message` 空 / 超 2000 / 类型错误。

**事件格式**（每条 SSE：`event: <name>\n` + `data: <json>\n\n`），事件序 `meta → delta* → done`，LLM 静默 60s 发 `ping` 保活：

| 事件 | data 字段 | 说明 | 前端动作 |
| --- | --- | --- | --- |
| `meta` | `conversation_id:int`、`user_message_id:int`、`mode:'full'\|'conservative'\|'refuse'`、`confidence:float`、`citations: CiteCard[]`、`rewritten_used:bool` | 检索完、LLM 调用前发出 | 新会话建项；渲染引用卡片；`mode='refuse'` 时引用为空 |
| `delta` | `text:string` | 文本增量 | append + rAF 渲染 + 滚底 |
| `ping` | `type:'ping'` | LLM 60s 静默保活 | **忽略**（不渲染、不改状态） |
| `done` | `answer_id:int`（拒答/失败为 0）、`citations: CiteCard[]`、`grounding_score:float`、`synthetic:bool`、`error?:string`（仅失败） | 收尾 | 记录 answer_id；失败（answer_id=0 或 error 存在）按 §5 处理；流结束 |

`CiteCard`（meta 与 done 同构，`n` 从 1 起、与正文 `[n]` 一一对应）：
```json
{ "n": 1, "chunk_id": "...", "doc_id": "scaq", "title": "四川省安全生产条例",
  "chapter": "第二章 安全生产保障", "article_no": "第二十四条", "doc_no": "四川省...",
  "effective_date": "2023-...", "source_url": "https://...", "snippet": "内容前 120 字" }
```

**拒答路径**（后端 `mode='refuse'` 或检索为空）：不调 LLM，事件序为 `meta(citations=[]) → delta(固定话术) → done(answer_id=0, grounding_score=0.0)`。前端不渲染引用区，正文即话术。

### 4.2 会话管理（A02）— 均返回统一响应

| 接口 | 请求 | `data` 字段 |

| `DELETE /api/v1/ai/conversations/{cid}` | — | `data: null`（`message: "会话已删除"`） |

### 4.4 枚举速查

| 枚举 | 取值 | 前端映射 |
| --- | --- | --- |
| `role` | `user` / `assistant` | 右/左气泡 |
| `status` | `SUCCESS` / `FAILED` / `INTERRUPTED` | 正常 / 「生成失败，请重试」 / 「（回答中断）」+ 部分文本；`FAILED`/`INTERRUPTED` 显示重试、**无反馈栏** |

| `feedback` | `-1`/`0`/`1` | 点踩 / 无 / 点赞高亮 |

## 5. 异常 / 边界处理

| 场景 | 处理 |
| --- | --- |
| 未登录 / token 过期 | Axios 拦截器 401 → 清 localStorage token → `router.replace('/login')`；SSE fetch 收到 401 同理，先 `res.json()` 判 status 再统一跳转 |
| 敏感词（`/chat` 返回 400） | `ElMessage.error(message)`，AI 气泡回滚，输入保留可修改 |
| 会话不存在 / 非本人（404） | 统一提示「会话不存在」，若为当前会话则刷新列表并回落空会话态 |
| `message` 空 / >2000 | 前端输入框 `maxlength=2000` + 字符计数 + 空值禁用发送；后端 422 兜底 |
| 新会话但 meta 未到达（流首部即失败） | 无 cid 可建项；user 行已由后端落库，刷新会话列表后可见（标题=首 20 字）。提示重试 |
| 流中断（断网 / 后端崩溃 / `done` 未到） | 保留部分文本标记「（回答中断）」，提供重试；后端 best-effort 落 `INTERRUPTED` |
| 卡死（>90s 无任何事件，含 ping） | 客户端主动 abort + 提示「响应超时」，按中断态处理 |
| 发送中重复提交 | 发送期间输入框禁用 + 按钮变「停止」，单流互斥 |
| 历史消息点「查看原文」 | 按钮置灰（sources 无 doc_id/article_no，见 §6），仅展示 snippet |
| `article` 404 | `ElMessage.warning('未找到对应条文')`，不打开弹窗 |
| 反馈接口失败 | 高亮回滚 + `ElMessage.error` |
| 删除当前会话 / 全删 | 回落空会话态（快捷提问仍可用），列表保持空态 UI |
| XSS | AI 文本一律 `marked → DOMPurify` 后 `v-html`；引用 snippet/标题等也走同一清洗；禁止渲染后端未清洗字段为 HTML |
| 快速切换会话时流未结束 | 先 abort 当前流再切换；已收部分文本标记中断 |

## 6. 待实现细节

- **【后端契约缺口·需确认】** 历史消息 `sources` 缺少 `doc_id` / `article_no`，导致「查看原文」对重新加载的历史消息不可用。方案 A：后端在 `chat_service.list_messages` / `get_sources` 的 source 里补 `doc_id`+`article_no`（可经 `document_id` join 或检索层父块索引回填）；方案 B：新增 `GET /article` 支持按 `document_id` 查询。MVP 采用前端置灰方案。
- **重新生成语义**：后端无「候选答案 / 重写回答」接口，「换一个回答」「重新生成」MVP 均为重发相同 message（会多落一条 user 消息）。若产品要求「原答替换」，需后端加 `rewrite`/`regenerate` 接口并在同一 user 消息下替换 assistant 行。
- **侧栏宽度**：Element Plus 无现成拖拽组件。MVP 固定 `280px`；增强可选 `css resize:horizontal` 或自研拖拽（240–400px），记录在 CSS 变量。
- **会话列表分页**：后端支持 `page/page_size`，列表 >20 条时需「加载更多」或分页；MVP 拉首页 20 条。
- **Markdown 增量渲染性能**：超长回答时 rAF 全量重渲染可能卡顿，可降频（每 200ms）或分段渲染；`[n]` 后处理在代码块内的误替换待处理（可先对代码块占位保护）。
- **移动端适配**（PRD 6.3）：侧栏折叠 / 抽屉，仅影响 P05 布局，MVP 桌面优先。
- **`synthetic` 字段**：当前后端恒为 `true`，前端暂不展示；若后续区分真实引用答案可加「AI 生成」徽标。
- **Vite proxy 对 SSE**：`/api` 走 `http-proxy` 支持流式，但需确认 proxy 不缓冲（`proxyTimeout`/`x-accel` 头已由后端设置）；生产需前端同源或网关转发，避免 fetch 被代理层缓冲导致首字延迟。
- **`mode` 扩展位**：后端保留 `strict/precise` 语义，前端 UI 暂不暴露，`ChatIn.mode` 恒传 `null`。
