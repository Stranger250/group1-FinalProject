## ① 页面清单与路由

考试端全部页面**仅要求登录**（所有角色可访问，含 EMPLOYEE），不做角色门禁。管理端（P06-P08）由其他章节负责。

| 路由 | 页面 | 对应 PRD | 说明 |
| --- | --- | --- | --- |
| `/exams` | P09-阶段A · 选卷页 | §5.1 P09 | 员工可见的**已发布**试卷卡片列表，点击「开始考试」 |
| `/exams/:recordId` | P09-阶段B · 在线作答页 | §5.2 P09 线框 | 倒计时 + 题号导航 + 作答 + 防切屏；**刷新即恢复**（本路由 URL 携带 recordId，是恢复的锚点） |
| `/exams/:recordId/result` | P10 · 成绩单页 | §5.1 P10 | 总分 / 是否合格 / 每题作答 vs 正确答案 + 解析；交卷后自动跳转 |

**路由元信息与守卫**

- 三页均 `requiresAuth: true`；全局前置守卫：无 token → `/login`（带 redirect 回跳）。
- `/exams/:recordId` 挂载时 `GET /exams/{record_id}`（resume）；若返回 `state === 'SUBMITTED'` 直接 `router.replace` 到 result 页。
- 选卷页 `/exams` 的入口：顶部导航「考试中心」菜单（仅对非管理端展示入口，管理端仍以 P08 试卷管理为主，本页对管理端同样可用）。

**状态来源与 URL 协同**

开始考试 → `POST /exams/start {paper_id}` 拿到 `record_id` → `router.replace('/exams/' + record_id)`。此后一切刷新/恢复都靠 URL 里的 recordId，Pinia 内存态不承担持久化。

## ③ 关键交互与数据流

### 3.1 入口与开始考试
1. 选卷页 `/exams` 挂载 → `GET /api/v1/exams/papers`（公开、仅 PUBLISHED）→ 渲染卡片。
2. 点击「开始考试」→ `store.start(paper_id)`：
   - `POST /exams/start {paper_id}`。
   - 响应 `data` 可能是 **exam_sheet**（进行中）或 **result_sheet**（该试卷存在已超时的进行中记录被自动交卷）。
   - 用 `data.state === 'SUBMITTED'` 分支：是 → 直接进成绩单；否则初始化 answersMap、currentIndex=0、countdown，`router.replace('/exams/' + data.record_id)`。

> 说明：已存在进行中记录时后端复用（不新建）；已交卷记录可**重考**（后端 DB 唯一键只约束 ONGOING），故选卷页不做「已考过就禁用」。

### 3.2 作答数据模型
- 以 `Map<question_id, user_answer>` 为唯一作答源，键为题目 id（非 seq）。
- 各题型收集规则（**前端收原始值，规范化由后端 canonicalize 兜底**，见 §④）：
  - SINGLE / JUDGE：单选 → 单个选项标签大写 `"A"`。
  - MULTIPLE：勾选集合 → 逗号连接 `"A,C"`（后端会排序+去重，前端不必排序）。
  - FILL：按空位输入，`;` 连接为 `"空1;空2;..."`（与 DB §6.1 约定一致）；空位数量 = 题干中 `（数字）`/`(数字)`/`①②` 占位符数量，识别不到时回退为 1 个输入框。
- 切题保存：切换 currentIndex 前触发一次 `saveDirty()`。

### 3.3 自动保存（增量 + 防抖 + 定时）
- 触发点：① 切题（上一题/下一题/题号导航）时保存**自上次保存以来变更的题**（dirtySet）；② 全局定时器每 15s：dirtySet 非空即保存；③ `visibilitychange→visible`（切屏回来）保存；④ 页面 `beforeunload` 用 `fetch(keepalive:true)` 尽力保存。
- `saveDirty()`：取 dirtySet 对应题目的 `{question_id, user_answer}` 列表 → `POST /exams/{record_id}/save {answers}`。
- 防抖：`dirtySet` 在答案变更时 set，保存成功后清空对应项；连续快速作答只对当前批次发一次请求；用 `saving` 标志位避免并发（pending 时不重复发，合并到下一次）。
- **响应处理**：save 响应若是 exam_sheet → 用 `remaining_seconds` 校正倒计时、用 `answers` 回填（防御性对齐）；若 `data.state === 'SUBMITTED'`（被超时自动交卷）→ 显示提示并 `router.replace` 成绩单。

### 3.4 倒计时与时间到自动交卷
- **倒计时源**：以服务端 `remaining_seconds` 为权威（每次 start/save/switch/resume 响应都会带回），本地 1s 递减；**不做** deadline 字符串与本地时钟比对，规避服务端 naive 本地时间与客户端时区的漂移（后端返回的 deadline 为 naive ISO，无时区）。
- 到 0 → `store.submit()`：`POST /exams/{record_id}/submit {answers: 全量答案}`。
  - 后端 `_reason` 复查 `now >= deadline` → 交卷原因记为 `timeout`（权威在服务端，即使前端提前/延后 1s 也不影响）。
- 后端兜底：若前端定时器失效（如被节流），下一次 save/switch/resume 触发时后端懒校验超时自动交卷——前端在任一响应检测到 `state==='SUBMITTED'` 即跳成绩单。

### 3.5 防切屏
- 监听：`document.visibilitychange`（切到 hidden）与 `window 'blur'`（配合 `document.hidden` 去重，避免一次切换双计数）。
- 事件触发 → `cheatCount++`（本地累计）→ `POST /exams/{record_id}/switch {cheat_count: cheatCount}`。
- 响应二分支：
  - 未触发（`data.state` 不存在）：展示 `data.cheat_count`（服务端 max 合并后的权威值）到 SwitchWarnBar「已切 n/3 次」，`data.remaining_seconds` 校正倒计时。
  - 已触发（`data.state === 'SUBMITTED'`，即第 4 次切屏自动交卷）：`ElMessageBox` 提示「切屏超限，已自动交卷」，`router.replace` 成绩单。
- 注意：后端 `triggered` 字段恒为 `false`，**不可**作判断依据；一律以响应体是否含 `state === 'SUBMITTED'` 判断被自动交卷。
- 后端 `max` 合并计数（防前端重置为 0 绕开），阈值 `CHEAT_LIMIT=3`（>3 即第 4 次触发）。

### 3.6 手动交卷
1. 点击「交卷」→ `ElMessageBox.confirm`（提示：共 n 题、已答 x 题、未答 y 题）。
2. 确认 → `POST /exams/{record_id}/submit {answers: 全量答案}`。
3. 响应为 result_sheet → `router.replace('/exams/'+recordId+'/result')`。
4. 校验失败/异常：保留作答页，`ElMessage.error`，不跳转。

### 3.7 成绩单展示（P10）
- 挂载 → `store.result()`：`GET /exams/{record_id}/result`；或复用交卷响应（submit 返回的 result_sheet 已可渲染，避免二次请求）。
- 渲染：summary 区（总分/合格线/passed/reason/时间）+ 逐题卡片：
  - 题干 + 选项（`options`，FILL 为 null 则展示作答与答案文本）；
  - 用户作答 `user_answer` vs 正确答案 `correct_answer`（一致高亮绿、错误红）；
  - `is_correct`（0/1）与 `score`（该题得分）；
  - `analysis` 解析（无则显示「暂无解析」）。
- 多选判分口径由后端 `grade()` 保证（全对得满分，漏选/错选 0 分），前端**只展示后端已算的 `score`/`is_correct`**，不做二次判分。
- 「返回考试列表」→ `/exams`。

### 3.8 恢复（刷新）
- 刷新 `/exams/:recordId` → 挂载时 resume（`GET /exams/{record_id}`）：
  - exam_sheet：用 `questions` 重建题目、用 `answers` 回填 answersMap、`remaining_seconds` 重置倒计时、`cheat_count` 重置切屏显示 → 正常继续作答。
  - result_sheet：直接 `router.replace` 成绩单。
- 后端为该接口设 `Cache-Control: no-store`，前端不缓存。

### 4.2 考试会话接口

**POST `/exams/start`** — 开始（或复用进行中记录）

```
请求 data: { paper_id: int(≥1) }
响应 data: exam_sheet | result_sheet（见下）
错误：404 试卷不存在 / 400 试卷未发布(仅新建时校验) / 409 并发开始冲突(重试即可)
```

**GET `/exams/{record_id}`** — 恢复（进行中返回题目+已存答案；已交卷返回成绩单）
```
错误：404 不存在或非本人（掩码）；响应头 Cache-Control: no-store
```

**POST `/exams/{record_id}/save`** — 增量保存
```
请求 data: { answers: [{question_id: int, user_answer: str(≤255)}] }  // 重复 qid 后端去重取最后值
响应 data: exam_sheet | result_sheet（被超时/切屏自动交卷时）
错误：400 题目不属于本试卷 / 404 非本人
```

**POST `/exams/{record_id}/switch`** — 切屏上报
```
请求 data: { cheat_count: int(0..100000) }  // 前端累计值，可从 0 起步
响应 data（未触发自动交卷）: {
  record_id, cheat_count,            // 服务端 max 合并后权威值
  remaining_seconds, threshold: 3,
  triggered: false                   // 恒为 false，勿用作判断
}
响应 data（触发自动交卷，cheat_count>3）: result_sheet（state=SUBMITTED）
判定：data.state === 'SUBMITTED' → 已被自动交卷
```

**POST `/exams/{record_id}/submit`** — 交卷 + 自动阅卷
```
请求 data: { answers: [{question_id, user_answer}] }  // 全量答案
响应 data: result_sheet
错误：404 非本人（掩码）；422 校验失败
```

**GET `/exams/{record_id}/result`** — 成绩单
```
错误：400 尚未交卷无法查看 / 404 不存在或非本人（掩码）
```

### 4.3 视图结构（字段级）

**exam_sheet（进行中试卷视图，不含答案/解析）**

```ts
interface ExamSheet {
  record_id: number;
  paper_id: number;
  paper_name: string;
  state: 'ONGOING' | 'SUBMITTED';       // 出现 SUBMITTED 即已终态，应按成绩单处理
  total_score: number;
  pass_score: number;
  duration: number;                      // 分钟
  start_time: string | null;             // naive ISO
  deadline: string;                      // naive ISO（前端不依赖，用 remaining_seconds）
  remaining_seconds: number;             // 倒计时权威源
  server_time: string;
  cheat_count: number;
  questions: Array<{
    seq: number;                         // 题序（1 起）
    id: number;                          // question_id（作答 Map 的键）
    type: 'SINGLE' | 'MULTIPLE' | 'JUDGE' | 'FILL';
    content: string;
    options: string[] | null;            // FILL 为 null；JUDGE 固定 ["A 正确","B 错误"]
    score: number;                       // 该题分值
  }>;
  answers: Array<{ question_id: number; user_answer: string }>;  // 已存答案（恢复用）
}
```

**result_sheet（成绩单，交卷后唯一暴露答案与解析）**

```ts
interface ResultSheet {
  record_id: number;
  paper_id: number;
  paper_name: string;
  state: 'SUBMITTED';
  status: 'PASS' | 'FAIL';
  reason: 'manual' | 'timeout' | 'cheat_limit';  // 交卷原因
  total_score: number;
  pass_score: number;
  passed: boolean;
  submitted_at: string | null;
  start_time: string | null;
  duration: number;
  cheat_count: number;
  questions: Array<{
    seq: number;
    question_id: number;
    type: 'SINGLE' | 'MULTIPLE' | 'JUDGE' | 'FILL';
    content: string;
    options: string[] | null;
    user_answer: string;        // 用户作答（未作答=''）
    correct_answer: string;     // 判分快照（exam_answer.correct_answer）
    is_correct: 0 | 1;
    score: number;              // 该题得分（全对=full_score / 否则 0，后端已算）
    analysis: string | null;    // 解析
  }>;
}
```

**状态机（前端只需认知两种）**

```
ONGOING  ── submit ──┐
ONGOING  ── 时间到(timeout) ──┐
ONGOING  ── 切屏>3(cheat_limit) ──┐
        └──→ SUBMITTED（终态）→ 之后任何 save/submit/switch/resume 幂等返回同一 result_sheet
```

### 4.4 题型作答格式（对齐 DB §6.1，前端发送原始值，后端 canonicalize 兜底）

| 题型 | 前端控件 | user_answer 串格式 |
| --- | --- | --- |
| SINGLE 单选 | el-radio | `"A"`（选项标签大写） |
| MULTIPLE 多选 | el-checkbox | `"A,C"`（逗号连接；后端排序去重） |
| JUDGE 判断 | el-radio（选项固定） | `"A"` 或 `"B"` |
| FILL 填空 | 每空一个 el-input | `"空1;空2"`（`;` 连接，顺序对应题面空位） |

> 全角/大小写/多余空格等，后端 `canonicalize()` 统一归一（全角→半角；MULTIPLE 排序去重；SINGLE/JUDGE 大写；FILL 按 `;` 分空 strip、不转大写），前端无需对齐细节，但**判分结果以后端为准**。

## ⑤ 异常/边界处理

| 场景 | 前端处理 |
| --- | --- |
| 401 未登录/令牌过期 | axios 拦截器统一清 token → 跳 `/login`，带 redirect 回跳原考试页 |
| 404 掩码（无记录/非本人统一 404） | 考试页/成绩单页显示 `ElResult` 404 文案「记录不存在或无权限」；成绩单页提供返回选卷 |
| 400「考试尚未交卷」访问 result | 说明有 ONGOING 记录 → 跳回 `/exams/:recordId` 恢复作答 |
| 400「试卷未发布」start | 卡片已禁用该卷并提示（选卷接口仅返回 PUBLISHED，理论不触发，防御） |
| 409「开始冲突」start | 提示「请重试」；通常由并发导致 |
| 409「试卷已被删除」resume/save | 考试无法继续，`ElMessage.error` 后跳选卷页 |
| save 失败（网络/500） | 保留 dirtySet，标「保存失败」，下一触发点重试；退出考试前若仍有未保存，弹确认提示 |
| 超时自动交卷被后端抢先（save/switch 响应带 state=SUBMITTED） | 提示「考试时间到，已自动交卷」→ 跳成绩单 |
| 切屏自动交卷（switch 响应 state=SUBMITTED） | 提示「切屏超过 3 次，已自动交卷」→ 跳成绩单 |
| 倒计时到 0 但 submit 请求失败 | 重试一次；仍失败则提示并允许手动再点交卷（后端 deadline 兜底，后续任一接口会触发自动交卷） |
| 刷新瞬间丢失内存答案 | 依赖 resume 返回的 `answers` 回填；beforeunload 尽力同步一次 |
| 题干空位标记识别失败（FILL） | 回退单输入框；明确在 UI 提示「多个空请用中文分号；分隔」 |
| 多开浏览器 Tab 同卷 | 后端唯一键防同人同卷重复 ONGOING，后开的 Tab start 会复用同一 record；前端以「同一试卷只能有一场进行中」提示 |
| 组件卸载 | 清理定时器（countdown interval、autosave interval），移除 visibility/blur 监听，避免内存泄漏与重复上报 |
