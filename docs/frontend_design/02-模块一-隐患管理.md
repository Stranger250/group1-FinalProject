## 2. 公共基础设施

### 2.1 Axios 封装 `src/api/http.ts`

```ts
const http = axios.create({ baseURL: '/api/v1', timeout: 15000 })
```

- **请求拦截器**：有 token 时注入 `Authorization: Bearer <token>`；`FormData`/`URLSearchParams` 请求不手动设 Content-Type（交给浏览器）。
- **响应拦截器（成功）**：解包统一响应——`res.data.code === 200` 返回 `res.data.data`；`code !== 200` 视为业务失败，`Promise.reject(new Error(res.data.message))`。
- **响应拦截器（失败）**：取 `err.response.data.message` 作为错误文案；`status === 401` 时清空登录态并 `router.push('/login')`；其余（400/403/404/422/500/503）`reject(new Error(message))`，由页面层 `catch` 统一 `ElMessage.error`。
- **超时特例**：AI 识别接口单发 `timeout: 160000`（后端视觉识别等待上限 150s + 重试余量）；上传接口单发 `timeout: 30000`。

### 2.2 认证 store `src/stores/auth.ts`

```ts
state:  token: string (localStorage 'shudao_token' 持久化)
        user:  { id, username, name, role_id, phone } | null
getters: isLoggedIn; isManageRole  // role_id ∈ {SAFETY=2, ADMIN=3}
actions: async login(username, password)   // 存 token+user，写 localStorage
         async register(payload)           // 注册成功后前端提示，不自动登录
         async fetchMe()                   // 有 token 时调用 /auth/me 恢复 user；401 → logout
         logout()                          // 清 token/user/localStorage → router.push('/login')
```

App 启动时：`localStorage` 有 token 则 `await fetchMe()`（失败即被 401 拦截自动登出），保证刷新页面后角色信息（闭环按钮显隐依赖 `role_id`）正确。

### 2.3 枚举与常量（`src/constants/hazard.ts`，唯一真源，供各页面复用）


## 3. P01 登录/注册页（`/login` → `LoginView.vue`）

### 3.1 组件树

```
LoginView
├─ el-card（居中登录卡片）
│  ├─ 顶部 Logo/标题「蜀道安全助手」
│  ├─ el-form（ref=loginFormRef，model=loginForm）
│  │  ├─ username: el-input（前缀图标，placeholder 请输入用户名）
│  │  ├─ password: el-input type=password（show-password，placeholder 请输入密码，@keyup.enter 提交）
│  │  └─ 错误提示行（el-alert，登录接口返回的错误文案展示位）
│  ├─ el-button type=primary 登录（:loading）
│  └─ 底部链接「没有账号？立即注册」→ 打开注册弹窗
└─ RegisterDialog.vue（el-dialog）
   ├─ el-form（ref=registerFormRef，model=registerForm）
   │  ├─ username / password / confirmPassword / name / phone
   └─ 按钮：取消 / 注册（:loading）
```

### 3.2 关键交互与数据流

**登录**：

1. 校验通过 → `authStore.login(form.username, form.password)`；
2. 成功 → `ElMessage.success('登录成功')` → `router.replace(authStore.user ? '/hazards' : '/hazards')`（默认落地 `/hazards`）；
3. 失败 → 在卡片内错误提示行展示后端 message（401「用户名或密码错误」/ 403「账号已禁用」），不清空已输入的用户名。

**注册（弹窗）**：

1. 打开弹窗时重置表单；表单规则见 §4 表；
2. 校验通过 → `POST /auth/register`（JSON）；
3. 成功 → `ElMessage.success('注册成功，请登录')`，关闭弹窗，将 `{username, password}` 回填登录表单（后端注册不签发 token，不自动登录）；
4. 失败 → `ElMessage.error(message)`（如「用户名已存在」）。

### 3.3 表单规则

| 字段 | 必填 | 前端规则 | 后端契约约束 |
| --- | --- | --- | --- |
| username | 是 | required | 3–64 字符 |
| password | 是 | required，min 6 | 6–64 字符，且 utf-8 ≤72 字节 |
| confirmPassword | 是 | 与 password 一致 | — |
| name | 是（注册） | required | 1–64 字符 |
| phone | 否 | 选填；手机号正则 `^1\d{10}$` 软校验（不合法给提示但不阻断） | ≤20 字符 |

## 4. P02 隐患上报页（`/hazards/report` → `HazardReportView.vue`）

### 4.1 组件树

```
HazardReportView
├─ el-card「隐患上报」
│  ├─ el-form（ref=reportFormRef，model=reportForm，label-width=96px）
│  │  ├─ 隐患描述* : el-input type=textarea，maxlength=500，show-word-limit，rows=5
│  │  ├─ 隐患等级* : el-radio-group（4 档，每项下方展示 desc 文案）
│  │  ├─ 隐患类型   : el-select（HAZARD_TYPES，可清空；留空提交后端默认「其他」）
│  │  ├─ 隐患位置   : el-input，maxlength=128（placeholder：填写位置或留空）
│  │  └─ 现场图片   : HazardImageUpload（见下）
│  ├─ AI 识别面板  : AiAnalyzePanel（见下）
│  └─ 底部操作     : el-button 取消（返回列表）/ el-button type=primary 提交上报（:loading）
└─ （图片预览 / AI 标注图走 el-image preview）
```

### 4.2 HazardImageUpload 子组件

- **能力**：多图上传（最多 9 张）、缩略图预览、单图删除；同时维护「已上传 URL 列表」与「本地 File 列表」。
- **Props**：`urls: string[]`（v-model，随表单提交的 `/uploads/...` 数组）、`max=9`。
- **配置**：`el-upload` `list-type="picture-card"`、`accept=".jpg,.jpeg,.png"`、`:limit="max"`、自定义 `http-request`。
- **beforeUpload 前端拦截**（拦截不通过的返回 `false` + `ElMessage.error`，后端 400 兜底）：
  - 扩展名 ∈ `jpg/jpeg/png` 且 MIME ∈ `image/jpeg|image/png`，否则「仅支持 jpg/png/jpeg 图片」；
  - 大小 ≤ 5MB（后端 `max_upload_mb=5.0`），否则「图片不能超过 5MB」；
  - 当前数量 ≥ 9 →「最多上传 9 张图片」。
- **上传流程**：每个 File 单独调 `POST /hazards/upload`（FormData，字段名 `file`，timeout 30s）→ 返回 `{url: "/uploads/..."}` → 压入 `urls` 并记录该 File 到 `rawFiles`；失败 `ElMessage.error` 并从列表移除。
- **对外暴露**：`rawFiles: File[]`（供 AI 识别取文件）、`selectedIndex`（当前选中用于 AI 识别的那张）。

### 4.3 AiAnalyzePanel 子组件（AI 识别增强）

- **触发**：`rawFiles.length > 0` 时显示「AI 识别」按钮；点击对**当前选中图**（默认第一张，可点缩略图切换）发起识别。
- **请求**：`POST /hazards/analyze`（FormData `file` = 选中 File，timeout 160s），`:loading` 防重复点击。
- **成功回显**：
  - 建议区：建议类型（→ 回填 `type`）、建议等级（→ 回填 `level`）、图片描述（→ 填入 description 文本框作为草稿）、识别依据 `reason`、置信度 `confidence`（进度条/百分比）；
  - 标注图：展示 `annotated_url`（多框不同颜色 + 编号 1–N，与 detections 一一对应）；无有效框时 `annotated_url` 为 null，隐藏图片仅显示文本建议；
  - 检测列表：`detections[]` 每项渲染「编号 + type + level + description + confidence」，编号颜色与标注图框色一致；
  - **保留 `report` 对象**（analyze 响应的顶层 `report` 字段，内含 `annotated_url`）供提交时作为 `risk_report` 回传。
- **回填可编辑**：AI 建议**只做预填，不做锁定**，用户确认/修改类型、等级、描述后再提交（PRD「人工确认」口径）。
- **降级**：接口 503（模型未配置/超时）→ `ElMessage.warning('AI 识别暂不可用，请手动选择类型与等级')`，清空建议区，不阻断后续手动填写与提交。

### 4.4 提交数据流

1. 表单校验（description 必填 ≤500、level 必填）；
2. 组装 payload：
   ```ts
   {
     description: reportForm.description.trim(),
     level: reportForm.level,
     type: reportForm.type || '其他',
     location: reportForm.location?.trim() || null,   // 缺省后端落「未填写」
     images: imageUpload.urls,                        // 已上传 URL 数组（≤9）
     risk_report: aiAnalyze.report ?? null,           // 做过识别则回传，落 hazard.risk_report
   }
   ```
   （不传 title，后端自动取描述前 20 字生成。）
3. `POST /hazards` → 成功：`ElMessage.success('上报成功，编号：' + data.hazard_no)` → `router.push('/hazards')`（列表刷新，见 §5.4）；
4. 失败：`ElMessage.error(message)`，停留当前页保留已填内容。

### 5.2 请求参数

`GET /hazards`（query，全可选，不传则后端不筛）：

| 参数 | 值 |
| --- | --- |
| `status` | `WAIT_PROCESS` / `FINISHED` |
| `level` | `CRITICAL`/`MAJOR`/`GENERAL`/`MINOR` |
| `type` | 中文类型，如 `高处作业` |
| `keyword` | 匹配标题/描述/位置 |
| `start_time` / `end_time` | ISO 时间 `YYYY-MM-DDTHH:mm:ss` |
| `page` | 默认 1 |
| `page_size` | 默认 20（后端上限 100） |

### 5.3 响应数据

`{ page, page_size, total, items }`，`items[]` 字段见 §7.5。

### 5.4 关键交互

- **查询**：改任一筛选条件 → `page=1` 重新拉取（参数为空串/`undefined` 不发送）；
- **重置**：清空全部筛选 + 重置分页 + 重新拉取；
- **分页/每页条数**变化 → 重新拉取；
- **刷新时机**：进入页面 `onMounted` 拉取；从 P02 上报成功跳回（`router.push('/hazards')`）时页面组件**重新挂载**即自然刷新；同路由内由查询/重置驱动；
- **无权限/不存在**：列表接口登录用户可见全部（PRD 透明度设计），无需额外处理。

## 6. P04 隐患详情页（`/hazards/:id` → `HazardDetailView.vue`）

### 6.1 组件树

```
HazardDetailView
├─ el-card 头部
│  ├─ 标题行：hazard_no + title
│  ├─ 标签行：StatusTag(status) + LevelTag(level) + el-tag(type)
│  └─ 操作行：el-button「返回列表」/ el-button type=success「一键闭环」(角色+状态门控，见 6.3)
├─ el-descriptions :column=2
│  ├─ 上报人 creator_name / 上报时间 create_time
│  ├─ 位置 location / 更新时间 update_time
├─ el-card 隐患描述：description（全文，white-space: pre-wrap）
├─ el-card 现场图片
│  └─ el-image 缩略图列表（:preview-src-list 支持点击放大预览；空则提示「暂无图片」）
├─ el-card 处理进度（el-timeline，HazardTimeline）
│  └─ timeline[] 每项一个节点：时间 + operation + operator_name + remark + 状态流转徽标
└─ el-card AI 识别报告（仅 risk_report 非空时渲染）
   ├─ 标注图 annotated_url（若有）
   └─ detections 列表 / 建议类型等级 / 置信度
```

### 6.2 数据流

- 进入页面 `onMounted` → `GET /hazards/{id}` → 渲染 `detail`；
- 404（「隐患不存在」）→ `ElMessage.error` + `router.replace('/hazards')` 返回列表；
- **一键闭环**：
  1. 按钮显隐：`authStore.isManageRole && detail.status === 'WAIT_PROCESS'`；
  2. 点击 → `ElMessageBox.confirm('确认将该隐患标记为已闭环？','提示',{type:'warning'})`；
  3. 确认 → `POST /hazards/{id}/close` → 成功 `ElMessage.success('已闭环')` + 重新拉详情（时间线新增「闭环」节点，状态标签变已闭环，按钮消失）；
  4. 失败：403「无权限」/ 404 / 400（「仅待处理状态的隐患可闭环」）→ `ElMessage.error`，并刷新一次详情同步最新状态。

### 6.3 时间线渲染规则

- 后端 `timeline[]` 已按创建时间**倒序**（最新在前），直接顺序渲染 `el-timeline`；
- 节点展示：`create_time`（YYYY-MM-DD HH:mm:ss）+ `operation`（「提交」「闭环」）+ `operator_name` + `remark`；
- 状态流转徽标：`old_status → new_status` 用 StatusTag 分别渲染（`提交`节点 old 为空，仅显示 new=待处理）。

## 7. 与后端契约（字段级）

统一响应：成功 `HTTP 200` + `{code:200, message:"success", data:…}`；失败走 HTTP 状态码，响应体 `{code:<状态码>, message:<详情>, data:null}`（422 校验失败 message 形如 `description: Field required`）。**前端只看 `data` 与 HTTP 状态**（响应拦截器 §2.1 已统一处理）。

### 7.1 POST `/api/v1/auth/register`（公开）

请求（JSON）：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| username | string | 必填，3–64 |
| password | string | 必填，6–64 字符且 utf-8 ≤72 字节 |
| name | string | 必填，1–64 |
| phone | string? | 选填，≤20 |

响应 `data`：`{id, username, name, role_id, phone}`（role_id 恒为 1=EMPLOYEE）。

错误：400「用户名已存在」；422（字段校验）。

### 7.2 POST `/api/v1/auth/login`（公开，**OAuth2 表单**）

请求：`application/x-www-form-urlencoded`，字段 `username`、`password`（**不是 JSON，用 `URLSearchParams` 提交**）。

响应 `data`：

```json
{ "access_token": "<jwt>", "token_type": "bearer",
  "user": { "id": 1, "username": "zhangsan", "name": "张三", "role_id": 1, "phone": "13800000000" } }
```

错误：401「用户名或密码错误」；403「账号已禁用」。

### 7.3 GET `/api/v1/auth/me`（需登录）

## 8. 异常 / 边界处理汇总

| 场景 | 前端处理 |
| --- | --- |
| 未登录访问受保护页 | 路由守卫 → `/login` |
| 任意请求返回 401（token 过期/失效） | 拦截器清登录态 → `/login`（如：刷新后 `fetchMe` 失败） |
| 上传非图片 / 超 5MB | beforeUpload 先拦截提示；后端 400 兜底提示 message |
| 上传超过 9 张 | beforeUpload 拦截「最多上传 9 张图片」 |
| AI 识别 503 / 超时 | `ElMessage.warning`，清空建议区，**可手动选类型/等级继续** |
| AI 识别无有效框 | `annotated_url=null`，仅回显文本建议，隐藏标注图 |
| AI 识别置信度低 / 建议不合理 | 建议只预填不锁定，用户可改 |
| 提交描述/等级未填 | el-form 规则拦截（required）；后端 422 兜底 |
| 详情 404 | `ElMessage.error` + 返回列表 |
| 一键闭环非待处理状态 | 按钮已按状态隐藏；若并发已闭环返回 400，提示后刷新 |
| 一键闭环非管理角色 | 按钮隐藏；直接调接口 403 提示「无权限」 |
| 后端 500 | 拦截器取 message（如「编号生成冲突，请重试」）提示 |
| 列表无数据 | 表格空态（`empty-text="暂无隐患"`） |
| 详情/图片加载中 | 表格/卡片 `v-loading` |
