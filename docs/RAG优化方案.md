### 0.2 全局参数契约表

| 域 | 契约项 | 取值 | 决策理由（一句话） |
|---|---|---|---|
| 分块 | 原子检索单元 | **第X条 = 1 父块**（2087 个）+ 章头辅助块 199 个 | 条均 134.6 字，引用地址天然成立，问答粒度与"依据第X条"精确对齐 |
| 分块 | 父子块阈值 | 条长 **>400 字** 才二次分块 | 最长 907 字需留安全余量（中文约 1.1–1.3 字/token） |
| 分块 | 子块切分 | 按句（。；、），每组 100–250 字，相邻重叠 1 句 | 召回粒度 vs 上下文完整折中 |
| 分块 | 召回 / 展示对象 | 召回在**子块**上做；引用/展示**永远用父块** | 长条整体嵌入稀释语义；A01 来源引用的最小可信粒度是"第X条" |
| 块 ID | 格式 | `{doc_id}_{article_no}_{version}`，例 `scaq_第二十四条_v2023` | 幂等 upsert + 人读可展示 + 支持版本追溯 |
| 召回 | embedding | bge-large-zh-v1.5（`normalize_embeddings=True`，本地**绝对路径**加载） | 1024 维、中文法规语料成熟；暂不精调（Top-5 召回 <80% 再精调） |
| 召回 | 向量路 | Top-50，`cos ≥ 0.30` 粗剪 | 宽松剪枝，精筛交给重排 |
| 召回 | 关键词路 | jieba 分词 + rank_bm25，Top-50 | 条文有大量精确术语（条号/期限/金额），BM25 必须字面命中 |
| 融合 | 算法 | RRF，K=60，取 Top-20 | 两路分数量纲不可比，RRF 只看排名，零调参 |
| 重排 | 算法 | bge-reranker-base（cross-encoder）Top-20 → **Top-5** | 法条细节敏感，bi-encoder 对"同法不同条/相近术语不同义务"钝感 |
| 注入 | 给 LLM 的块数 | **最多 Top-5**（含引用展开块） | 5 条约 675 字正文 + 元数据 ≈ 2k token，远低于窗口 |
| 生成 | 主模型 | **DeepSeek-V3**（默认） | 实训已接通、TTFT 低、SSE/并发好 |
| 生成 | 降级模型 | ERNIE-Speed / qwen-turbo（成本收紧档）；高难问题路由 qwen-plus | 强检索 + 小模型即可，单问成本 <0.01 元 |
| 生成 | 采样参数 | `temperature=0.1, top_p=0.9, max_tokens=800, penalties=0` | 法律回答要确定性；max_tokens 统一 **800** |
| 生成 | SSE 协议 | `meta(citations) → delta* → done`；心跳 `ping`（60s） | 引用预声明先于文本，前端先渲染"依据"占位行 |
| 阈值 | 置信度 | RRF 融合分 **min-max 归一化到 [0,1]**：top-1 <0.30 拒答 / 0.30–0.45 保守 / ≥0.45 全量 | 全链路唯一分制，重排分只做相对排序不做阈值 |
| 引用 | 交叉引用展开执行层 | **仅检索层**（重排前一次联动召回），展开块打标 `expanded=true`；生成层不展开 | 防双重展开；模型不负责补全引用内容（防幻觉） |
| 引用 | 来源列表组装 | 后端从 `meta`/`done` 的 citations 累积数据渲染，**不由模型生成** | 杜绝"有脚注无来源"的伪造 |
| 出题 | 取料 | 每知识点 **6–10 条**（1 正确 + 2~4 干扰 + 冗余） | 条均 134.6 字，单条信息量不足以撑起四个选项 |
| 出题 | 难度判定 | 规则评分器：0=简单 / 1=中等 / ≥2=困难（离线预计算入 metadata） | 不靠模型感觉 |
| 出题 | 准确率口径 | **对外验收 = 审核通过率** `(直接通过+文案润色后通过)/批次总数 ≥80%`；**内控** = 已入库题目双人抽样正确率 ≥95% | 对齐 PRD E02 人工确认入库；内控从严水位 |
| 性能 | 在线指标 | 并发 ≥50QPS；AI 首字 ≤3s；检索链路 API ≤500ms P95；SSE 流式 | PRD §6.1 性能指标（50QPS 为 AI 接口内部压测目标） |
| 性能 | 链路预算 | 改写→召回→融合→重排 **≤400ms**；LLM TTFT 800–2000ms | 首字=引用块先行（~400ms），正文 ≤3s |
| 缓存 | L1–L4 | L1 检索结果 LRU 5min / L2 语义近似 Redis 10min / L3 生成结果 Redis 30min / L4 热门知识点 1h；空结果缓存 60s | 查询高度重复，缓存是省成本扛 QPS 第一杠杆 |
| 评测 | 主评测集 | 问答 3100（法规 2200 + 场景 600 + 边界拒答 300）+ 多轮集（新增，见 §5.4）+ 出题专项 620 | 版本化冻结，上线门禁用 |
| 评测 | CI 冒烟集 | 200 问 + 30 拒答 | 每次改动快速自检，不等全量回归 |
| 评测 | 检索目标 | Recall@5 ≥0.92 / MRR ≥0.85 / NDCG@5 ≥0.90 / 命中条号正确率 ≥0.95 / top-1 命中 ≥0.70 | top-1 与用户感知最相关，单列 |
| 评测 | 生成目标 | 引用覆盖率 ≥95% / 引用可核验率 100% / 幻觉率 ≤5% / 拒答正确率 ≥95% | A01 验收点（来源引用 / 防幻觉） |

> **落地约束**：以上参数统一放**配置中心**（`config.py` + JSON，带 `version`），代码层 import 唯一配置源；任何一章的实现不得自行定义第二套取值。知识库重建、检索参数、prompt 版本改动前先过 §5 回归门禁。

### 0.4 效力优先级规则（裁决在排序与作答层，检索不删结果）

1. 法律 > 行政法规 > 部门规章；法律 > 地方性法规 > 政府规章（`doc_level` 数值编码）；
2. 同位阶：新法优于旧法；特别规定优于一般规定；
3. 部门规章与地方性法规同位阶冲突时，四川地域内适用四川本地规定；
4. 重排分数基础上给**上位法小幅加权（+0.05~0.1）**；生成时对"地方法 vs 上位法冲突"输出并列结构并以"上位法为准"提示，**不替用户裁决**（见 §3.5.4）。

### 0.5 交叉引用展开：唯一执行链

```
知识库构建期（离线）: 全量扫描 172 处内容内引用 → 建引用边 → 写入 ref_out
检索期（在线，重排前执行一次）: 命中条含 ref_out → 按 doc_id+条号精确查回被引条 → 追加进 LLM 注入列表，打标 expanded=true
生成期（不展开）: 模型只"点选"注入块编号；库内被引条照常给脚注；库外引用原样保留条号但不给脚注，来源列表附"※ 建议查看原文"
```

防双重展开：展开动作只发生在检索层；生成层收到的是已展开的块，不再二次解析引用。

### 1.2 法规语料组织与检索优先级

#### 1.2.1 效力分层与冲突裁决

见 §0.4（裁决在排序与作答层，检索不删结果）。

#### 1.2.2 检索优先级：四川法优先、国家法兜底

**决策**：主召回不做层级过滤（保 recall），排序时用 `region`/`doc_level` 加权；四川法召回不足时，自动补召国家法同主题条款。这样"有限空间作业""高速公路施工安全"等四川本地高频场景优先命中 11 部主体法规，涉及上位依据（如处罚、事故报告）时国家法自然浮现。

#### 1.2.3 跨法规交叉引用（172 处）的处理

实测正文含 172 处"第X条"式内容引用，典型如四川条例"依照《中华人民共和国安全生产法》第X条"。**决策：原文保留 + 引用展开双机制，不改写正文**：

1. **原文保留**：`content` 一字不改，被引条款仍独立存在于其所属 doc 的块中，不破坏引用地址，杜绝改写引入的幻觉。
2. **引用索引**：全量扫描 172 处，用正则 `《[^》]{1,30}》第[一二三四五六七八九十百零]+条` + 指代映射表（"本法/该条例"解析到当前 doc）建引用边，写入元数据 `ref_out`。
3. **检索时引用展开**：命中条含 `ref_out` 时，自动把被引目标条（在库内者）一并召回进上下文。解决"四川条例引用国家法、但国家法条文未被召回"的检索断层。
4. 被引目标在库外的（引用已废止旧版或外部文件）：保留引用文本，`ref_out` 标记为"库外/待补"，进入企业补充清单。

### 1.3 分块策略：章/条原子分块 + 父子块（契约 0.2）

**为什么按条分块优于定长切块**：

| 维度 | 定长切块 | 按条原子块（选定） |
|---|---|---|
| 引用完整性 | "第X条"编号常被腰斩或并进相邻块 | 一条=一块，引用地址天然成立 |
| 问答粒度 | 一块常横跨条边界（条均仅 134.6 字） | 与"依据第X条"提问粒度精确对齐 |
| 交叉引用 | 172 处引用无法稳定定位到块 | 每条有稳定 ID，引用展开可落地 |
| 冗余 | 重叠产生重复存储与召回噪声 | 无重叠 |
| 更新 | 修订一条牵动多个块 | 按条精准替换 |

- 块数：2087 条 + 199 章头辅助块 ≈ **2286 父块**。
- 长条：>400 字按句切子块、子块召回、**父块全文进 LLM、引用永远用父块**（契约 0.2）。建议先用脚本实测 2087 条长度分布后固化阈值。

### 1.4 落库流水线与增量更新

```
crawler_output/*.json
  → audit.py   质量审计（crawler/audit.py，输出 docs/_rag_data_audit.json + 字段级缺失统计）
  → clean.py   清洗（strip 标题、去 BOM、补元数据、统一 status 三态、规范 article_no 字段名）
  → parse.py   解析 chapters/articles → 原子块 + 章头块 + 长条父子块
  → tag.py     打 domain_tags + difficulty（出题评分器离线预计算，见 §4.3）
  → ref.py     扫描 172 处交叉引用建 ref_out
  → embed.py   bge-large-zh-v1.5 批量（batch=32）
  → load.py    Chroma（collection=shudao_kb, id=chunk_id, 幂等）
  → verify.py  抽样验证召回命中率
```

**增量与修订（双轨，不建额外版本库）**：补漏/新法规 → 重跑 clean/parse/embed/load，upsert 幂等；法规修订 → 更新源文件 → 人工核对修订依据 → 新 `version` 覆盖 + `is_latest=true` → 检索默认只召回现行版；旧版本不删（2087 条规模开销可忽略，为"新旧条款对比"留后手）。现成例子：四川省消防条例 `status=已修改`（2011 生效）需核实最新修订文本后入新版。

### 1.5 企业文档补充导入路径

现状缺口：内部制度/操作规程/事故案例无数据。管道：**Web 管理后台上传 → 解析分块 → 人工审核发布**。

1. 上传解析：Word/PDF/MD/TXT（python-docx / pypdf / docx2txt），超长扫描件走 OCR 预案；
2. 分块：企业文档无"条"结构，**按标题树切块**（一/二级标题为界），长章节沿用父子块；无标题文档 jieba 分句后按语义阈值聚合；
3. 审核发布：预览分块与元数据草稿 → 人工确认 `doc_type` / `access_level` / 生效日期 → 入同库；
4. 补充优先级：① 蜀道集团安全生产责任制内部制度；② 高频工种操作规程（隧道/桥梁/高边坡/有限空间作业）；③ 近三年典型事故案例与整改报告；
5. 案例特殊处理：全文脱敏 + 文首加"结论性要点"前置段（便于检索命中与 A01 来源引用）。
6. **与出题衔接**（评审补充项）：`access_level=内部/机密` 的文档**不进入出题取料**（考试面向公开法规，避免涉密外泄）；案例"结论性要点"不参与难度评分（难度评分器只作用于法规条文）。出题检索默认 `doc_type=法规`。

### 1.6 数据质量治理

实测问题与处置（详见 `docs/_drafts/1-知识库构建.md` §2.7）：title 前导空格 `strip()`、doc_no 为空官网核对/兜底"—"、effective_date 为空用 publish_date、status 统一三态、版本疑似过期（消防条例 2011、生产责任规定 2007、突发事件办法 2012）人工核实。

质量闸门：以审计报表的"字段缺失率、引用解析覆盖率（172 处中成功解析到库内目标的比例）、未补元数据清单"作为上线准入与巡检指标。

## 二、检索层优化（召回层）

目标：在 2087 条语料下把 A01 的精准检索做到可量化——检索到**正确且最小可回答单元**的条文。**领域过滤 → 混合召回 → RRF 融合 → 交叉编码器重排 → 引用展开**五段流水线，全部参数取契约 0.2。

### 2.1 Embedding 选型：bge-large-zh-v1.5，暂不精调

| 维度 | bge-large-zh-v1.5 | bge-m3 | 结论 |
|---|---|---|---|
| 向量维度 | 1024 | 1024 | 持平 |
| 最大长度 | 512 token | 8192 token | 本语料 >95% 条文在 512 内，长条由父子块兜底 |
| 检索能力 | 稠密 | 稠密+稀疏+ColBERT | 稀疏能力与 BM25 重复，边际收益低 |
| 推理成本 | 低（CPU/ONNX 可跑） | 高 | 直接关系 50QPS / ≤3s 预算 |

**暂不精调**：法规条文是规范书面语，通用能力已覆盖；预留判定标准——上线后 **Top-5 召回率 <80%** 才用 2087 条做领域对比学习（LLM 构造难负例、条内字面替换做正例增强）。切换/重灌成本极低（2087 条）。

### 2.2 混合检索：向量 + BM25（jieba）+ RRF

数据特征决定双路必要：① 172 处交叉引用 + 大量精确术语（条号/期限/金额）靠**字面命中**，BM25 天然擅长；② 条文短（均长 134.6 字），短文本 BM25 得分不受长度归一化稀释，"条文级"语料上 BM25 比长段落语料可靠得多。融合用 **RRF（K=60）**：向量分与 BM25 分量纲不可比，加权需调两组权重且不稳定；RRF 只看排名，鲁棒零调参（本项目实训已实测 K=60 稳定）。

### 2.3 查询理解与改写（三级，带延迟预算与旁路开关）

1. **口语化 → 法言法语**：规则初筛（口语词/标点/疑问词）+ LLM 改写（`max_tokens ≤48`），约六成规范查询零改写成本。例：`高速上出了事故找谁 → 高速公路交通事故 应急处置 职责`。
2. **多轮查询改写（归检索层）**：维护最近 2~3 轮 + 当前问，LLM 生成独立成句查询（standalone query），继承首轮锁定的领域过滤条件；**仅当含指代词或轮次≥2且问≤6字才触发**；结果会话级缓存。
3. **同义词/术语扩展（仅 BM25 路，OR 扩展，最多 2~3 个）**：蜀道领域术语词典（人工审核 + 评测校验），例：`高速公路↔高速↔高等级公路`、`有限空间↔受限空间`、`坍塌↔冒顶↔塌方`。向量路不扩展（避免噪音）。

改写→重排整链预算 **≤400ms**（契约 0.2），改写是耗时的 LLM 调用，必须在首字预算内消化。

### 2.4 重排：bge-reranker-base 精排（Top-20 → Top-5）

**重排对法条场景是"必要"而非"可选"**：正确条文与混淆条文（同法规不同条、相近术语不同义务）在语义向量上邻近，却承担完全不同义务（时限 30 日 vs 15 日、部门 A vs B）。bi-encoder 只做独立编码，对细节差异钝感；cross-encoder 让查询与条文联合注意力，直接服务 A01 来源引用准确与防幻觉——**Top-5 里混入一条"像但不准"的条文，LLM 大概率引用它，这是幻觉源头**。

选型：`bge-reranker-base`（512 窗口条文级足够）；后续超长条/多文档聚合可升 `bge-reranker-v2-m3`。重排分只做**相对排序**，绝对阈值统一走归一化置信度（契约 0.2，见 §3.5.2）。

### 2.5 蜀道领域过滤（召回前）

两级过滤，避免误过滤漏召：

1. **元数据过滤**（Chroma `where`）：`domain_tags` / `region` / `category` / `access_level` 组合。业务域 → 命中法规：隧道/公路施工 → 高速、道路运输、消防、有限空间；地质灾害 → 地灾、突发事件；有限空间作业 → 有限空间、安全生产法；生产安全事故 → 事故报告、生产责任；道路交通事故 → 道交责任制、道交实施办法、道路运输、高速。
2. **意图分域**：改写后轻量意图分域（关键词表优先，兜底 LLM 分类）。置信度高时先过滤再召回；置信度低时全量召回交给重排裁决。
3. **权限过滤（评审补充项，强制）**：用户角色 → 可见 `access_level` 集合 → 召回前 `where access_level ∈ 集合`。未登录默认仅 `公开`；内部用户升级角色后刷新权限缓存，检索结果不得越权展示（与 §7 查看原文接口权限一致）。

### 2.6 交叉引用联动召回（172 处专项）

命中 Top-3 中任何一条含 `ref_out` → 按 `doc_id + 条号` 精确查回被引条 → 一并进 LLM 注入列表（打标 `expanded=true`）。价值：① 避免 LLM 对"第X条"内容凭空生成（直接命中数据痛点）；② 解决"四川条例引用国家法、但国家法条文未被召回"的检索断层；③ 精确条号查找由 BM25 词表索引保证零丢失，内存级毫秒完成，不占延迟预算。

### 2.7 top-k 取值逻辑

2087 条语料足够小：**召回给足 Top-50（穷尽相关条文），靠重排收敛到 Top-5**——"召回宽、精排严"低成本高收益。注入 LLM 最多 5 块（契约 0.2）。

## 三、生成层优化（A01 来源引用 / 防幻觉落地层）

设计目标一句话：**让模型只能"照着检索到的块说话"，引用的每一条都能点回原文，检索不到就明说不知道**。

### 3.1 输入输出与职责边界

| 环节 | 输入 | 输出 | 职责 |
|---|---|---|---|
| 安全前置 | 用户原始问题 | 过滤后 / 拦截响应 | 敏感词、涉密、诱导拦截（§3.8） |
| 会话管理 | session_id + 问题 | 改写后问题 + 历史摘要 | 5 轮多轮（§3.6） |
| 检索 | 改写后问题 | top-5 块 + 元数据 + 归一化置信度 | 来自 §2，含引用展开 |
| 引用校验 | 注入块列表 | 合法引用集合 | 防伪造引用（§3.4.4） |
| Prompt 组装 | 系统 Prompt + 检索块 | 注入后的消息 | 硬约束注入（§3.3） |
| 生成 | 注入消息 | SSE 流（meta + delta + done） | 流式（§3.7） |
| 输出后处理 | 模型原始流 | 清洗后回答 | 越界角标删除、安全复检 |

关键决策：**检索块放 user message、系统约束放 system message**（每轮检索块都变，system 固定可做 Prompt 版本缓存；便于后端把"注入块列表"与"允许引用集合"严格对齐做引用校验）。

### 3.2 模型选型与参数（契约 0.2）

- **主模型 DeepSeek-V3**：实训环境已接通（`BASE_URL/API_KEY/MODEL_NAME`），TTFT 低、SSE 支持好、并发性价比高。备选 qwen-max（长文本法律条款忠实复述稳定），统一 OpenAI 兼容接口无缝切换。
- **成本降级档（评审协调，非矛盾）**：工程层 §6.7 的"小模型 + 强检索"是**容量不足/预算收紧时的降级路径**，不是默认。判定依据：单问成本、TTFT、幻觉率三项 A/B 对比后决定。高难问题（多条款交叉/事故定责/跨法比较）始终路由大模型。
- **不用本地 LLM**：法律回答对生成质量要求高，本地 7B 级在"只依据上下文复述"上抖动大，且实训机无推理卡。
- 参数：`temperature=0.1, top_p=0.9, max_tokens=800, presence/frequency_penalty=0`。

### 3.3 系统 Prompt 设计

**角色**：蜀道安全助手——面向交通建设企业安全员的安全生产法规咨询专职助手。限定服务对象（安全员，回答落到"现场安全管理/责任/处罚"）、知识范围（蜀道知识库 28 部法规）、输出风格（列依据、给原文、不猜测）。

**最高约束（防幻觉第一道闸门，system 首部）**：

```
1. 你只能依据下方 <context> 中给出的知识库条文回答。
2. 回答中的每一个事实断言（罚款金额、期限、责任主体、处罚措施等）
   都必须能在 <context> 中逐字找到出处，并标注脚注编号。
3. 严禁使用 <context> 之外的任何法律条文、你的预训练记忆或常识推断法律内容。
4. <context> 之外的内容一律不回答。
5. 涉及具体数值/期限/条款号时，必须原样复述 <context> 原文，不得改写、推算或四舍五入。
```

第 5 条针对 172 处交叉引用和大量数字条款——模型最易"补充常识"处，用"原样复述"压死。

**完整 Prompt 草案**（直接落地版，详见 `docs/_drafts/3-生成层优化.md` §5.3.4）：system 固定；user 内 `[1]…[n]` 块（最多 5 个）+ 历史摘要 + 本轮问题。

### 3.4 引用机制（A01 来源引用验收点）

- **回答内脚注 `[n]`**：n = context 块注入序号，与块一一对应；一条依据句后跟一个 `[n]`，同段引多块用 `[1][2]` 并列。**编号集合由注入块决定，模型只"点选"**。
- **引用来源列表**：回答末尾由后端从 `meta`/`done` 的 citations 累积数据组装，**不由模型生成**（杜绝编造来源），保证 100% 可点回原文。
- **grounding 校验器（流式结束、缓存入库前执行）**：正则提取全部 `[n]` → 校验 n ≤ 注入块数且块在本轮注入列表内 → 越界角标删除 → 删除后无任何有效脚注则判"无依据回答"，触发重生成（最多 1 次）或降级拒答 → 可选加强：断言句与引用块 embedding 余弦 <0.60 打标"待人工复核"。
- **交叉引用（生成层不展开）**：库内被引条已在注入列表则照常脚注；不在则原样保留"依据安全生产法第X条"字样但不给脚注，来源列表加一行"※ 第X条原文未在当前检索范围内，建议查看全文"。

### 3.5 幻觉抑制

1. **强制引用（grounding 驱动）**：没有检索块 → 不进入生成，直接走拒答，省一次调用。
2. **置信度分支（唯一分制，契约 0.2）**：top-1 归一化 <0.30 拒答话术（带检索建议，不调生成）；0.30–0.45 保守模式（只答单点结论 + "建议查阅原文"）；≥0.45 全量回答。多轮追问在"改写后"query 再算置信度，避免改写失败导致假阳性。
3. **多文档一致性校验**：注入块含 ≥2 部法规且主题重叠时触发；LLM 结构化判定 `{conflict, level, verdict}`；冲突时输出并列结构 `上位依据：安全生产法第X条…；地方补充：四川条例第X条…` + "不一致时以国家上位法为准，具体执行请咨询企业法务"——**不替用户裁决**，把冲突显式暴露给安全员。
4. **高风险断言人工兜底**：处罚金额/事故等级/审批流程三类断言，管理端一键"引用原文比对"。

### 3.6 多轮对话：5 轮上下文管理

- 会话槽：Redis/内存，**上限 5 轮**，第 6 轮提示"已达上限，建议新开会话"并归档。
- **历史不逐字存，只存每轮摘要**：每轮回答后把「用户问 → 2-3 句摘要（含法规名、条款号、关键实体、结论）」写入历史队列；注入为一段"历史摘要"文本。
- **本轮 query 改写归属检索层**（§2.3，改写发生在检索前）；生成层只负责摘要存储与注入。
- **引用追溯**：引用只指向当轮注入块，历史摘要不带脚注（防跨轮错乱）；用户追问"你上轮说的第 21 条"，改写把"第 21 条"带回检索重新命中并给**本轮新脚注**。

### 3.7 SSE 流式输出与引用先返（契约 0.2）

```
GET /api/chat/stream → SSE
event: meta      // 第 1 个事件，预声明引用（由注入块直接生成，不依赖模型）
data: {"task_id":"...","citations":[{"n":1,"doc_id":"scaq","title":"四川省安全生产条例",
       "chapter":"第二章 安全生产保障","article_no":"第二十四条","snippet":"..."}, ...],
       "mode":"full|conservative|refuse"}

event: delta     // 文本增量
data: {"d":"生成文本增量token"}

event: done      // 结束：完整引用列表 + 校验统计
data: {"answer_id":"...","citations":[...],"grounding_score":0.92,"elapsed_ms":2800}

（间隔 60s 发 event: ping 保活；断线按 task_id 重连续推）
```

**要点**：citations 在检索完成后、LLM 调用前已组装，前端收到 `meta` 即渲染"依据来源"卡片并高亮条号，正文流到 `[n]` 处即可匹配高亮；检索为空时直接返回 `meta`（空引用）+ `delta`（"知识库未检索到相关内容"）+ `done`，**不调 LLM**，杜绝幻觉兜底回答。

### 3.8 敏感词过滤与安全审核（接入三个位置）

1. 入口（网关/FastAPI 中间件）：DFA 词典 + 可选云内容安全 API，命中即拦截，不进检索与 LLM；
2. 输出流式过程：delta 逐片过内容安全（供应商 API 输出审核 + 本地词库双检），违规片拦截为 `[已屏蔽]` 并追加事件；
3. 落库前：问答日志（prompt/回复）写入审计库前再扫一遍。
敏感词库随 `data/sensitive_words.txt` 维护，与法规同走每日 diff 流程。

## 四、AI 出题专项（模块三 E02，准确率 ≥80%）

### 4.1 出题 vs 问答：检索模式完全不同

| 维度 | A01 问答 | E02 出题 |
|---|---|---|
| 输入 | 自然语言问题（一条） | 知识点 + 难度（结构化） |
| 检索目标 | top-1 相关条文 | **每知识点捞 6~10 条**（1 正确 + 2~4 干扰 + 冗余） |
| 召回粒度 | 相关度优先 | 知识点标签过滤 + 难度过滤 + 相关度排序 |
| 时效性 | 在线、SSE、≤3s | **离线批处理，不占在线并发指标，对准确率极度敏感** |
| 输出 | 自然语言 + 引用 | 结构化 JSON 题目（入题库，人工审核后上线） |

**三段式检索**：① 知识点路由——2087 条 LLM 离线打标 1~3 个标签（词表约 80 个，如"主要负责人职责、双重预防机制、有限空间作业审批、事故报告时限、处罚幅度"），人工抽检 5%~10%；标签写入 metadata。② 难度过滤——难度评分器（§4.3）离线预计算，出题时 metadata 过滤 O(1)。③ 多条文取料——知识点描述性 query 向量 top-8 召回（可叠加 BM25+RRF），默认以**四川本地法规为主体取料**，国家法作为解析中的上位依据（输出引用链如"《四川省安全生产条例》第X条 → 依据《安全生产法》第Y条"）。

### 4.2 出题 Prompt 与四题型模板

**防幻觉锚点 = 条号**（system 硬性规则）：所有事实逐字/严格等价于材料条文；解析必须引用具体条号且该条号必须存在于材料中；干扰项必须取自材料中其他条文的真实内容改写；严格按 JSON 输出。

- **单选**：正确项逐字对应一条文；3 干扰项从取料包其他条文真实事实改写；解析分"依据（引条号摘关键句）"+"排除（说明差异）"两段。
- **多选**：5 选项（2~3 正确），正确项集合唯一；典型出题点 = 多主体并列义务、"三同时"包含项、演练频次。
- **判断**：同义改写或**扭曲改写**（改期限/主体/倍数/加否定词），扭曲必须源于真实条文；解析点明改写点。
- **填空**：空位唯一、答案唯一、逐字出自条文（多为期限/金额/主体名词），严禁多解。

**输出后硬校验（不依赖模型自觉）**：从 `analysis` 正则抽"第X条"逐一核对是否在取料包中；条号不在材料内 → 整题重生成（最多 2 次），仍失败标 `generation_failed` 不进库。

### 4.3 难度评分器（离线预计算入 metadata）

| 条文特征 | 加分 |
|---|---|
| 定义性/单纯义务条款（无数字无处罚） | 0 |
| 含处罚条款（罚款/停产/吊销/拘留/万元） | +1 |
| 含数字条款（X日/月/年、倍数、金额、百分比） | +1 |
| 多主体/多情形并列 | +1 |
| 交叉引用 ≥2 处 | +1 |
| 条文 >300 字 | +1 |

**三档判定：0=简单 / 1=中等 / ≥2=困难**。`difficulty=困难` 时强制取料包 ≥3 条带处罚/数字特征条文，并对召回结果按难度评分重排序。

### 4.4 题目去重与干扰项溯源（杜绝编造）

- **三层去重**：检索层（批次内正确项条文互不重叠）→ 生成层（题干规范化后 SimHash 64bit，汉明距离 ≤3 判重复）→ 选项级互斥（干扰项条款池，同一数字只允许作一次正确答案）。
- **干扰项全部来自取料包真实条文**：真实主体/处罚幅度/期限（数字改写为同法规真实存在的另一数字）。
- **溯源强校验**：抽取选项关键事实（数字/期限/金额/主体词）在材料中匹配（jieba + 正则数字归一），**任一选项无出处 → 整题重生成**；重试 2 次仍失败用规则从真实条文构造替换。结果写 `interference_verified` 供审核工作台展示出处。

### 4.5 与人工审核衔接（E02 人工确认）与 ≥80% 口径（契约 0.2）

- **状态机**：`draft → pending → approved | rejected`，另有 `draft 修改`（审核人编辑后通过，记 `modified=1`）。
- **审核工作台**：题干/选项/解析 + 右侧溯源条文原文（条号高亮，可点跳原文）；驳回必选原因（事实错误/条号引用错/选项重复/超纲/难度不符/解析不足）；支持整批操作。
- **对外口径**：审核通过率 `R = (直接通过 + 文案润色后通过) / 批次生成总数 ≥ 80%`。仅不影响事实与答案的文案润色计为通过；条号引用错、数字错、主体错、选项重复、正确答案错、超纲、解析缺失或矛盾一律计未通过。
- **内控审计（从严水位）**：每月随机抽已入库 10% 双人独立复核，进库题目正确率应 ≥95%；统计各知识点/难度通过率分布，倒逼修正检索权重与 prompt。
- **负样本回流**：`rejected` + 审核原因进反例库，每两周更新一次出题 prompt 与取料排序。

### 4.6 题库字段与导入导出（E01）

题目主表字段：`id / batch_id / question_type / knowledge_point / difficulty / stem / options(JSON) / answer(JSON) / analysis / sources(JSON 溯源数组，含 role: answer|distractor|analysis) / source_law_title / source_article_no / status / reviewer / review_note / interference_verified / created_at / updated_at`。建组合索引 `(knowledge_point, difficulty, question_type, status)` 支撑 E03 组卷抽样。

Excel 导出列：`序号 | 题型 | 知识点 | 难度 | 题干 | 选项A~E | 正确答案 | 解析 | 来源法规 | 来源条号 | 附加引用条文 | 备注`。导入逐行校验不中断整表。溯源要点：法规名用清洗后 title（实测个别带前导空格）；以条文 `article_no` 为准不依赖 `doc_no`（实测多部为空）；`index.json` 已含 source_url 可全链路追溯。

## 五、评估与迭代闭环

**强监督信号：条号即答案**——2087 条均带"第X条"编号，正文含 172 处内容内交叉引用，"引用了哪几条"可精确判定，大半指标自动化无需模型主观判断，这是本方案相对通用 RAG 评测的最大红利。

### 5.1 评测集构建（两级管理，契约 0.6）

| 类别 | 数量 | 生成方式 | 判定依据 |
|---|---|---|---|
| 法规问答 | ≈2200 | 规则模板 60%（按处罚/期限/主体/程序四类抽取）+ LLM 生成 40% | 标准答案 = 条号，精确判定 |
| 场景问答 | ≈600 | LLM 生成 + 人工修订 | 跨法规检索（四川条例引用国家法），含多条条号 |
| 边界拒答 | ≈300 | 人工 + LLM 扩展 | 知识库外 / "尚缺"类（企业文档未入库），必须拒答 |
| 多轮集（新增） | ≈300（60 组 × 5 轮） | LLM 构造 + 人工修订 | 见 §5.4 |
| 出题专项 | ≈620 | 200 条 ×（单选+多选+判断）+ 20 条填空 | 见 §5.5 |

生成校验：LLM 生成样本必须"答案可回溯校验"——生成内容必须出现在输入条文中，否则丢弃。人工抽检 10%，双人独立标注 + Kappa ≥0.8。条号主键统一 `{doc_id}_第X条`（多部四川法规均含"第X条"，必须前缀去歧义）。

### 5.2 检索指标（契约 0.2）

| 指标 | 目标 |
|---|---|
| Recall@5 | ≥0.92 |
| MRR | ≥0.85 |
| NDCG@5 | ≥0.90 |
| 命中条号正确率（集合级） | ≥0.95 |
| top-1 命中率 | ≥0.70（在线只展示 top-1，与用户感知最相关） |

负样本专项：同主题易混条文对（四川条例 vs 安全生产法同性质条款）单独成集，检验跨法规消歧。

### 5.3 生成指标（规则层 + LLM-as-judge 双层）

- **规则层（零成本全量必跑）**：命中条号正确率、引用正确率（回答引用的条号 ⊆ 检索块条号，正则抽取比对）、拒答正确率、多选题格式校验。
- **LLM-as-judge 层（抽样跑 30%）**：忠实度逐句打分、幻觉率判定。judge 模型**固定**一个独立来源的国内 API 模型（建议 qwen-plus 或 GLM-4），不随被评模型换版（防同厂自评偏差），prompt 模板固定写死评分标准。
- **一致性校准**：首版 100 题双轨运行（规则 + judge），一致率 >95% 才信任 judge 单测。
- **批量流水线**：一条命令跑完输出 `report.json`（各指标汇总、按法规/类别分维度、失败样例前 50 含检索块与答案快照）。

### 5.4 多轮评测集（评审补齐项）

PRD A01 要求至少 5 轮多轮对话（会话内消息序列），原评估章缺失，现补齐：

- **构造**：60 组会话，每组 5 轮。第 1 轮为独立问题，第 2~5 轮包含指代消解（"它/那个条例/刚才那条"）、上下文承接（追加条件）、跨轮引用追溯（"你上轮说的第 21 条"）三类手法；每轮标注标准答案条号。
- **指标**：① 指代消解率 = 改写后 query 正确指向历史实体的比例（≥90%）；② 上下文承接 = 第 N 轮回答是否正确引用前轮实体/条款（≥85%）；③ 跨轮引用追溯 = 追问"上轮第X条"能否重新命中该块（≥85%）；④ 单轮检索指标沿用 §5.2；⑤ 5 轮完整度 = 达到 5 轮不中断的比例。
- **校验**：改写后 query 单独评测（检索前），与生成评测分离，定位失败在改写还是生成。

### 5.5 出题专项评测

- 自动一致性校验（规则层全量）：答案可判定性、选项质量（无重复/同义/取巧）、解析规范性（含"依据《XX》第X条"且条号在主键库中真实存在）、知识点一致性。
- **线下验收**：620 题全量双人审核（准确率门槛为上线前置条件，不可只抽检），Kappa ≥0.8。
- **口径**（契约 0.2）：对外 = 审核通过率 ≥80%；内控 = 进库抽样正确率 ≥95%。连续两周 <80% 触发题库停用、重跑生成与审核。

### 5.6 阈值联合标定（评审补齐项）

cos≥0.30、重排分、归一化置信度是同一链路不同环节的截断，统一为**一套归一化分制**（契约 0.2），联合标定流程：

1. 用 2087 条构造正样本 query（改写自条款内容）+ 50 条无关负样本；
2. 跑完整链路，统计正负样本归一化置信度分布，取正负样本分位数的中间值作为拒答/保守/全量两条界线；
3. 一组阈值一次回归跑完（召回率 vs 拒答率 trade-off 曲线），不孤立调参；
4. 上线后按人工抽检与线上踩率校正，阈值变更必须过 §5.7 回归门禁。

### 5.7 回归测试与线上反馈闭环

- **回归门禁**：知识库增删改 / embedding 换版 / 检索参数调整 / prompt 或生成模型换版时，跑同一冻结评测集对比基线。**命中条号正确率、幻觉率回退 >1pt 阻断上线；Recall@5 回退 >2pt 阻断**。基线 `baseline.json` git 存档。
- **线上闭环**：结构化日志 `{query, retrieved_article_nos, answer, cited_article_nos, latency, feedback}`；全部"踩"+随机 5% 点赞 + judge 低分样本进难例队列；每周 Top-100 人工复核分类（检索失败/引用错误/幻觉/拒答失误），修正后回流评测集并沉淀 prompt 示例；监控"踩率/被拒答率/引用命中率"趋势与离线对照——离线高分而线上踩率高说明评测集覆盖不足，反向扩充。

## 六、工程与性能

### 6.1 总体架构与指标分解

```
[Nginx 网关] → [FastAPI 业务后端（含 rag 模块，SSE）]
                      ├─ 多级缓存(Redis/内存)
                      ├─ 检索: Milvus(向量, 生产)/Chroma(开发) + jieba-BM25(内存倒排)
                      ├─ 重排: bge-reranker-base(本地 ONNX int8)
                      ├─ 生成: DeepSeek-V3 / qwen-turbo(API, SSE)
                      └─ 内容安全中间件: 敏感词预检/后置审核
```

| 指标 | 含义 | 手段 |
|---|---|---|
| ≤3s 首字 | 发问到第一个字符（引用块或正文增量） | 检索与生成解耦、引用先返（§6.2/§6.5） |
| ≤500ms P95 | 检索链路 API（预处理+检索+重排+引用组装，不含 LLM） | 小语料全内存、异步并行、连接池 |
| ≥50 QPS | 系统整体吞吐，含 SSE 长连接在途 | 异步 IO + 限流 + 多级缓存降载 |
| SSE 流式 | 正文逐 token 推送 | StreamingResponse + 事件协议（契约 0.2） |

### 6.2 全链路耗时预算（首字 ≤3s）

```
用户发问
 ├─① 网关鉴权 + 敏感词预检            30~50ms
 ├─② 会话上下文组装 + 问题改写(轻量)   20~50ms
 ├─③ 并行检索：向量(60~90ms) ∥ BM25(10~20ms)
 ├─④ RRF 融合 + 去重 + 阈值过滤        <10ms
 ├─⑤ bge-reranker 重排 Top-5          40~80ms
 ├─⑥ 命中缓存? → 直接复用              <5ms
 ├─⑦ 引用块组装并先行推流(meta 事件)   累计 250~400ms ✅ 首字=引用块
 └─⑧ LLM TTFT                        800~2000ms ✅ 正文 ≤3s
```

**关键设计——引用先于正文**：引用块来自检索+重排结果，与 LLM 解耦，`meta` 事件约 400ms 即到前端（"依据《XX条例》第X条"卡片），3s 内必然开始刷正文。

### 6.3 向量库选型与迁移路径

| 阶段 | 选型 | 理由 |
|---|---|---|
| 开发期 | **Chroma（持久化）** | 单机嵌入式零运维，2087 条毫秒返回；混合检索已在实训验证；快速迭代元数据/过滤策略 |
| 生产期 | **Milvus Standalone + 独立 jieba 倒排** | 50QPS + SSE 长连接要求稳定并发读，Chroma 受 GIL/本地计算限制；Milvus 支持标量过滤（doc_no/category/access_level 预过滤）、连接池、水平扩容 |

> 若集团已有 ES 8.x 可复用（自带 HNSW + BM25），但缺省 Milvus：避免与既有业务索引抢资源，故障域清晰。

**迁移路径（四步）**：接口抽象（`VectorStore.search/insert/delete` 各实现一份，业务不感知）→ 导出 `chunks.jsonl` 留档 → pymilvus 分 4 批导入（复用同份向量不重算）→ 灰度只读切 Milvus，跑一周检索回归（top-5 命中对比 Chroma）后下掉。

### 6.4 多级缓存（省成本扛 QPS 第一杠杆）

| 层 | 载体 | 缓存内容 | 命中 | TTL | 价值 |
|---|---|---|---|---|---|
| L1 | 进程内 LRU | 归一化 query → top-5 片段 | 归一化后完全相同 | 5min | 省 embedding+检索 |
| L2 | Redis | query embedding → top-5 片段 | 余弦 ≥0.95 | 10min | 同义改写重复问题直命中 |
| L3 | Redis | 规范化 query → 完整 SSE 流 | L2 命中 | 30min | **不调 LLM**，最大降本 |
| L4 | 内存+Redis | 热门知识点 → 预聚合片段 | 统计 top50 命中 | 1h | 热门问答零检索 |

空结果也缓存（60s）防穿透；缓存更新用互斥锁 + single-flight，同 key 并发只放行一个回源。L3 命中率目标 30%（契约 0.2）。

### 6.5 并发与限流（50 QPS）

并发预算：50QPS × 平均 2.5s ≈ **125 在途请求**，检索侧 350ms 内释放，长连接只占 LLM 流式阶段，瓶颈在供应商并发而非检索。手段：检索全异步化（query embedding + BM25 + 向量三路 `asyncio.gather`）；连接池（aiohttp limit=100、Milvus 200、Redis 50）；LLM 并发信号量（8~16）+ 熔断（连续 5 次超时/429 退避 30s）；Nginx 按用户 `limit_req`（10 req/s）+ 服务内 IP+token 滑动窗口兜底；批量 embedding（batch=32，2087 条约 66 次调用）。

### 6.6 SSE 流式对接（FastAPI 原生）

全栈 FastAPI（业务后端与 RAG 同栈，无跨语言桥，见 §0 技术栈说明）：SSE 由后端原生 `StreamingResponse` 实现，`/api/chat` 接收请求 → 内部调用 rag 模块 → 逐事件 `yield`（`meta(citations) → delta* → done`）→ Nginx 透传。鉴权/权限/日志统一在后端完成，前端只对接一套 API。Nginx 注意 `proxy_buffering off`、`proxy_read_timeout 120s`、http/1.1。观测：Prometheus 埋 `first_token_ms`、`retrieval_p95`、`cache_hit_rate`、`llm_qps`、`fail_rate`；告警：首字 >3s、检索 P95 >500ms、LLM 熔断触发。

### 6.7 成本优化

- **token 精简（约省 40%~60%）**：system prompt 模板化带版本号；命中段先截断至 300 字再拼入；改写用规则；多轮历史只带最近 2 轮；目标单轮 ≈ 系统 150 + 上下文 2000 + 输出 ≤800 ≈ 3k token，小模型单价单问 <0.01 元，L3 命中时成本 0。
- **embedding 建库批处理**：一次性批量（batch=32）；增量入库走每日定时 diff，新/变条文单独嵌入；全量重算仅版本升级触发。

### 6.8 性能验收 / 压测方案（评审补齐项）

PRD §6.1 的并发 ≥50 / AI 首字 ≤3s / API P95 ≤500ms 与 A03 SSE 是三处预算推导（50QPS 为 AI 接口内部压测目标），需可执行验收：

| 验收项 | 方法 | 工具 | 门禁 |
|---|---|---|---|
| 检索链路 ≤500ms P95 | 纯检索接口压测（不含 LLM） | Locust / k6，100 并发 10min | P95 ≤500ms |
| 在线 ≥50 QPS | 端到端 SSE 混合场景压测（含 LLM，mock + 真调用两档） | Locust + 供应商配额配合 | 稳定 ≥50 QPS，无 429 雪崩 |
| 首字 ≤3s | 压测中记录首个事件到达时间 | 压测脚本采集 | P95 首字 ≤3s |
| 125 在途 + Semaphore(8~16) | 叠加真 LLM 调用的排队延迟验证 | 与上文同场景 | 排队延迟纳入首字预算 |
| 冷启动 | 空缓存全失时端到端延迟 | 单独压测 | 首字 ≤3s（允许 <500ms 检索指标放宽） |
| 回滚门禁 | 每轮发版跑 CI 冒烟集 + 关键压测 | 流水线 | 指标回退即阻断 |

模型实例部署预算：8 核 CPU / 16G 内存可支撑 50QPS（bge 模型 ONNX int8 + 内存倒排 + Redis 缓存）。

### 6.9 冷启动与缓存未命中路径（评审补齐项）

- 进程启动：bge-large-zh 与 bge-reranker 常驻内存（杜绝每次请求加载——新手最常见 QPS 杀手）；首次启动预热（空 query 跑一遍 embedding/rerank）；jieba 词典、BM25 倒排、敏感词库启动时一次性载入。
- 连接池预热：Redis/Milvus/供应商连接池启动时预建，避免首请求连库耗时。
- prompt 前缀缓存：system prompt 固定 → 供应商 API 前缀 KV cache 命中，降低 TTFT。
- 缓存全失兜底：L1–L4 全 miss 时按完整链路走（预算已含），空结果缓存（60s）防雪崩穿透。

## 七、合规、权限与原文访问

### 7.1 AI 合成内容标识（评审补齐项）

依据《生成式人工智能服务管理暂行办法》《人工智能生成合成内容标识办法》：AI 生成的回答与题目须做合成标识——**显式标识**：SSE `done` 事件带 `synthetic=true`，前端在回答/题目底部展示"本内容由 AI 生成，仅供参考，请以法规原文为准"；管理端审核工作台标记 `ai_generated=true`；**隐式标识**：生成元数据（模型、prompt 版本、生成时间、task_id）写入问答/题目日志留痕。导出题库 Excel 含"AI 生成"列。

### 7.2 权限过滤（评审补齐项，落地检索管线）

用户角色 → 可见 `access_level` 集合 → 检索召回前 `where access_level ∈ 集合`（§2.5.3）→ 引用/查看原文接口同权限校验（后端透传，前端不可绕过）。权限矩阵（对齐 PRD B02 的管理员/普通用户两种角色）：普通用户 = 公开；管理员 = 公开 + 内部；机密级企业文档属扩展层，后续经管理后台上传导入时再扩展（见 §1.5）。角色升级后刷新权限缓存。

### 7.3 "查看原文"接口（评审补齐项）

A01 来源引用的"点击跳原文"不能只给 `source_url`（外部链接），需站内兜底：

```
GET /api/kb/article?doc_id=scaq&article_no=第二十四条
  → 权限校验(access_level) → 返回 {title, chapter, article_no, content, source_url, version}
```

按 `doc_id+article_no` 从向量库/metadata 取全文（保留原始章节归属），内容与检索注入块一致。前端脚注点击优先站内弹窗，其次外部 source_url。出题审核工作台的"点条号跳原文"复用此接口。

### 7.4 内容安全接入位置

见 §3.8 三位置（入口拦截 / 输出流式审核 / 落库前复检）。接入《网络信息内容生态治理规定》要求的审计留痕：敏感词命中记录、拦截原因、审核操作日志均入库备查。
